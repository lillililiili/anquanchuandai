## 2. 现场首页：07

**画面顺序锁定：** 品牌／现场／厂站与消息铃 → 问候、头像、日期 → 当前作业大卡 → 我的装备卡（产品行、异常提示、装备入口）→ 四栏底导航。

保留浅07天空厂房背景、人物头像，作业卡右侧大场景与左侧文字融合。不要把场景压成小缩略图，也不要将完整作业卡换成纯文字行。

| 原控件 | 保留的目的 | 可做的小修 |
| --- | --- | --- |
| 厂站下拉 | 原厂站选择流程 | 补长名称省略与无权限说明，不改选站后的全局导航规则 |
| 消息铃／异常提示 | 对应消息列表或具体事件 | 有真实eventId时准确带入；没有时不伪造一个事件 |
| 查看作业 | 当前任务详情，有多条时可进入既有列表 | 核对实际taskId；空态仍在原卡区域 |
| 装备行箭头 | 本条设备详情 | 核对deviceId，状态和时间取同一条设备数据 |
| 查看全部／查看我的装备 | 本人装备内容 | 可补精确定位或局部装备页；保留两个可见入口，不以重复为由删除 |

当前源代码还存在待认领按钮、事件指标、作业列表、搜索及现场工具等图外内容。先保留其入口和已有功能，记录与07的首屏差异；不根据本稿自行全部折叠、删掉或搬到“我的”。如需调整这些扩展内容的位置，应单列前后对照，不能混入图片、间距微调。

固定示例任务、人物和装备混入真实状态属于数据展示问题。可以在原区域改为真实值、未知或明确示例；修正数据不得成为取消卡片的理由。

## 3. 通讯：06

**画面顺序锁定：** 品牌与标题头部 → 搜索框 → 已选数量／多选 → 联系对象卡片 → 选择发起设备区 → 手机呼叫 → 安全帽呼叫 → 状态说明 → 四栏底导航。

保留浅06右侧打电话人物、气泡和天空。不能变成矮横幅，也不能把底部两种呼叫改成另一页的分段按钮。

- 搜索仍在原位置，可按人员或设备查找；卡片保留选择框、头像／设备图标、身份说明和右侧电话图标。
- “已选N人”应按人员身份去重；独立设备选择不要冒充多一个人。修正计数不要求删除原有设备卡。
- 多选、手机呼叫、安全帽呼叫保留在图示位置。组呼和帽端发起可以先完成选择、确认和不可用说明，不能删按钮，也不能用单呼或本机通话假冒其行为。
- 同一人多终端时，可通过原卡片展开或局部选择面板确认终端；不在所有呼叫前强制新增一个“呼叫准备”一级页面。
- 已有语音、视频、TTS、历史记录入口继续保留。TTS跳转可增加明确意图，使原按钮到达原通讯页的播报区域；不将整页改为多步骤向导。
- 点电话不是自动同意重拨：错误、离线、能力不足在原操作附近说明；真实请求遵守现有权限和接口。

当前 `deviceId/personId/eventId/video` 参数继续兼容。新增意图参数属于可单独安排的局部修正，不是本轮已经写入的代码。

## 5. 我的装备：00

**画面顺序锁定：** 返回／品牌 → 我的装备与人员身份 → 大产品卡列表 → 绑定历史 → 四栏底导航。

每张产品卡维持“左侧产品大图、右侧名称／编号／状态／时间／箭头、底部用途说明”的结构。安全带提示仍位于其卡内。图片底色和边框按浅00校准。当前本人详情无底栏，与图00的差异见任务04登记，不能直接当作已完成或默默改壳层。

后续可利用原装备入口打开这一展示，不改变人员、设备台账的归属。若增加轻量子视图，返回到实际来源，保持当前底栏分支；参考图00的“我的”选中态对应从“我的”进入的场景，不意味着从现场进入也必须强制跳去我的。

接口没有手表时，UI评审可在明确示例状态下展示图中三卡；真实业务模式按实际装备显示，缺失种类不得假装在线。无任何领用时，在原卡区域显示空态。大卡结构不改成无图列表。

绑定历史保留原入口和记录去向。补字段或补详情参数属于微调；增加领用审批、资产编辑或新设备协议不在本批默认范围内。

**画面顺序锁定：** 返回／品牌／标题头区 → 作业信息与只读关联 → 参与人员及装备状态 → 待核验／关联事件卡 → 联系监护人。原图此页没有四栏底导航，不给它另造导航；当前实现与原图有差异时只单列该项，不批量改变全部详情页。

- 保留浅03人物和厂房头图。

## 7. 异常核验：02

**画面顺序锁定：** 返回／品牌／标题与相应头图 → 异常摘要卡 → 原安监／来源记录卡 → 现场核验说明 → 附件区 → 保存草稿／提交核验并排按钮 → 底部说明。无四栏底导航。

当前是消息页的事件详情工作区，尚无独立核验路由。后续先对齐详情内对应表单区域，若需要按图进入独立子视图，只包裹现有事件控制器和表单，不复制一套处理流程或改变消息列表。

- “保存草稿”只表示草稿；“提交核验”须对应现有合法处置动作。名称校正可以在原按钮和说明位置完成，不能把提交当作认领、关闭或外部正式结案。
- 原安监事件编号有来源才显示；无对接时保留原卡尺寸与位置，显示“暂未关联”，不硬填AQ编号。
- 原图500字与最多4张照片可作为UI录入规格；若真实接口限制更严，原位提示，不静默截断或假上传。
- 缺附件接口时可完成选图、预览、删除和本地草稿交互，明确“仅保存在本机／尚未上传”；生产提交不能把附件说成已上传。保持原附件区，不以无接口为由删去。
- 保留已有认领、评论、转交、关闭、重开、复核等权限与状态机；它们没有全部出现在02中，不因此删除。超出图示表单的功能仍保持原入口，不擅自整批移到“更多”。

## 8. SOS协助：04

**画面顺序锁定：** 品牌与返回标题 → SOS醒目标识／人物信息 → 厂区示意或位置面板 → 位置来源与时间 → 协助组 → 加入协助／结束协助并排 → 底部说明。无四栏底导航。

- 保留浅04对讲人物头图。地图大区域保留，不压缩成一行位置文字。
- 原图示例地图有“厂区示意·非实测”。UI演示保留标注，真实位置不能直接用生成图上的示例点代替；未知位置就在原区域明确显示。
- 事件来源装备保留；可通话装备允许是该人员当前另一台有能力的设备，不改呼别人。
- 协助组／加入协助的界面可以先完成；未联调时明确暂未开通，不能把单人通话当作已加入多人组。
- 结束协助只作用于明确的协助或会话；不得顺带关闭SOS事件。演练与真实事件的文案根据真实模式区分，不能所有SOS都写成演练。
- “帽端长按SOS 3秒退出”来自预览说明，尚不能视为所有设备协议事实；确认前保留“原设备行为待联调”的限定。

## 9. 视频通话：05

**画面顺序锁定：** 返回／品牌／视频通话标题 → 对方身份及关联作业 → 大视频区域 → 发起端／通话状态／时长 → 波形 → 麦克风／扬声器／全屏三控件 → 红色挂断 → 底部说明。无四栏底导航。

- 保留浅05身份区右侧小人物；实际视频保持原色。
- 真实媒体绑定既有RTC会话。待接通、拒绝、失败和结束显示真实状态；连接前不跑“已接通时长”。
- 没有实时画面时可在同尺寸区域显示等待或有持续标记的示例画面，不把页面改成列表卡。
- 麦克风、扬声器和全屏控件的样式、顺序和挂断位置按图；未实现的控件先完成明确的UI状态，不能显示已经改变设备状态。
- 旋转或退出全屏不得新建通话。关闭展示与挂断应有明确区别，沿用现有媒体生命周期。

## 13. 重复功能怎么处理

1. **入口重复但用途明确：保留。** 现场与我的都能查看本人装备；首页异常与消息都能打开同一事件。
2. **同一数据展示多次：优先修数据一致性。** 不因“重复”删除07的装备入口或移动当前作业卡。
3. **不同按钮误入同一内容：修参数或定位。** 例如TTS与对讲区分操作意图，保留原按钮、页面和大体布局。
4. **后端或协议暂缺：完成UI并标明状态。** 不以接口未实现为由取消组呼、帽端发起、附件等图示功能。
5. **涉及入口归属、模块数量或父子层级变化：超出默认微调。** 单列原路径、拟改路径、原图依据和影响，不能由开发者凭偏好直接实施。

## 14. 接口接入与UI演示

已有登录、当前用户／授权厂站、人员、设备、作业、事件、通讯和通知服务继续沿用工程里的API与控制器。修改前核对方法、参数、权限、厂站上下文及响应；保留既有会话失效、取消迟到请求和幂等处理。

缺接口的功能分为三种可交付内容：

| 内容 | 可完成的UI工作 | 必须说清的状态 |
| --- | --- | --- |
| 纯本地交互 | 展开、搜索输入、选择、照片本地预览、草稿编辑 | 本机保存与提交不是一回事 |
| 依赖远程执行 | 组呼、帽端发起、未接入的上传或反馈 | 准备界面完整，远程执行暂未开通，不报假成功 |
| 参考图演示 | 示例三类装备、示意地图、静态视频、外部来源卡 | 持续标明示例／非实测／非实时，不发真实指令 |

不把“已有接口”改成演示适配来省事；不把“暂无接口”当成推迟整个UI模块的理由。用户页面使用简短状态语言，具体接口缺口记在开发记录中。
