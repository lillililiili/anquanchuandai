# 安卓开发强限制与验收清单

版本：V3 · 2026-09-17。适用于后续所有开发者及AI代理。**本轮仅写文档；本文不启动实现。**

本文件与[10-开发指南](10-安卓开发指南-预览图复刻与微调.md)、[11-逐页说明](11-安卓逐页开发说明与跳转保留表.md)构成当前有效说明。旧07—09的页面重组和换肤方案已被撤销。

## 1. 不得自行解释放宽的限制

| 编号 | 强限制 | 判定例子 |
| --- | --- | --- |
| R01 | 必须先打开该页对应浅／深原图，再修改 | 只读旧分析、不看图就写UI，不通过 |
| R02 | 保留四栏数量、顺序、文字和默认现场首页 | 三栏、通讯默认首页、“消息”改名“告警”，不通过 |
| R03 | 原图模块的上下顺序和左右构图不得凭偏好重排 | 联系按钮上移、作业卡下移、把设置搬去首页，不通过 |
| R04 | 不得大幅改变原图的头图、人物、背景及产品图占比 | 全部删除浅色人物、产品大图改小图标，不通过 |
| R05 | 每个主题分别按其原图实现 | 浅深强行套一个新模板，或把深蓝改灰褐暖石，不通过 |
| R06 | 不得用“统一风格”重写应用壳层和路由体系 | 重建三分支、统一迁走全部详情页，不通过 |
| R07 | 不得因重复而直接删卡、删入口或合并页面 | 删除07两个装备入口之一、撤销现场入口，不通过 |
| R08 | 不得因无接口删去图示功能模块 | 附件区、组呼选择、帽端呼叫整体消失，不通过 |
| R09 | 不得把不同功能暗中替换为同一种操作 | TTS实际只进语音、组呼只呼第一人、帽呼变手机呼，不通过 |
| R10 | 保留已有功能、权限、API字段、会话和厂站语义 | UI能点击但对象错误、越权、丢幂等，不通过 |
| R11 | 禁止假数据冒充真实业务状态 | 示例装备在线、生成地图当实测、未上传称成功，不通过 |
| R12 | 主题切换不能重置业务 | 丢输入／选择／草稿、跳首页、重拨或重复提交，不通过 |
| R13 | 背景随主题按页映射，禁止统一替换成新场景 | 一个工业横幅覆盖所有页、图里无人物却补人物，不通过 |
| R14 | 不重用已经撤销的UI作为起点 | 从垃圾桶复制三栏代码或那对工业背景回来，不通过 |
| R15 | 无独立预览图的页面保留现状 | 自创人员中心、资产中心、消息仪表盘，不通过 |
| R16 | 不得把原图整页贴成背景再叠透明点击区 | 无真实输入、滚动、状态绑定的静态仿制，不通过 |
| R17 | 不顺手重构、升级依赖、改PC或后端 | 为换主题重做工程结构、改数据库或Docker服务，不通过 |
| R18 | 不修改原预览图来迁就实现 | 把实现截图当成新参考图、覆盖客户Word，不通过 |
| R19 | “只写文档”期间不得修改代码、资源或部署 | 以验证文档为由跑安装、生成素材、清理工程，不通过 |
| R20 | 不以测试通过替代视觉验收 | 自动化全绿但与预览图大相径庭，不通过 |

上述限制只可由用户后续明确的新指令调整，开发者或AI的“最佳实践”“更符合理念”不构成变更依据。

## 2. 小改白名单与边界

| 可安排的小改 | 满足以下条件才属于小改 |
| --- | --- |
| 字号、边距、裁切校准 | 目的是贴近指定原图，不是更换设计风格；不得系统性把全部卡片变窄、变密 |
| 长文本、大字、窄屏适配 | 普通视口仍保持参考图；仅必要换行、滚动和扩大不可见触控区 |
| 现有按钮跳转修复 | 按钮原位保留、对象正确、已有入口不失效，不改变整个父子体系 |
| 增加主题项 | 放在原设置入口内，点击立即切换，不挤掉原功能 |
| 新增少量状态字段 | 位于相应原卡片中；不新增占据首屏的大区域 |
| 本地照片预览、草稿、选择确认 | 使用图中原附件区、原表单或局部弹层，不创造第二套业务页面 |
| 按图补齐具体子视图 | 只对02—05等有明确原图的对象展开；复用原业务控制，不批量迁移同类页面 |

“修改行数少”不是微调判据。只改一行导航定义也可能造成大幅改版；局部主题适配涉及多处颜色值也不必然是重做。以用户能看见的结构、入口和业务变化判断。

## 3. 每批修改前必须写明

填写一段短记录即可，不要求冗长流程：

| 记录项 | 要求 |
| --- | --- |
| 页面及原图 | 如“通讯，浅06／深06”；无图则写“无独立图，保留现状” |
| 当前问题 | 明确到图片裁切、某行溢出、某按钮参数等，不写“整体不够专业” |
| 精确改动 | 列出可核对的小项；说明原图坐标区域／控件 |
| 保留项 | 头图、模块顺序、按钮位置、原跳转及业务控制器 |
| 文件范围 | 只列需要触及的文件；公共组件额外列受影响页面 |
| 验证 | 对应原图截图、具体点击链路、主题状态保持 |

如果发现必须改模块归属、Tab、默认首页、整套颜色或主构图，先把该项作为超范围差异说明。**先展示具体差异再让用户决定；不能先大改后请求接受。** 这一约束来自用户明确否定上轮整体改版，而不是额外要求每个边距修正都询问一次。

## 4. 视觉验收方法

### 4.1 比对区域

1. 以原图手机内部的应用内容为基准，记录内容区边界；排除手机外壳、外部阴影、图外背景、硬件相机孔。
2. 原图与模拟器截图以相同内容宽度对齐、等比缩放；不得非等比拉伸任一侧来制造一致。
3. 参考图比雷电视口更长时，保留合理文字尺寸、模块比例和顺序，用滚动展示；不能强压所有内容进一屏，也不能把底栏当普通滚动内容。
4. 主界面先看头部、第一张卡、主要操作、底栏；长页面再逐段对照，不能只验首页首屏。
5. 使用同一份明确示例数据做视觉比较；生产接口验证另外记录。实际人名、时间、行数变化不得造成假失败，也不得成为任意改变版式的借口。

### 4.2 验收尺度

以下数值是本指南提出的工程自检容差，不是从原图精确测得的设计标注，更不是“允许重设计的比例”：

| 检查项 | 验收要求 |
| --- | --- |
| Tab与主要模块 | 数量、顺序、文字、所在区域零擅自变动 |
| 图中主体 | 人物、设备、场景的有无和位置按相应主题原图；不替换成不同风格主体 |
| 等比校准后的关键边线 | 普通标准视口下以≤4dp偏差作为逐项自检目标；持续偏移整组控件不能按误差放过 |
| 图区和主卡比例 | 高宽比偏差以≤3%作为自检目标；超出时列明是视口适配、真实内容还是未完成 |
| 文字层级 | 主标题、卡标题、正文、辅助文字的大小和字重关系与图一致；不以系统默认值直接代替 |
| 配色与图片裁切 | 从对应原图内容区核对；不新配一套色表，不以截图压缩色差为由整体换色 |
| 图标细节 | 保留原图主要轮廓和位置；原图之间不一致的底栏图标以当前回退版统一图标为小幅一致化基准，不改标签／顺序 |
| 字体与可用性 | 中文无缺字，常用点击区目标至少48dp；可扩大透明触控区，不需同比放大图形 |
| 照片、视频、验证码 | 保持内容真实性和原色，不能全局反相 |

标准视口的逐图对照负责“像不像”；窄屏、大字、键盘、空态负责“能不能用”。不得为了其中一项全面牺牲另一项。容差只作工程自检，最终仍以图面逐项复核为准，不能用一个自动相似度分数宣布1:1完成。

### 4.3 双主题分别验收

每一页至少保留浅色、深色各一张同状态截图。浅色对浅图，深色对深图；原图的结构差异见11，不要求两张实现截图的装饰布局完全一致。

必须检查：背景、顶栏、底栏、卡片、边框、文字、按钮、图标、弹窗、输入框、加载／空／失败态以及系统栏。未知状态、演示标志、告警等级在切换后仍可识别。

## 5. 功能与状态验收

- [ ] 主入口仍为现场／通讯／消息／我的；启动和选站保留原流程。
- [ ] 原查看作业、装备、事件、联系人及绑定历史入口仍可达，目标ID正确。
- [ ] 参考图中重复入口未被删掉，指向同一对象时数据一致。
- [ ] 无接口模块仍有完整必要UI与本地交互，远程执行状态如实说明。
- [ ] 已有真实接口没有替换为mock；角色、厂站、会话隔离不退化。
- [ ] 手机呼叫、帽端呼叫、多人选择、TTS语义不混淆。
- [ ] 深浅切换保留搜索、选择、输入、草稿、当前事件、当前位置和返回关系。
- [ ] 切换不触发登录、业务提交、重拨、重复通知订阅或额外敏感写操作。
- [ ] 真实通话不受主题影响，未接通不显示真实通话计时。
- [ ] 离线／无权限／未知数据在原区域显示，不补假在线、假楼层或假票号。
- [ ] 退出、切账号、切厂站和结束会话仍遵守既有限制。

只为涉及状态、导航、请求或缺陷的小改增加有意义的回归测试；纯图片裁切、色值、间距更适合截图复核。不要为可逆样式改动堆砌镜像实现的测试。

## 6. 素材、文件和部署限制

1. 保留原浅／深18张参考图和客户Word，不覆盖、不裁写原文件。
2. 缺素材时先记录对应图和区域；本轮只写文档，不启动生成。
3. 后续新增主题素材采用独立命名和浅／深映射；先核对再引用，禁止引用已撤销版本的素材当新依据。
4. 需要清理文件时先确认不再被引用；按相对路径移至根目录“垃圾桶”，附清单，不能直接永久删除。
5. 不采用整仓 `reset --hard` 或广泛清理命令回退UI；只恢复本批已确认的文件，保留用户先前修改。
6. 后续获准施工后，安卓包在雷电覆盖安装并验证；Docker和连接脚本延用现状，不以换肤任务重建环境。
7. 发布记录应区分UI可用、真实API联调、真实硬件验证；不能把演示通话或截图通过说成端到端硬件通过。

## 7. 后续交付必须包含

| 交付项 | 最低内容 |
| --- | --- |
| 改动摘要 | 哪一页、哪几个小项，原模块和入口是否保留 |
| 视觉证据 | 对应原图链接，浅／深实现截图，尚存差异说明 |
| 跳转证据 | 原入口→目标→返回路径，具体对象是否正确 |
| 功能状态 | 已有API验证结果、纯本地完成内容、未开通远程能力 |
| 文件范围 | 实际修改与新增文件；资源来源与恢复位置 |
| 模拟器结果 | 构建／安装结果、冷启动页面、主题及必要交互检查 |

本次文档验收只检查内容一致、原图索引准确、旧方案失效标记和工程文件未改；上表实现验收留待后续明确开始开发时执行。

## 8. 可直接附在开发任务前的约束文字

> 本任务在已回退的安卓版本上进行，只允许针对已列明页面作微调。必须先查看该页浅色、深色原预览图，按对应版本1:1复刻。保留“现场／通讯／消息／我的”四栏、现场默认首页、原有模块顺序、主要构图、卡片比例、人物及背景、按钮位置和已有功能入口。不得自行改版、重分页面职责、删除重复入口、把深蓝换暖石、套通用新模板或复用已撤销实现。已有接口正确对接，无接口先完成UI与本地交互并如实标明状态。新增功能优先使用原入口或局部弹层。每批提交精确改动清单和浅深对照截图；发现需改变整体布局时先列具体差异，不得先实施。任务写明“只写文档”时，禁止修改代码、生成／替换素材、构建或部署。
