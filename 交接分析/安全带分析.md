## 真实数据路径

1. 设备先通过 `GET /api/melhat/config/index.php?ctl=config&act=get_config` 获取配置。服务端从字典 `MELHAT_CONFIG_SET`、`MELHAT_MODEL_SWITCH_SET`、`MELHAT_NOTICE_SWITCH_SET` 组装配置；不是单靠 YAML 就能恢复全部设备行为。
2. 设备接入 WebSocket `/wsHat`，用 `act=ca_login` 登录。按设备编号查 `tab_box`，标记在线、建立内存 session 映射，写 Redis BELTINFO/SIP_BELT。代码仍大量使用 hat/melhat 命名，但 `TabSecureHatMapper` 主设备查询已改为 `tab_box`，不能凭命名就认定主链路缺表。
3. `act=ca_report_location` 解析为 `TabBeltLocationRecordDTO`。需要报文有 `user_id`，服务端通过用户找设备，再把定位、电量、佩戴、网络等字段复制进 `TabBoxLocationRecord`，写入 `tab_box_location_record`。代码把 `y_point` 当经度、`x_point` 当纬度，将 `Altitude` 写入 `relative_altitude`，随后推送 `hatLocation` 给 PC WebSocket。
4. `act=ca_sos` 生成 `TabAlarmSos`，根据字典 `fd_sos_type` 补告警描述，写 `tab_alarm_sos`，再推送 `hatAlarm`。`ca_sip_sos` 还会尝试调用 FreeSWITCH 组建协助会议。
5. PC 使用 `/ws/{client}/{type}` 接收推送，并通过 `/box/*`、`/box/record/*`、`/alarm/*`、`/data/*` 查询。APP 主要通过 `/data/app/box/status`、`/data/app/box/record`、`/alarm/sos/list` 读取数据，并非蓝牙直连设备的客户端。
6. HTTP 离线补传入口是 `POST /api/melhat/index.php`，`ctl=lowcaps&act=ca_backup_data`。该分支目前仍有硬编码轨迹和旧表问题，见下文。
