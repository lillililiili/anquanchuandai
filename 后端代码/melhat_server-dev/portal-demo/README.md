# 独立数据库演示环境（实施中）

这是 S1–S4 可操作演示计划的独立环境，不是原 local-dev 模式。**尚未完成全部业务闭环，不可据此验收 S2–S4 写功能。**

## 隔离设计

- Compose project：wearable-portal-demo；库：wearable_portal_demo；独立 MySQL、Redis、文件卷和 JWT 密钥。
- 后端只连接 Docker internal 网络，不具备默认外网出口；独立 nginx TCP 入口同时连接入口网络，转发固定后端/MySQL/Redis 地址，不提供通用代理。
- 本机端口 18085 / 13308 / 6381 均仅绑定 127.0.0.1，原 18084 / 13306 / 6379 不修改。
- Profile 为 dev,portal-demo。演示配置覆盖原数据源、Redis、文件路径及设备平台地址，Quartz 不自动启动。DemoBoundary 在安全链之前阻断非登录/portal 路由，包括旧设备命令、注册、任务管理和通用上传。
- sys_user/role/menu 为必要认证结构及新生成的三个普通演示账号，无管理员通配权限。SQL 仅提取原初始化脚本中的结构，不导入原账号或业务记录。

## 启动

在本目录执行 `./Initialize.ps1` 生成独立随机密钥，不覆盖已存在配置。之后 `./Start.ps1` 编译共用后端并构建/启动独立演示实例；已有新 JAR 时可 `./Start.ps1 -SkipBuild`。停止使用 `./Stop.ps1`，数据卷保留。脚本失败应停止处理，不要修改原实例以绕过错误。

前台在 `pc前台代码/wearable-portal-web` 执行 `npm run dev:demo`，入口 http://localhost:5178。`npm run build:demo` 输出 dist-demo；正式构建仍输出 dist。当前尚未实现演示生产预览 API 代理，不能用静态文件预览代替后端贯通测试。

## 账号与初始数据

首次成功启动后，`runtime/accounts.local.json` 保存 demo_owner（负责人）、demo_verifier（核验员）、demo_reader（只读）的随机密码。该文件与 .env 已 Git 忽略，不应复制到前端或提交。登录实际校验 MySQL 中的 BCrypt 密码，使用 Redis/JWT 会话，不提供万能密码。

负责人拥有三个厂站，其他两个账号仅访问模拟厂站 1 和空厂站 3。厂站 1/2 各 25 名模拟人员及三类装备，厂站 3 空名册；没有真实人员或设备。带表协议仍待确认。
