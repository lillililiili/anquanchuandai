## 运行

在本目录使用已有依赖，不需要启动后端或数据库：

```powershell
npm.cmd run dev:mock
# http://127.0.0.1:5181/#/admin/login
npm.cmd run build:mock
npm.cmd run preview:mock
# http://127.0.0.1:5182/#/admin/login
npm.cmd run test:admin-mock
npm.cmd run lint:admin-mock
```

两个端口均严格检查，端口占用时退出，不自动换端口。产物独立写入 `dist-admin-mock`。原 `dev`、`build:prod`、`build:stage` 和真实登录不变。

登录选择身份，无需密码。初始系统管理员可看三个站；厂站管理员、资产管理员可看一号站；审计员可看一号站和空厂站。资产管理员无权限协作和接入配置权限。授权按单条角色的操作与范围同时匹配，再取并集；不跨角色拼接范围。A1–A4已开放基础资料、设备档案、领用归还及维修退役；协助组和接入配置仍留待后续阶段。

模拟身份只使用 sessionStorage 的 `Wearable-Admin-Mock-Token`。所有业务和场景仅保存在内存，切页保留、刷新重置；注销保留本页内存业务，但清理页面选择。不存在 IndexedDB/localStorage 业务持久化。

## 工作台与演示控制

有数据的每站：36 台资产、17 台库存且明确未领用设备、12 台有效领用设备、3 张活动维修单、1 台关系未知、1 台关系冲突。资产含三类装备；带表能力待确认，不生成厂家传感字段。离线不影响可领数量。当前绑定开始时间未知，不补造领用流水。

点击指标查看同口径分页明细（20 条/页，服务上限100）。最近管理变更初始为空，A1–A4内存操作成功后追加脱敏记录。人员组织、基础权限及设备资产办理已开放；协助组和接入配置保留阶段说明。

顶栏“演示控制”可针对工作台、明细、最近变更以及A1–A4资料和运维查询设置未接入、失败、无权限，或让下一次查询延迟3秒。空结果选空厂站或使用关键词筛选。恢复默认场景不改业务数据。重置需要二次确认，仅恢复后台内存种子并删除本后台模拟Token，不清空浏览器全局存储。

## A1可操作流程

1. 系统管理员选择空厂站，在“人员组织→组织与区域”分别建立区域和班组；两棵树独立，关联不授予权限。
2. “人员档案”新增编号、姓名及所属组织/区域。人员不必有账号；姓名可重复，编号不可重复。A3已开放人员入口的领用与部分归还。
3. “班次名册”新增未来班次和成员。输入时区明确取自厂站（缺失时UTC），内部保存UTC；当前/历史班次只读。名册中人员不能直接停用，需要先处理未来班次。
4. “权限协作→模拟账号”创建不带密码的账号，可选一对一关联同站人员。新账号无授权，可以立即退出、选择该身份查看无授权状态。
5. 返回管理员身份编辑账号，添加角色和范围。角色模板范围与账号收窄范围共同生效；系统管理员可新建自定义角色，厂站管理员只能委派预置查看员/人员维护员/资产办理员，且不得超过自身范围。
6. 修改后查看工作台最近变更；注销保留内存，刷新重置。自定义账号刷新后不存在会回登录。

厂站、人员、账号、角色不物理删除；组织/区域仅无引用叶节点可删除，审计快照保留。停用前展示影响清单，不做级联停用、归还或授权。组织按厂站独立维护，不支持人员跨站调动。系统内置角色和系统管理员受保护。界面范围校验仅用于演示，不等同于生产安全控制。

可通过构建环境变量 `VITE_ADMIN_PORTAL_URL` 配置可信的前台 http(s) 基础地址（不接受凭据、query、hash）；未配置入口禁用。该链接不传递Token、人员或设备ID。生产部署前需要重新确认可信域名，不能把模拟范围判断当作服务端安全机制。

### A3：发放、部分归还与损坏转维修

入口为“装备资产 → 发放与回收”，也可从人员列表/详情及设备列表/档案点击“办理领用”“办理归还”。系统、厂站或资产管理员须同时拥有人员和每件设备范围的资产办理权限及读取权限；审计员只读，不自动扩大授权。

1. 在空厂站先建立区域、人员和三台不同类型的库存设备；资料、型号可待补充。
2. 从人员入口同时选择安全帽、安全带、手表，核对提醒并勾选模拟边界后提交。一次办理一个办理号、三条按件流水；可领3→0、有效领用0→3。
3. 从安全帽设备档案“办理归还”，完好归还这一件，其余两件保持关系；可领变1。
4. 从人员入口勾选其余两件，一件完好、一件需检修。需检修逐件填写故障及选择有效模拟账号作为处理人；无需账号关联人员。
5. 最终可领2、有效领用0、活动维修单1。历史中的原维修单链接现在进入A4完整详情，可继续接单、检测及报废，不重复建单。

领用只允许启用人员、明确空槽位及可领库存；一人同类最多一件。关系未知、冲突和不可见不解释成未领用。离线、通信未知、过期、资料不全及能力待确认仅提醒，不阻止模拟台账办理，不代表适合真实作业。设备入口只办当前这一件，人员入口可办1–3件；正常旧绑定即使开始时间未知也可归还，不补造原领用时间。

同一提交中任一项无效均整单失败；版本冲突须重新读取，不自动重试。命令带operationId并复核当前权限，同输入重试不重复生成历史或工单。历史冻结办理时人员、设备及经办人名称；当前名称继续随主数据变化。只保证单页面内存一致性，不保证服务器或跨浏览器并发安全。

## A4：维修、停用恢复与报废

入口：“装备资产 → 维修与退役”，包含运维设备、维修工单、生命周期记录。设备台账／档案的“运维办理”共用同一面板；工单详情“工单办理”显示可执行操作及禁止原因。

1. 库存且明确未领用的设备可以送修，填写故障并选择具有本设备资产办理权限的启用账号。A3损坏归还的工单直接继续处理。
2. 切换为指定处理人，接单开始，再填写维修内容和检测说明。“未通过”追加记录并继续维修；“通过”需勾选模拟验收确认，原子关闭工单并回库存，可再次通过A3领用。
3. 系统／厂站管理员可在自己管理角色的范围内重新指派并填写原因。管理员要亲自维修，须先指派给自己；普通资产办理身份不能接管或报废。处理人停用或撤权后必须重新指派。
4. 明确未领用且没有活动维修单的库存设备可停用。恢复需原因、检查说明及检查通过确认。使用中先正常归还，不强制解绑。
5. 管理员可报废库存／停用设备；维修设备必须通过原活动工单“无法修复并报废”，同时记录无法修复并关闭工单。必须复输当前编号（区分大小写）并再次确认。报废不可恢复，历史保留，资产总数不减少。

种子工单无处理人时显示待指派，旧时间未知不补造。运维记录冻结设备编号和名称、经办人及处理人；当前设备资料另行显示最新值。维修过程记录与生命周期记录单独保存，不混入领用归还流水。时间由模拟服务生成并按UTC显示。

- `maintenanceData.js`：四类查询和八个专用命令，管理员角色范围、处理人检查、状态转换与记录追加。
- `components/MaintenancePanel.vue`：全局共用面板，失败保留输入、冲突重新读取、二次确认、未保存确认及会话清理。
- `views/Maintenance.vue`：工作区；`views/MaintenanceSummary.vue`：保留旧路由的完整工单详情；`components/MaintenanceRecords.vue`：独立分页记录。
- `maintenanceData.test.js`：A4状态、事务、权限和历史测试；`scripts/admin-a4-browser.js`：真实浏览器操作演示；`scripts/admin-a4-edge-browser.js`：长文本、记录分页、分区错误与失效。

仅前端内存模拟，不发维修通知、不连接后端，不代表正式审批、真实维修资质或设备安全认证。操作不会改设备通信、源时间、型号能力或另一前台的数据。验证细节及既有lint阻塞见《后台-A4-实施与验证记录》。

# A5：授权效果、模拟凭据与常设协助组

入口仍为 `npm.cmd run dev:mock`（127.0.0.1:5181），预览为5182。六个一级菜单不变，在“权限协作”内进入模拟账号、基础角色、常设协助组。

- 修改账号角色/范围、自定义角色授权/启停：先保存表单查看授权效果，再点击“确认授权生效”。预览过期需返回重新读取/预览，不能绕过确认直接提交。账号普通资料修改不要求确认授权。
- 账号“查看”面板中可“重置模拟凭据”：填写原因并确认，仅增加本页模拟凭据版本，不设置真实密码。旧版后台模拟会话需重新选择身份。
- 新建常设协助组时选择同厂站的管理区域、成员及负责人；可跨区域，但操作者必须拥有完整组范围。SOS开关和接收成员独立选择；关闭、停用均不生效，不发送任何通知。
- 组档案的当前装备来自A3有效关系。通过原领用归还入口换领后，当前摘要随之变化，配置历史中的名称及接收成员快照不变。PC/APP终端未接入；账号启用不代表在线。
- 旧种子组负责人/SOS显示待配置，无虚构历史。启用组仍阻止成员停用，停用后保留成员和策略；重新启用复核引用。
- 业务仍仅在页面内存。刷新恢复种子、退出保留数据。仅使用 `Wearable-Admin-Mock-Token` 和 `Wearable-Admin-Mock-Session-Version` 两个后台会话键；不清空其他存储。

前台边界：这里是按人员维护的**常设协助组**；另一个工程现有的是按设备选择的**临时调度组**。本轮没有修改前台、没有共享Mock仓库，也不把本后台授权当作前台授权。未来联动需按厂站/人员ID、有效领用关系、终端能力及实际模块授权进行适配；不会把组成员资格转为设备权限或已接通状态。

新增服务均为前端内存能力：`authorizationPreview`、`groups/group/groupCandidates/groupTerminals/groupHistory`；命令 `accounts.resetCredential`、`groups.create/update/status`。授权更新命令携带预览标识，提交复核操作者、会话、上下文、版本、输入和仓库修订。历史读取同时约束历史范围，避免组范围缩小后泄露旧成员。

A5浏览器操作回归：创建 `output/playwright/admin-a5`，用Playwright CLI打开5181或5182后执行 `run-code --filename scripts/admin-a5-browser.js`。该脚本通过实际页面创建资料、授权、重置、跨区建组及A3换领，不注入业务仓库、不拦截网络响应。详细结果以《后台-A5-实施与验证记录》为准。
