# 智能穿戴管理平台后端与 PC 管理端分阶段详细开发计划

版本：V1.0　适用分工：你负责后端与 PC，协作者 B 负责 Android，双方使用 AI 辅助开发。

本计划承接整体开发计划和代码现状分析，按可以独立交付的业务模块安排你的工作。你每完成一个模块的可联调接口，就交给 B 接入 Android，同时继续完善该模块的 PC 页面。B 不必等待整个后端或 PC 管理端完成。

本文件替代原整体计划中与你们新分工不一致的人员安排和工作量分配。产品方向、真实性要求和安全验收边界继续沿用。接口路径、表名和文件组织均为拟议设计，不表示当前仓库已经存在。

## 1 你的职责和工作方式

### 1.1 你负责到什么程度

你负责业务规则、数据库、服务端权限、厂商接入、接口实现、PC 页面，以及后端部署和数据恢复。设备在线、事件等级、可执行操作、人员设备关系等业务判断由服务端统一维护；PC 和 Android 消费同一规则结果。

B 负责 Android 页面、客户端数据接入、会话、通知、音视频和弱网体验，同时负责反馈移动端接口需求、复现问题和进行真机验收。Android 不直接访问数据库，不自行维护另一套设备状态或告警处置规则。

双方共同确认业务流程和接口契约。你维护契约与数据库迁移；B 维护 Android 对接状态和验收记录。跨端问题要先定位：接口响应是否正确、客户端是否正确解释、实时消息是否到达，再分配修复责任。

### 1.2 每个模块固定按五步推进

1. **确认业务**：列出使用角色、主流程、权限范围和失败场景。
2. **确定契约**：定义字段、接口、状态、错误码和示例，交给 B 评审；B 可以据此先写页面和模拟适配。
3. **实现后端**：迁移、约束、服务、权限和测试，发布到固定联调环境。
4. **交付接口并完成 PC**：达到接口交接条件即通知 B；你继续做 PC 页面和端到端流程。
5. **联合验收**：PC 和 Android 操作同一份数据，确认状态、权限和错误一致，再关闭模块任务。

不把“Controller 能返回 200”视为接口完成。接口至少应能在真实测试数据库中运行，并有正常、无权限、状态冲突和失败示例。业务数据不得由模拟响应回填成真实成功。

### 1.3 控制你自己的并行量

你同时只推进一个主模块，另留一个已交付模块处理 B 的联调反馈。AI 任务也围绕这两个模块安排，避免多个任务同时修改身份模型、公共响应和数据库迁移。

建议每周安排约 3.5—4 天确定性开发，其余时间用于接口讨论、审查、联调、修复和发布。按实际记录调整，不把 B 的工作时间计入你的后端和 PC 产能。

在 M1 前可以持续演示已完成的小模块；不能把评审演示称为硬件试点。需要安全带的型号/协议在 S0 即开始准备，不等到 S8 才联系厂商。

## 3 S0 工程基线与风险收敛

**目标**：你能稳定修改和部署，B 能稳定连接测试后端；新业务建立在明确的基线上。

### 后端与工程任务

- [ ] S0-01 固定当前代码基线，记录后端、PC、Android 对应提交；确认历史台账源码是否能够找回。找回后在隔离环境评估，不直接覆盖当前项目。
- [ ] S0-02 固定可工作的 JDK、Maven、Node 和包管理方式，记录实际构建命令。检查本地 JAR 依赖来源和打包可重复性。
- [ ] S0-03 建立开发、联调、生产配置边界；测试库独立，配置不包含真实生产凭证；演示数据独立且可识别。
- [ ] S0-04 确定版本化数据库迁移目录、脚本编号和执行方式；新模块所有结构变化进入迁移，不手工改库后忘记记录。
- [ ] S0-05 优先核查登录资料中的 password 字段、模拟 Controller 生产隔离、匿名入口、下载代理和日志敏感信息；在向 B 开放共享环境前关闭不必要入口。
- [ ] S0-06 建立后端测试入口、PC 必要测试基础、构建检查和健康检查，修复当前 PC 测试 setup 缺失等基础问题。
- [ ] S0-07 创建统一接口约定：分页、ID、时间、版本号、错误码、空值、权限和数据来源。
- [ ] S0-08 向硬件供应商收集样机、协议、事件含义、时间/重传机制、凭证、设备回执及网络需求，形成待确认清单。

### PC 任务

确保现有页面可启动，整理保留与关闭入口清单；建立平台名称配置和公共错误提示。当前 SOS 假接通提示先移除或明确标为未完成，真实接听由 S7 完成。此阶段不进行全站视觉重做。

### 交给 B 的成果

联调环境地址、健康检查方式、接口约定、版本信息和账号领取方式。B 可以配置 Android 多环境和网络层，尚不把未稳定的业务接口视为完成。

**验收**：按说明在干净环境完成构建；共享环境没有不必要的匿名/演示入口；账号敏感字段不出现在实际 HTTP 响应中；无真实生产数据混入测试库。

## 4 S1 登录与厂站权限

**业务闭环**：用户登录 → 取得可访问厂站 → 选择厂站 → 在该范围内操作 → 权限撤销或退出后访问失效。

### 后端任务

- [ ] S1-01 审查并复用现有认证；统一当前用户 DTO，返回账户状态、角色和操作权限，不返回密码等内部字段。
- [ ] S1-02 建立厂站与账号授权关系；保留组织结构，物理厂站单独表达。
- [ ] S1-03 定义管理员、设备管理员、值班员、安全复核员、班组长和只读角色的首版操作矩阵。
- [ ] S1-04 提供授权厂站列表、当前用户和退出接口；厂站参数必须在后端校验，不信任 PC 或 Android 自报范围。
- [ ] S1-05 建立业务对象权限公共校验方法，供后续列表、详情、写入、下载和通信复用。
- [ ] S1-06 明确权限撤销、账号停用、令牌过期和退出的生效机制；后续实时推送使用同一身份范围。
- [ ] S1-07 创建两厂站、多角色的测试数据和反向权限测试，不只使用 admin 调试。

### PC 任务

登录页面统一为“智能穿戴管理平台”；实现厂站切换、授权导航和操作按钮；处理无厂站权限、401、403、账号停用和退出失败。切厂站清理旧数据与待提交操作，防止旧请求覆盖新厂站页面。

### 接口交接点

交付当前用户、授权厂站、登录和退出接口。B 接入登录、厂站选择和会话清理；契约明确“隐藏按钮不代表服务端已授权”。

**验收**：A 站账号不能查询 B 站数据；停用后失效；退出后 PC 不自动重连旧会话；PC 和 Android 收到一致的权限语义。

## 5 S2 人员与基础资料

**业务闭环**：维护现场人员与所属队伍 → 分配厂站 → 查询人员 → 为领用和作业选择正确的人。

### 后端任务

- [ ] S2-01 建立 Person，独立于登录账号；字段包括稳定 ID、人员标识、姓名、组织/班组、承包商、状态与有效期。
- [ ] S2-02 支持无登录账号的人员；账号与人员关联可选，人员选择不依赖管理员用户列表权限。
- [ ] S2-03 建立人员与厂站的有效授权关系，定义调离、停用和有效期届满对新领用/新任务的影响。
- [ ] S2-04 实现组织、班组与承包商最小维护；可复用若依组织能力，但不把承包商关系混为厂站权限。
- [ ] S2-05 建立最小 Space 区域层级：厂站、区域、可选设施和楼层；本阶段只维护资料，不声称实时定位。
- [ ] S2-06 提供人员分页、详情、选择器、维护和状态变更；限定可选厂站范围。
- [ ] S2-07 首期逐条维护即可；客户确需批量导入时加入模板、预校验和失败明细，避免静默部分导入。

### PC 任务

人员列表支持厂站、姓名、单位、班组和状态筛选；详情展示基本资料，为后续装备和事件留出分区。实现区域资料维护、停用确认和有效期提示，避免先建无数据的复杂空间画布。

### 接口交接点

人员列表、详情、选择器、区域查询接口。B 可以完成本组人员列表和人员详情，装备区在 S4 接入真实关系。

**验收**：没有账号也能建人员；人员选择不需要系统管理员权限；跨站不可见；停用不抹掉历史资料；姓名重复时仍能依据稳定 ID 区分。

## 6 S3 通用设备台账

**业务闭环**：登记型号能力 → 建立设备 → 分配厂站 → 查询设备档案。

### 后端任务

- [ ] S3-01 建立产品类型和型号，先支持安全帽、安全带；能力按真实型号定义，不能由类型名称自动赋予。
- [ ] S3-02 建立 Device：平台 ID、厂商、SN、型号、厂站、资产状态、外部标识映射及版本字段。
- [ ] S3-03 约定 SN 规范和唯一范围，并使用数据库约束兜底；帽号保留为厂商标识，不能用字符串全量替换方式改造旧表。
- [ ] S3-04 实现登记、分页、详情、基本信息修改和厂站分配；未分配设备使用独立权限策略。
- [ ] S3-05 分离资产状态与连接状态；新建设备 online、电量和最后上报为空，不默认在线。
- [ ] S3-06 定义型号能力返回和有效能力校验，包含属性、事件、可用操作及协议版本。
- [ ] S3-07 为旧 SafetyHatInfo 建立 ID 映射和适配边界；旧数据迁移先做预览，正式切换在 S11 演练。

### PC 任务

一张统一设备列表，按类型/型号筛选；详情显示资产信息、能力和数据来源。仅展示实际支持的功能；领用、遥测、通话等未完成能力不做假按钮或伪数据。

### 接口交接点

设备分页、详情、型号及能力接口。B 做设备列表/详情，并使用 capability 控制入口；禁止在 Android 中写死“安全帽一定有视频”。

**验收**：帽带共用台账；SN 重复并发写入仅一条成功；新建设备状态未知；无视频能力型号无视频入口；修改使用版本号防覆盖。

## 7 S4 领用归还与设备生命周期

**业务闭环**：分配厂站 → 领用给人员 → 归还 → 维修或停用 → 恢复库存，历史始终保留。

### 后端任务

- [ ] S4-01 建立 Assignment，保存设备、人员、有效起止时间、办理账号和归还原因。
- [ ] S4-02 实现领用和归还事务，锁定设备或采用等价并发约束；一台设备不能同时有两条有效领用关系。
- [ ] S4-03 允许一人帽带并用；确需同类数量限制时配置策略，并处理不同设备竞争同人名额的并发情况。
- [ ] S4-04 领用检查厂站、人员有效期和资产状态；未分配、维修、停用、报废设备不能正常领用。
- [ ] S4-05 维修/停用/报废不能直接覆盖有效领用关系；先归还，或进入带原因和审计的专门异常回收流程。
- [ ] S4-06 审计与资产/绑定修改在同一事务完成，加入版本冲突和幂等请求处理。
- [ ] S4-07 提供人员当前装备、设备当前领用人、双方历史和生命周期操作接口。
- [ ] S4-08 厂站调拨先限定为无有效领用设备；保留原厂站历史访问策略和调拨记录。

### PC 任务

设备页办理领还，展示可选人员和不可办理原因；人员详情展示同时佩戴的多台设备；历史按时间排序；维修恢复需说明。网络超时显示“结果待核验”，刷新服务端记录后再决定重试。

### 接口交接点

B 优先接“我的/本组当前装备”和领用历史；Android 是否承担办理领还按试点需要决定，不要求同步复制所有资产维护页。

**验收**：两人抢同一设备仅一人成功；帽带可同时领用；审计失败全部回滚；重复提交不产生重复领用；归还后刷新和服务重启历史一致。

## 8 S5 统一安全事件

**业务闭环**：事件进入 → 授权人员收到 → 原子认领 → 处置 → 复核/关闭 → 查询时间线。

### 后端任务

- [ ] S5-01 建立 SafetyEvent 与 EventAction，确定事件 ID、来源、发生时间、接收时间、人员/厂站/位置快照和规则版本。
- [ ] S5-02 把实时告警、围栏告警和 SOS 映射到统一事件契约，原始证据单独保留；明确旧事件 ID 映射。
- [ ] S5-03 实现新建、认领、处置、待复核、关闭的状态机；转交、误报、重开均记录原因和操作者。
- [ ] S5-04 认领使用条件更新或版本锁；不存在、已被认领和无权限分别返回可解释结果。
- [ ] S5-05 实现分页、详情、动作历史和未处理数量，均按授权范围查询。
- [ ] S5-06 建立认证后的实时推送；断线恢复以 HTTP 查询或增量游标补齐，WebSocket 只是通知渠道，不作为唯一事件存储。
- [ ] S5-07 事件与通知待办持久化，通知失败可重试；完成基础超时升级策略，SOS 不受普通告警降噪影响。
- [ ] S5-08 提供仅限测试环境的事件模拟器，生成明确标识的假数据，先验证业务状态机。

### PC 任务

统一事件工作区：左列表右详情、默认未关闭、按厂站/人员/类型/状态筛选、认领处置、历史时间线。显示位置来源与陈旧状态；“我已看见”“已认领”“已关闭”分别表达。

### 接口交接点

事件列表、详情、动作接口及实时消息结构。B 可用模拟事件完成接警和处置页面；真实接入在 S6/S8 替换数据源，不改核心业务契约。

**验收**：PC 与 Android 同时认领仅一个成功；另一端可更新；重复消息不重复建业务事件；关闭必须满足状态和权限；掉线恢复后没有遗漏待办。

## 9 S6 安全帽接入与可信状态

**业务闭环**：真实帽子上报 → 身份与报文校验 → 可靠存储 → 更新状态/事件 → PC 与 Android 查询。

### 后端任务

- [ ] S6-01 将现有 HeadbandService 封装为 HelmetAdapter，隔离帽号、厂商 token、字段和错误格式。
- [ ] S6-02 根据供应商协议完成回调认证、身份绑定、时间窗口和防重放；未确认可信接入前不开放到现场使用。
- [ ] S6-03 保存必要原始报文及接收时间，建立消息 ID/组合键去重和失败隔离；持久化后再确认受理。
- [ ] S6-04 区分实时状态和历史样本；乱序消息不能覆盖更新的状态，迟到事件按发生时绑定归属。
- [ ] S6-05 统一在线、电量、传感器质量和过期规则，后台同步一次可信状态，避免列表分页后逐页临时改状态。
- [ ] S6-06 接入基础定位，保存坐标系、来源、精度和时间；位置缺失不阻断事件，但明确未知。
- [ ] S6-07 建立报文重放工具、适配日志和第三方失败告警，提供真实样机联调记录。

### PC 任务

设备详情增加最近上报、数据质量和接入诊断；事件来源由模拟切换为真实；设备状态和统计统一口径。诊断报文受权限控制并脱敏。

### 接口交接点

B 使用原有设备和事件 API，增加真实样机回归；你说明上报周期、过期语义和变化的可选字段。不要让 B 通过客户端定时器猜测在线状态。

**验收**：签名错误拒绝；重复/乱序不破坏状态；帽子换绑后补传归属正确；厂商不可达时显示未知/陈旧；真实事件在两端可见。

## 10 S7 SOS 与调度通信

**业务闭环**：从人员或事件发起联系 → 获得授权通话凭证 → 真实加入 → 结束 → 结果和证据可查。

### 后端任务

- [ ] S7-01 建立 CallSession 和 DeviceCommand，统一 callId/commandId、请求人、目标、事件关联和幂等键。
- [ ] S7-02 将 SOS 认领与通话分开：认领成功不等于接通；通话失败不关闭 SOS。
- [ ] S7-03 校验当前可用且有权限的联系目标，申请 RTC 凭证；明确凭证有效期、刷新机制和失败码。
- [ ] S7-04 完成通话开始、加入、失败、结束状态及记录关联；客户端上报须验证成员身份，并结合供应商可用回调/查询核验。
- [ ] S7-05 实现重复挂断、断线、超时和服务重启后的状态核查，避免残留频道或永远显示通话中。
- [ ] S7-06 实现基础 TTS，逐设备记录平台受理、执行回执、失败或未知；不把接口成功等同于现场已听到。
- [ ] S7-07 修正现有单呼帽号自赋值和按频道结束不更新记录的问题；保留实际失败原因但向客户端返回安全文案。

### PC 任务

从事件和人员详情发起单呼、SOS 联系和基础播报；音视频按需打开；真实加入后显示接通；显示发送中、失败、待核验。通话结束释放本地资源，广播防止重复点击。

### 接口交接点

**优先提前交 RTC 接口给 B**：字段契约确定后可先做设备测试环境验证，再交付完整生命周期。B 完成权限申请、音视频、切后台和真机验证，你负责服务器授权与记录。

**验收**：PC↔设备、Android↔设备按实际支持路径真实通话；两端状态一致；无回执广播不显示执行完成；手机被系统挂起、第三方失败和重复结束均可追溯。复杂组呼和录制检索后续增加。

## 11 S8 安全带与跨设备关联

**业务闭环**：同人领帽和带 → 带上报已确认的异常 → 关联当时人员 → 使用当前合法可用渠道联系 → 处置。

### 后端任务

- [ ] S8-01 按真实协议建立 BeltAdapter，登记该型号实际可检测的属性、事件和操作。
- [ ] S8-02 若通过网关或帽子转发，分别记录源设备和传输节点身份；独立计算子设备数据质量。
- [ ] S8-03 处理扣合、挂接、冲击等已确认状态及单位；无法检测的能力不得由平台推断为正常。
- [ ] S8-04 复用统一事件，不新建另一套“安全带告警中心”；规则检查能力、时间和状态有效性。
- [ ] S8-05 事件关联发生时人员；发起联系时再核验当前绑定、在线和权限，避免打给已换绑的另一人。
- [ ] S8-06 借用同人帽子位置时标记关联来源和时间；没有可信关联则位置未知。
- [ ] S8-07 完成真实带报文、掉线、重复、时间异常和网关在线但子设备离线的测试。

### PC 任务

设备详情显示安全带实际能力和状态；人员详情展示帽带组合；事件详情展示带为来源、帽子为可选联系设备。定位、穿戴和资产领用不混用。

### 接口交接点

B 在通用设备和事件组件中增加型号能力展示；已有接口尽量增加可选字段，不复制另一套 Android 业务。协议没到位时只交模拟能力并明确记录。

**验收**：帽带都是真实设备；同人关联正确；扣合不被描述成正确锚固；断连显示未知；换绑后历史不变；无帽可联系时有明确替代联络提示。

## 12 S9 作业监护与值班台

**业务闭环**：建立最小作业任务 → 添加人员和装备要求 → 值班查看 → 异常关联任务 → 交接和结束。

### 后端任务

- [ ] S9-01 建立任务、成员、责任人/监护人、区域、时间、作业类型和外部票号引用。
- [ ] S9-02 实现准备、进行、暂停、结束状态和动作审计；不冒充工作票审批或作业许可。
- [ ] S9-03 按任务配置装备要求，返回缺装备、已领但状态未知、有效、待人工确认等结果。
- [ ] S9-04 明确事件匹配任务规则；多任务冲突时待确认，不任意选一个任务补上。
- [ ] S9-05 建立值班待办查询：未认领、本人处置中、超时、失去可信监护状态；人数与设备数分别统计。
- [ ] S9-06 实现基础交接班，将未完成事项显式移交给接班人员并记录确认。
- [ ] S9-07 任务结束保留相关事件和历史；未关闭高风险事件提示处理，不能随任务结束一并自动关闭。

### PC 任务

任务列表、建立任务、成员和装备检查、事件关联；将默认首页调整为值班台，突出待办、责任人、重点人员和数据质量。复用已有台账和事件模块，避免重新写一套数据聚合逻辑。

### 接口交接点

B 接入我的任务、任务详情、关联人员装备和待办；复杂配置继续留在 PC。值班台聚合接口不能泄露其他厂站的统计。

**验收**：无票数据不完整显示待核实；没有要求票的任务不自动判成违章；同人多设备人数不重复；任务结束不丢事件；交接前后责任清晰。

## 13 S10 位置追溯与区域围栏

**业务闭环**：查看可信位置 → 按人追溯 → 在首厂选定区域启用规则 → 产生可核实的越界事件。

### 后端任务

- [ ] S10-01 在 S6 的基础位置上增加人物位置选择，综合来源、质量和时效；一个人一个主位置，保留来源证据。
- [ ] S10-02 实现轨迹时间范围、分页/抽稀和数量上限；批量关联历史身份，避免每个轨迹点查当前设备。
- [ ] S10-03 实现首厂最小多边形围栏、适用人员、时段、进入/离开、防抖和规则版本。
- [ ] S10-04 按真实坐标系验证；过期、精度不足和漂移状态不直接判成违章。
- [ ] S10-05 事件保留围栏版本和判定证据；禁用围栏不删除历史事件。

### PC 任务

二维找人、位置质量、轨迹回放和围栏维护。可靠楼层源存在时再增加轻量分层视图；否则只做带“任务登记/人工标注”标签的区域示意。修复旧围栏 Hash 路由问题。

### 接口交接点

B 做人物位置和必要轨迹查询；复杂围栏绘制主要由 PC 承担。交付坐标系、精度、时区、空位置和陈旧位置样例。

**验收**：同人帽带不重复打点；楼层未知不编造；跨站轨迹不可查；定位漂移不会产生无法解释的连续告警；规则变更后历史能复盘。

- [ ] S11-02 旧数据只读盘点、映射和试迁移；缺失历史绑定标记未知；新旧写入权威只保留一处。
- [ ] S11-03 完成新环境安装和迁移演练，验证程序回退与数据库兼容，考虑切换后新业务记录。
- [ ] S11-04 完成数据库备份和恢复，逐项核对设备、绑定、事件、动作及审计，不只对总条数。
- [ ] S11-05 测试服务重启、通知积压、厂商故障和重复重试，验证持久化待办恢复。

- [ ] S11-07 完成 HTTPS、生产配置、日志脱敏、依赖检查、健康监控和异常告警；验证地图/RTC 的现场网络条件。

## 15 给 B 的接口交接规范

给 Android 的总入口（账号、禁区、接口地图、改造顺序）：[handoffs/B-android.md](../handoffs/B-android.md)。分阶段 App 计划：[Android端分阶段开发计划](Android端分阶段开发计划.md)。安全带协议未到，不要安排真接入。


### 15.1 建议接口分组

| 业务 | 拟议资源 | 需要明确的内容 |
| --- | --- | --- |
| 身份 | `/api/v1/me`、`/api/v1/sites` | 登录可先兼容现有入口，当前用户/厂站范围语义统一 |
| 人员 | `/api/v1/people` | 分页、有效期、所属范围和选择器最小字段 |
| 装备 | `/api/v1/devices`、`/api/v1/product-models` | 能力、资产状态、连接状态、未知值 |
| 领还 | `/api/v1/assignments` | 版本、幂等键、起止时间和历史范围 |
| 事件 | `/api/v1/events` 与事件动作 | 状态流转、认领冲突、复核权限和同步版本 |
| 通信 | `/api/v1/calls`、`/api/v1/commands` | 凭证、有效期、回执、未知结果与查询方式 |
| 作业 | `/api/v1/work-tasks` | 任务状态、成员、装备检查和票号引用 |
| 位置 | `/api/v1/locations`、`/api/v1/fences` | 坐标系、时间、精度、来源、分页限制 |

这是一份命名草案。实施时将具体 HTTP 方法、动作路径和状态码写入接口契约，避免双方根据上表自行补全。

### 15.2 固定约定

- ID 使用统一字符串表达；乐观锁 version 保持数字。不要让同一字段在不同接口间混用。
- 时间使用含时区的统一格式；同时区分发生时间与接收时间。显示时区由厂站配置或产品约定决定。
- 列表统一分页结构、总数和排序；空数组、空值和接口失败含义不同。
- 401 表示会话问题，403 表示授权不足，状态冲突使用明确业务码或 HTTP 409；两端按同一契约处理。
- 写操作返回实际版本和结果；超时后用幂等键/操作 ID 查询，不盲目重复执行。
- 实时消息包含事件/对象 ID、版本和厂站上下文，不携带多余敏感数据；旧版本消息不覆盖新状态。
- 接口增加字段优先采用向后兼容方式；重命名、删除、状态值变更必须提前通知 B 并写迁移说明。

### 15.3 每次交接的六件材料

1. 接口契约和变更说明。
2. 可运行后端版本与对应提交号。
3. 联调地址、测试账号角色及数据准备方式。
4. 正常、空数据、越权、冲突和超时的样例。
5. 已跑过的服务端测试与真实 HTTP 验证记录。
6. 未实现项、模拟来源及 B 本轮应验收的场景。

建议在仓库中维护 `docs/contracts/`、`docs/handoffs/` 和 `docs/acceptance/`，在交接单中分别标记“契约确定”“后端可联调”“Android 已接入”“联合验收通过”。这四种状态不能合并成一个“完成”。

## 16 你如何使用 AI 拆任务

每个阶段优先拆成 0.5—2 个工作日可检查的任务；较大的接口或状态机再分为迁移、服务约束、接口、PC 和验收。一次任务只指定有限目录和业务目标。

可复用任务模板：

```text
业务阶段：S4 领用归还
本次目标：实现设备领用事务和对应接口，不扩展其他模块。
已有输入：接口契约、设备/人员/厂站模型、权限公共方法。
约束：同设备仅一个有效领用；帽带可并用；审计失败全部回滚。
权限：必须核验设备和人员所属范围，不信任请求中的厂站。
异常：重复请求、版本冲突、人员过期、设备维修、审计失败。
交付：实现、必要迁移、反向测试、真实 HTTP 示例、给 B 的变更说明。
完成判断：列出实际执行的检查；未运行的检查明确记录。
```

先用 AI 设计需要验证的反例，再实现，并由你检查数据库约束和权限调用位置。把实现和验收视角分开，不让测试仅断言“函数返回成功”。需要新增依赖或改公共契约时单独审查，避免小功能带来整仓换栈。

## 17 你开始执行的第一周

| 日程 | 主要行动 | 当天可检查成果 |
| --- | --- | --- |
| 第 1 天 | 确认代码、历史台账是否可找回；与 B 确认 Android 首批需求 | 基线记录、模块顺序和问题清单 |
| 第 2 天 | 跑通后端和 PC 构建，准备隔离数据库与配置 | 可复现命令、环境说明、构建结果 |
| 第 3 天 | 排查敏感字段、共享环境开放入口和演示隔离 | 整改差异与真实 HTTP 验证记录 |
| 第 4 天 | 确定认证/厂站契约以及统一分页、ID、时间、错误格式 | B 可评审的契约第一版 |
| 第 5 天 | 发布首个可联调基线，和 B 验证连接；整理硬件协议缺口 | 首张交接单、下周 S1 任务和实际工时 |

S0 估计需要 5—7 天，第一周未通过构建或环境检查时继续补齐，不为了日历进入下一阶段。每周末记录实际完成的任务、B 的阻塞项和下一周目标，用真实产能修订估算。

## 18 范围调整原则

优先交付一个厂站、一款帽、一款带和一套安全事件流程。延期时先推迟复杂组呼、录制检索、分层画布、批量导入、分析报表和非试点设备。基础权限、真实状态、领还事务、认领并发、通信结果和恢复能力必须保留。

如果硬件协议迟到，你可以继续完成通用台账、模拟事件、任务和 PC 页面，B 继续客户端契约开发；真实多设备里程碑顺延。若现场要求可靠楼层定位或封闭网络音视频，这些应作为独立技术验证和实施工作量重新估算。
