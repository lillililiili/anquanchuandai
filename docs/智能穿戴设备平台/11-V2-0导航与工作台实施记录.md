## 已实现

### 导航

`portalPages` 独立注册九个原页面，`portalMenus` 配置七个工作入口。详情不占一级菜单。

| 工作入口 | 默认地址 | 原页面归属 |
| --- | --- | --- |
| 工作台 | /overview | 基础概况、待办、明细和快捷入口 |
| 现场监看 | /location?tab=live | 位置、视频、轨迹、围栏、单路视频详情 |
| 人员装备 | /personnel | 人员列表和详情；装备查询注明 V2-1 开放 |
| 作业监护 | /supervision | 保留占位，不生成独立模拟作业流程 |
| 事件处置 | /alarms | 原事件列表、摘要和核验详情 |
| 调度协同 | /dispatch | 保留占位，不建立通信连接 |
| 查询分析 | /materials | 现场资料、统计占位 |

新增三组页内导航，移除重复的旧定位标签栏；菜单高亮按归属映射，旧地址继续可访问。导航工具保留厂站并仅传递合法、同站设备标识；不通过当前绑定推定历史佩戴人。人员详情新增安全返回工作台支持。登录恢复保留旧详情白名单，普通工作入口剔除无关 query。

### 基础工作台

四项指标均从当前厂站完整集合计算，不使用当前页数量：

- 当班人数：具有明确 ON_DUTY 名册记录的 personId 去重。
- 已领用装备：明确 ASSIGNED 槽位中的 deviceId 去重；UNKNOWN、UNASSIGNED 和 CONFLICT 不计入。
- 未完成事件：UNCLAIMED、PROCESSING、AWAITING_VERIFICATION；UNKNOWN 单列。
- 本人待办：上述未完成事件中，ownerUserId 等于当前模拟身份 ID 的事件。

种子中身份 ID 与人员 ID 分离。未认领事件没有负责人；二号站事件不分给没有该站权限的核验员。事件摘要复用明确的模拟负责人证据，标注 CURRENT 快照。

一号站默认概况为 25 人、68 台已领用装备、15 个未完成事件、5 个本人待办；未知阶段 5 个。二号站负责人待办 10 个；空厂站为零记录。数字不是页面常量，随查询事实计算。只读身份待办显示“当前身份无处置权限”，不是零。

指标点击打开同口径明细弹窗，20 条分页；人员、事件可以继续查看现有页面。装备暂只查看明细，独立装备详情留待 V2-1。重点关注仅显示未完成事件前五项，不推定风险等级。快捷入口不触发媒体或设备连接。

人员和事件分区独立表达错误、未接入与无权限；未知不写成零。正式、预发布和数据库 demo 的工作台通过独立未接入提供器关闭数据，不猜测真实接口、不回退演示数据。Mock 工作台请求只在浏览器内存处理。

### 生命周期与后续扩展点

- `store/workspace.js` 仅保存同站设备选择、修订通知与相关实体名称，不保存第二份业务实体。
- 切厂站、注销和会话失效清理临时选择；首页使用现有取消请求与版本检查机制。
- 内存仓库更新在副本校验成功后提交，并递增修订号；失败不提交，普通读取不递增。为后续命令保留接口，本轮不增加命令。
- 首次进入单路视频的监看选择等厂站初始化完成后同步，避免被初始化清除；切站仍清除旧设备。
- 设备、人员、领用关系的完整规范化仍在 V2-1 实施，不在本轮提前开放领用操作。
