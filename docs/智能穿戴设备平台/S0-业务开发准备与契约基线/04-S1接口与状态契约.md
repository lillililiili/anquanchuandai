# S1 最小接口与状态契约

版本：S1-contract-v1.0。本文冻结实现目标，不代表接口已上线。四个接口均待新增，旧接口保持原样，由后端聚合/适配层完成身份、分页和字段转换。

## 1. 公共约定

- 基础路径：`/api/portal/v1`；GET；Bearer Token。前台沿用独立 sessionStorage Token、JavaScript 和 hash 路由。
- 所有身份ID均为不透明字符串，包括旧 Long ID 的字符串映射；不能把人员ID、登录账号ID、安全帽ID、设备编号混用。前端不能自行拼接人员ID或用姓名建立关联。
- 成功：`{code:200,msg:"成功",data:...,requestId:"...",asOf:"2026-09-17T03:00:00Z"}`。asOf 仅为服务端响应生成时间，不是设备上报时间。
- 失败：`{code:403,errorCode:"FORBIDDEN",msg:"无权访问",data:null,requestId:"...",asOf:"..."}`。新接口 HTTP 状态与 code 一致；兼容旧后端 HTTP 200 / code 401 的认证处理。
- JSON 中约定字段显式返回；没有证据返回 null，不用空字符串、0、当前时间或示例值补齐。集合确定为空用 []。
- 所有时间为 UTC RFC3339（Z，允许毫秒）。已知时区的旧 Date 才能转换；时区缺失或源时间不可信时返回 null 并标注原因。context 厂站 timeZone 使用 IANA 标识或 null；浏览器时区不是厂站时区依据。
- 列表参数 pageNum 默认1、pageSize 默认20，上限100；均为正整数。统一 data.items / total / pageNum / pageSize。AVAILABLE 时 total 为非负整数；未接入时 items=[]、total=null。不得把“尚未接入”解释为0人。
- 默认按 personCode 升序、personId 升序稳定排序；history 按可证明的发生时间倒序、recordId 升序，时间未知记录置后。不接收任意SQL排序字段。
- query 中未知参数、非法枚举、空 siteId、超限页大小、超过100字符的 keyword 返回400 VALIDATION_ERROR。keyword trim 后为空等于不筛选；约定仅按姓名/人员编码模糊搜索，不默认搜索电话。
- 核心厂站授权、人员身份或名册读取失败返回503，不能伪装空列表；独立次要分区失败可返回200并在分区标注 UNAVAILABLE。

## 2. 身份与来源基线

|实体|新字段|当前来源及适配决定|
|---|---|---|
|人员|personId、personCode、name|待建立人员主数据或经确认的人员映射。sys_user只能作为候选，不等于全部现场人员；账号用户名不是当然的人员工号|
|登录账号|accountId、legacyUserId|已绑定账号时映射sys_user.user_id；无账号人员允许null。不返回密码、身份证、签名或原始用户对象|
|设备|deviceId、deviceCode、type、legacyHatId|安全帽可映射SafetyHatInfo.id/hatNumber；带表档案未接入时不生成假设备|
|班次/班组|shiftId / teamId|待权威名册与组织映射；bindGroup是通信群组，不能直接当班组|
|厂站/区域|siteId / areaId|待授权主数据；dept_id未经映射不能当厂站ID|
|当前领用|relationId、personId、deviceId|bindUserId仅为旧账号关联线索；经过person-account映射与冲突检查后才形成当前关系|
|历史|recordId、relationId、evidenceQuality|旧当前绑定快照不证明历史领用或归还。独立关系流水待新增；保留旧引用便于审计|

旧标识保留在受控 legacy 映射对象中，只供定位兼容，不作为新URL主键。旧接口适配必须先做厂站/对象授权，再聚合；不能取全库后只在浏览器过滤。

## 3. 状态模型

### 分区

统一 Section：`{state,data,reasonCode}`。

|state|data|含义|
|---|---|---|
|AVAILABLE|对象或数组，允许确定的空数组|来源已接入且本次读取成功|
|NOT_INTEGRATED|null|来源未建设或未接入|
|UNAVAILABLE|null|来源已接入但本次读取失败|
|FORBIDDEN|null|允许访问人员但无权读取该分区|

reasonCode 在正常 AVAILABLE 时为 null，其余必须给出机器码，例如 ROSTER_NOT_INTEGRATED、SOURCE_UNAVAILABLE、SECTION_FORBIDDEN。历史中的 UNKNOWN 不是 Section.state。

### 当前装备：固定 helmet / belt / watch 三个槽位

槽位：`{type,assignmentState,devices,reasonCode}`。

- ASSIGNED：有权威当前关系，devices恰好1个。
- UNASSIGNED：当前领用数据完整且明确没有关系，devices=[]。文案“未领用”。
- UNKNOWN：关系未接入/证据不足，devices=[]。文案“领用情况未知”，不写“未领用”。
- CONFLICT：同一类型存在多个未解决当前关系，devices至少2个；不任取第一个。
- 一个设备多人当前领用也必须在聚合端识别冲突，禁止展示为各自确定领用。
- equipment Section 未接入时 data=null；有部分信息时 AVAILABLE，三个槽位各自表达关系状态。

设备公共对象：
`{deviceId,deviceCode,type,model,legacyHatId,communication,battery,capabilities,manufacturerExtensions}`。
type 仅 HELMET / BELT / WATCH；model、legacyHatId 可 null。manufacturerExtensions 默认 {}，保留厂家命名空间扩展位置，本阶段不定义任何带表传感字段。

communication：
`{state,sourceKind,sourceTime,receivedAt,observedAt,freshness,reasonCode}`。

- state：ONLINE / OFFLINE / UNKNOWN / NOT_INTEGRATED。
- sourceKind：PLATFORM_QUERY / DEVICE_REPORT / LEGACY_SNAPSHOT / NONE。
- 实时平台查询中已确认语义的1/0可映射ONLINE/OFFLINE；未匹配、非预期值映射UNKNOWN；带表通信来源未接入为NOT_INTEGRATED。
- 本地安全帽status=1不能直接证明在线，只能 UNKNOWN / LEGACY_SNAPSHOT。也不能映射“安全正常”。
- sourceTime 是设备/平台明确给出的事件时间；receivedAt 是有记录的采集接收时间；observedAt 可记录本次平台查询完成时间，三者不可互换。
- freshness：FRESH / STALE / UNKNOWN / NOT_APPLICABLE。无源时间或无已批准阈值时 UNKNOWN；未接入为 NOT_APPLICABLE；只有明确的源时间与来源特定阈值才可判断 FRESH/STALE。未来时间或异常时钟归 UNKNOWN，不当作FRESH。
- 在线但数据过期是合法组合；离线与过期不同。STALE不能自动触发告警结论。

battery：
`{value,sourceTime,receivedAt,freshness,reasonCode}`，value 为0..100或null。旧electricityUsage缺源时间时可保留数值但 freshness=UNKNOWN，显示“时间未知”，不能显示实时电量；若字段语义/单位未确认则 value=null。不沿用旧颜色阈值作为安全判断。带表协议缺失时 value=null、freshness=NOT_APPLICABLE、reasonCode=PROTOCOL_PENDING。

capabilities固定 video / talk / location / capture / record：
每项 `{state:"SUPPORTED|UNSUPPORTED|UNKNOWN",verification:"VERIFIED|UNVERIFIED",reasonCode}`。无协议的带表全部 UNKNOWN / UNVERIFIED / PROTOCOL_PENDING；安全帽也不得仅凭uid、URL断言能力已验证。UNSUPPORTED只用于有明确不支持证据的情况。

### 操作

`actions`包含 viewHistory / viewVideo / talk / viewWork / viewEvent，各为 `{allowed:boolean,reasonCode:null|string}`。
allowed是服务端能力/权限提示，不替代服务端授权。受设备能力、验证结果、对象权限和模块上线开关共同约束。S1 viewVideo/talk/viewWork/viewEvent=false，reasonCode=MODULE_NOT_ENABLED；历史仅在授权与来源可读时启用。未知操作默认拒绝。

## 4. GET /context

仅要求有效登录；返回当前账号授权范围，不加载若依后台菜单，不依赖尚未建设的 portal:access。

无参数。data：
- sites：[{siteId,name,timeZone}]；只能是已授权厂站。无授权返回[]，不回退所有厂站。
- selectedSiteId：可唯一确定默认厂站时返回其ID，否则null。前端不得自行选未授权厂站。
- areas：[{areaId,siteId,name}]。
- teams：[{teamId,siteId,name}]。
- shifts：[{shiftId,siteId,name,startsAt,endsAt,isCurrent}]，边界时间可null，isCurrent必须有依据。
- availability：{roster,areas,teams,shifts}，值为 Section.state；对应未接入集合返回[]，但通过availability与确定为空区分。
- capabilities：{people:{state,reasonCode},equipmentHistory:{state,reasonCode}}，state沿用能力三态。
- permissions：仅返回前台有关的权限码，不意味着授予权限。

若厂站授权映射本身未接入，sites=[]且 capabilities.people=UNKNOWN，reasonCode=SITE_SCOPE_NOT_INTEGRATED；不得声称账号无厂站权限。实际无授权时 people=UNSUPPORTED，reasonCode=NO_AUTHORIZED_SITE。授权服务故障503。

## 5. GET /people

权限设计：新增 portal:person:read + 服务端厂站范围。新权限为待实施增量，现有前端保存旧角色权限不等于已具备本接口权限。

参数：

|参数|必需/默认|规则|
|---|---|---|
|siteId|必需|授权厂站|
|pageNum/pageSize|1/20|公共分页|
|keyword|可选|姓名/人员编码，最多100字符|
|teamId|可选|属于所选厂站且已授权的班组|
|shiftId|可选|指定班次；缺省仅在权威名册能唯一确定当前班次时采用|
|workState|可选|WORKING / IDLE / UNKNOWN；来源未接入时仅能表达UNKNOWN，不能推断“空闲”|

F07范围是“所选班次人员”，不是全部登录用户。无法确定当前班次或未接入名册时返回 NOT_INTEGRATED、reasonCode=SHIFT_UNRESOLVED 或 ROSTER_NOT_INTEGRATED，不静默切换到全部人员。班组/班次非法引用400，不泄露其他厂站名称。

data：
`{state,reasonCode,items,total,pageNum,pageSize,scope:{siteId,shiftId}}`。
items 是 PersonSummary：
- personId、personCode（可null）、name（主数据必需，核心缺失记录不能伪装成有效人员）。
- avatarUrl、phoneMasked：可null；图片须可控访问；电话只返回授权脱敏值，例如“138****0000”，无权时null。
- siteId、team:{teamId,name}|null、area:{areaId,name}|null。
- accountId、legacy:{userId}|null：可null；不是展示工号。
- dataUpdatedAt：可证明的人员业务源更新时间或null，不是查询时间。
- duty：Section，AVAILABLE data={shiftId,state:"ON_DUTY|OFF_DUTY|UNKNOWN"}，只能由权威名册判定。
- works：Section，AVAILABLE data=[WorkSummary]。
- equipment：Section，AVAILABLE data={helmet:Slot,belt:Slot,watch:Slot}。
- actions：上述操作提示。

WorkSummary固定字段：workId、sourceWorkNo、name、area、personRole、supervisor、responsible、startsAt、endsAt、members、source、monitorStatus；未知值null。personRole为当前人员在该作业中的岗位名称，必须来源于作业成员关系；不能从登录角色推断。supervisor/responsible为{personId,name}|null；members为授权成员摘要数组或null；monitorStatus未接入时UNKNOWN。不把当前装备绑定构造为作业。S1可全部NOT_INTEGRATED。

## 6. GET /people/{personId}

参数 siteId 必需。权限 portal:person:read + 厂站与人员对象范围。personId URL解码后需符合不透明ID格式（1..64位字母、数字、下划线、短横线），非法400；合法但不存在/不在当前可见范围统一404，避免泄露对象存在性。

data：
- person：PersonSummary（与列表共享字段）。
- equipment、works：同 person 对应 Section，聚合响应必须同一快照保持一致。
- duty：同person.duty。
- events：Section；AVAILABLE data=[{eventId,type,level,title,occurredAt,status,source}]，待事件来源核实，缺失整个区未接入。
- location：Section；AVAILABLE data={longitude,latitude,coordinateSystem,sourceTime,receivedAt,freshness,quality,sourceDeviceId,attribution}。经纬度有限数且范围合法；坐标系明确 WGS84/GCJ02/BD09，否则不在地图落点；quality可null。attribution=CONFIRMED/UNKNOWN，必须确认发生时人员归属才用于人员位置。
- media：Section；AVAILABLE data=[{mediaId,type,createdAt,sourceDeviceId,attribution,previewUrl}]。不直接泄露旧存储URL；无授权预览时previewUrl=null。
- historySummary：Section；AVAILABLE data={total,lastOccurredAt}。total仅统计历史证据，不把当前快照计为领用次数。
- actions：与person一致。

旧按安全帽查到的轨迹，不足以证明某人在当时佩戴；归属未知时人员地图/事件/文件不自动挂接，reasonCode=HISTORICAL_ATTRIBUTION_UNKNOWN。S1不启动实时位置连接。

## 7. GET /people/{personId}/equipment-history

参数 siteId 必需，pageNum/pageSize同上；可选deviceType=HELMET/BELT/WATCH；不新增时间筛选避免不确定旧时间语义。权限 portal:person:history + portal:person:read + 对象范围。

data采用people相同分页包装（scope仅siteId），items为：
`{recordId,relationId,personId,deviceId,deviceCode,deviceType,action,occurredAt,startedAt,endedAt,operator,state,evidenceQuality,legacy}`。

- action：ISSUE / RETURN / CORRECTION / MIGRATION_SNAPSHOT。
- state：OPEN / CLOSED / UNKNOWN，仅描述有证据的关系区间，不代替通信状态。
- evidenceQuality：CONFIRMED / CURRENT_SNAPSHOT_ONLY / UNKNOWN。
- operator：{accountId,displayName}|null；无操作日志不能用设备updateBy冒充领用人。
- legacy：{hatId,userId}|null。
- startedAt/endedAt/occurredAt均可null；MIGRATION_SNAPSHOT缺少历史依据时全部null，state=UNKNOWN、evidenceQuality=CURRENT_SNAPSHOT_ONLY。旧bindTime仅是待核实线索，不默认真实领用时间。
- 历史源完全未接入时NOT_INTEGRATED、items=[]、total=null；若建立了可审计迁移快照仓，可返回标明质量的记录，页面文案“当前关系快照（非领用流水）”，不参与领用/归还次数。
- 跨人设备流转按发生时关系区间归属；缺失区间不能回填给当前绑定人员。

## 8. 错误与访问规则

|HTTP/code|errorCode|处理|
|---|---|---|
|400|VALIDATION_ERROR|显示字段错误，不清Token|
|401|UNAUTHENTICATED|统一清会话，合并提示，登录恢复有效站内目标|
|403|FORBIDDEN|无接口权限或site范围；显示无权限，不重试换厂站绕过|
|404|PERSON_NOT_FOUND|人员不存在/不可见；保留返回筛选入口|
|409|CONTEXT_CHANGED|请求中厂站/班次上下文已失效，刷新context并提示重新选择|
|503|SOURCE_UNAVAILABLE|核心源故障，显示失败与重试，不变为空数据|
|500|INTERNAL_ERROR|通用错误+requestId，不泄露堆栈|

新后端不得只依赖前端禁用按钮。权限新增与授权迁移方案单独审核；不能为了测试开启注册、放开匿名、给全部用户管理员权限。history权限不足时详情historySummary=FORBIDDEN、actions.viewHistory=false；直接访问history仍403。

## 9. 适配边界与前端接入

1. 旧帽分页 current/size → 新 pageNum/pageSize；R<Page>.data.records → items。人员列表不是安全帽列表，不能把total安全帽数转换为人员总数。
2. 人员分页应在授权名册范围内执行，再批量聚合装备，禁止逐人调用旧/user接口造成N+1，也禁止拿返回第一顶帽掩盖冲突。
3. 旧若依 TableDataInfo.rows/total 与 R<Page> 分开解析；遇到意外结构抛显式适配错误，不默认[]。
4. 将状态映射按来源拆分：平台查询与本地快照不能共用status映射函数。阈值未审批前freshness=UNKNOWN。
5. 前端建议新增api/portal、utils/portal-adapters、公共查询状态与装备组件；只在S1实施，不在S0创建应用文件。
6. F07筛选通过hash路由query保存siteId、shiftId、keyword、teamId、workState、pageNum、pageSize、selectedPersonId；快速切换取消旧请求或比对请求键，防止跨厂站旧响应覆盖。
7. 新增/personnel/:personId详情路由后同步扩展safeRedirect白名单；returnTo只允许有效站内人员列表路径及白名单参数，不能支持任意外链。
8. 退出/切换账号清context与人员缓存；厂站变更重置分页、选中人和详情。不自动打开WebSocket、RTC或发设备命令。
