# 后台 A5 实施与验证记录

日期：2026-09-20。范围：原PC `melhat_pc-main` 的 `admin-mock` 岛、后台测试及文档。未修改监护前台、后端、数据库、原应用认证或设备配置；未升级依赖。

## 实现与规则

- 新增账号/角色授权效果预览。用现有 `can`/`hasSite` 计算操作与厂站/区域组合，显示新增、撤销、保留、受影响账号、失去范围及无授权。预览在事务副本验证输入，不写业务或审计；提交绑定输入、身份、会话、上下文及仓库revision，失效返回409。
- 保留账号管理范围、系统账号/内置角色保护和有限委派。幂等命令仍先重新鉴权，订阅者异常不把已提交数据误报为失败。
- 模拟凭据重置只增加版本并审计，原因与确认必填。不生成密码、不改变人员/设备/工单。独立sessionStorage版本键校验旧模拟会话；不声称真实认证或跨浏览器强退。
- 常设协助组：同站跨区、管理区域、负责人、去重成员、独立SOS接收人员、启停；负责人须为成员，接收人不能随移除成员静默删除。新建/编辑检查版本和完整旧/新范围，旧种子缺失配置明确未知。
- A1引用检查增加组管理区域；启用组成员阻止人员停用。A3当前终端与设备关系单源派生，不维护第二份设备绑定。账号摘要、设备摘要各自鉴权；终端可达性、厂家通信能力与关联状态分开。
- 每次保存/启停追加名称及范围快照。配置历史独立分页，查询既检查当前组完整范围，也检查每条历史成员区域，避免历史越权。归还、换领不会改配置历史。
- 新增协助组路由、安全返回及查询状态场景，沿用六菜单。账号预览双层面板、失败保留输入、错误摘要聚焦、未保存关闭确认及退出/撤权清理。

## 与监护前台的关联边界

| 概念 | 本后台本轮实现 | 前台后续消费约束 |
| --- | --- | --- |
| 常设协助组 | 人员ID、厂站/区域、负责人、状态、版本 | 不与已有deviceIds临时调度组混为同一实体 |
| 当前终端 | 经授权的A3有效关系推导 | 换领后重查当前终端，不回填历史参与者 |
| SOS策略 | enabled、recipientIds；停用组策略不生效 | 配置存在不等于事件已通知、设备已收到或会话接通 |
| 账号授权 | 本后台实际操作与范围预览 | 不自动扩展至前台权限；真实共同授权契约尚待接入 |
| 历史归属 | 配置名称快照与当前主数据分离 | 不随改名/换领更新历史事实 |

两个工程仍为独立内存Mock，ID/种子未统一，无跨端自动同步。本轮不据此宣称前后台联调通过。之前核查出的前台领用生命周期、损坏归还及权限模型差异仍需独立跨端对齐任务，不在本轮静默修改另一个工程。
