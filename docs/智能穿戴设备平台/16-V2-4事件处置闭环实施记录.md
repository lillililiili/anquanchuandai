# V2-4：事件处置闭环实施与验证

## 范围

仅新前台、测试及文档；沿用七个菜单和页面内存 Mock。未修改或启动后端、数据库、原 PC、安卓及设备服务。没有依赖升级、真实回传或业务持久化。

## 已实现

- 事件列表提供全部事件／我的待办；同一事件集合派生列表、阶段统计及工作台待办，操作后发布修订通知。合法 query 保留筛选、分页及选择，末页失效回退有效页。
- `event-service.js` 提供认领、转交、转现场核验、草稿、提交、显式完成、摘要／核验模拟回执。每项操作校验身份、厂站、对象、版本和操作标识，在内存事务副本中校验后提交。
- 负责人及核验员可认领和核验；转交、转现场核验、完成及回执仅限当前负责人；只读查看员不开放写操作。此为演示权限差异，不是服务器安全隔离。
- 同事件、同核验员最多一个活动草稿；种子中的历史草稿仍只读，不冒充当前身份草稿。提交生成新版本并结束自己的活动草稿；旧版本不修改。
- 提交要求结论、现场情况；“需现场处理”另需措施。可无影像，但明确显示无附件。证据从授权厂站资料查询中选择，冻结标识、版本、摘要和时间；跨站或旧版本拒绝。
- “无法确认”不能完成本地跟进；其他结论提交也不自动完成。负责人显式完成后不提供重开、转交、再提交；模拟回执仍与本地阶段及原系统状态分开。
- 每次成功动作追加独立时间线，保留设备来源更新时间，另记本地操作时间。不将回执成功当原系统结案。
- 两站分别提供安全帽 SOS、安全带锁扣合成报告，复用型号与候选字典；保留原始事件类型，报告类别另列。没有手表告警、自动阈值告警或已恢复推断。
- 共享核验弹窗用于列表摘要与独立详情；离开未保存内容需确认，失败保留输入，提交按钮防重复。身份／会话／厂站／事件切换清理编辑状态。正式模式别名指向关闭组件，不请求 Mock 写接口。

## 演示步骤

运行 `npm run dev:mock`，访问 `http://127.0.0.1:5179`，选择演示负责人、一号站。

1. 进入“事件处置”，选择事件1，查看核验详情。
2. 认领 → 转现场核验 → 编写核验，保存草稿并重新打开。
3. 选择结论、填写现场情况；需要处理时填写措施。可从资料列表选择证据并点击“加入核验证据”。
4. 提交后在右侧查看只读版本与证据；事件仍为待现场核验。
5. 可分别模拟摘要失败、核验成功，查看两类回执与时间线；未发送任何外部系统。
6. 负责人显式完成本地跟进；我的待办及工作台同步移除。刷新恢复种子。

转交给演示核验员后，退出并切换身份可继续操作；切换身份不清空当前页面内存业务。核验员只能访问一号站，二号站不提供可转交的其他演示身份。

## 验证与边界

- 全量单元测试 131 项通过，含新增事件写入、版本冲突、幂等、只读／跨站拒绝、草稿归属、证据冻结、回执独立、取消／身份变化和源事实不变测试。
- 主流程浏览器脚本 `scripts/browser/event-write.js`：14 项检查通过，开发服务与构建预览均执行；另有 `event-write-edge.js` 7 项，覆盖转交、核验员、证据键盘操作、提交只读及只读身份。
- 既有浏览器回归：`mock.js` 59 项、`spatial-write.js` 20 项、`mock-video.js` 18 项通过，覆盖人员／空间／资料／视频／事件只读、围栏写入、文件导入、抓拍录像和权限差异。
- 检查 1440×900、1672×941 编辑弹窗及详情无横向溢出；采用限高滚动证据区，补齐文本框及确认框样式。截图位于忽略目录 `output/playwright/v24-*.png`。
- 主流程记录未出现真实业务写请求、外部媒体、RTC 或设备服务访问；没有运行真实后端验证。
- 执行 lint、正式／预发布／数据库 demo／Mock 构建及 Mock 预览。正式构建不开放新增模拟操作；素材、种子与操作实现只由 Mock 构建引用。
- 扫描非 Mock 产物未发现 `mock-events`、`mock-verification-`、`MOCK_ONLY`、安全帽 SOS／安全带锁扣合成报告标记。原有应用未部署或重启。

界面实现使用 frontend-design 与 UI/UX Pro Max 指导既有深蓝风格、可访问名称、禁用原因、表单恢复和限高滚动；使用 Playwright 进行真实浏览器操作及截图检查。

测试过程中修正了表单选择框可访问名称、弹窗样式，以及自动化脚本读取 textarea 值和刷新后路由初始化等待方式。不以首次失败记录作为通过依据。

未验证：真实认证、后端权限、数据库事务、多人并发、真实设备告警、外部回执及生产安全。这些不在纯前端演示验收范围内。当前事件类型筛选仍使用原始来源类型，新增报告类别作为独立事实展示，不能当作已确认厂家协议。

后续阶段为 V2-5 作业监护；本阶段不开发工作票审批、通信会话或安全判定算法。
