# V2-6 调度协同与 SOS 实施记录

日期：2026-09-19。范围：仅新前台、测试与文档；纯前端内存演示，不代表真实通信或生产安全验收。

## 实现与默认规则

- `/dispatch` 提供联系人/设备分页、临时协助组、当前会话、最近会话记录、独立广播任务与SOS入口。七个一级菜单不变。
- 人员、作业、事件、单路视频的“联系协助（模拟）”进入同一调度页，预选有明确模拟能力的对象，不自动呼叫。当前人员关系不补全历史求助归属。
- 仅演示负责人可操作；核验员、只读查看员只读。厂站及对象范围校验、版本、幂等、取消与身份变化检查由内存服务统一执行，不宣称服务端安全。
- 页面生命周期内只有一个活动会话。单呼/群呼初始模拟振铃，接通、拒接、超时、退出由明确点击推进；部分接通独立计数。所有对象离开后结束，不自动重连。
- 已有会话时可打开原会话或确认结束后新建，保留旧记录。切页保留全局提示；切厂站或注销须确认结束，取消保持原上下文。会话失效直接结束清理，不自动完成关联事件。
- 平台语音与视频为合成会话状态，不采集真实音视频。电话仅展示声明，号码、网关及厂家协议未接入。安全带和手表未知能力不能生成模拟接通。
- 临时协助组不修改组织班组。广播限制1～200字、至少一个同厂站可用模拟语音对象，保存独立任务；逐对象明确模拟成功/失败，不能称设备收到或已播报。
- 本机试听保持禁用：离线语音能力未验证，本轮未调用系统语音服务。此项不以假成功替代，也不影响任务与回执演示。

## SOS 与事件边界

顶栏“前端模拟演示”面板可读取模拟求助对象并显式触发SOS。新建合成事件进入统一事件数据集，工作台/事件列表随之更新；不从通信或传感器值自行生成事件。

`/dispatch/sos/:eventId` 以事件标识访问，不要求会话先存在。安全带可演示“有求助事实，但电话不可联系”。只有实际创建模拟会话后才记录事件关联；结束会话不修改事件阶段。

位置使用触发时冻结的模拟位置快照和其原始源时间，WGS84有效位置才落点；缺失与无权保持未知，不借用之后的设备当前位置。历史人员归属未知；视频入口明确为当前设备模拟视频，不是事发录像，不自动播放。

通过“进入事件处置与记录”使用既有认领/核验链路，安全返回SOS详情。新增事件、任务、会话、协助组与回执均只保存在内存，刷新清空；不引入IndexedDB或localStorage业务持久化。

## 工程入口

- `src/mock/dispatch-service.js`：统一模拟查询、状态转换、广播、SOS与范围校验。
- `dispatch-runtime.js`：Pinia全局会话投影、身份清理和离开确认。
- `DispatchView.vue`、`DispatchBanner.vue`、`ContactEntry.vue`、`SosTrigger.vue`、`dispatch.scss`：页面、跨页提示、统一入口与场景控制。
- `src/utils/dispatch-contract.js`、`dispatch-route.js`：响应校验与安全查询/返回。
- 构建期别名选择Mock或关闭实现；内部 `/mock-dispatch/*` 是内存请求标识，不是真实HTTP端点。正式、预发布和数据库demo不包含模拟调度实现。

## 演示步骤

1. `npm run dev:mock`，访问 `http://127.0.0.1:5179/#/dispatch`，选择演示负责人。
2. 一号站选择安全帽1、2，保存临时协助组，发起群呼；分别模拟接通和拒接，切换工作台查看持续会话提示。
3. 为已选对象创建广播任务并逐个产生模拟回执。结束会话不会完成事件。
4. 打开顶栏演示面板，读取对象，选择安全带1并触发SOS，查看不可联系原因；进入事件处置认领并返回。
5. 再触发安全帽1的SOS，查看冻结位置、手动发起模拟会话；结束后事件仍待独立核验。刷新恢复初始数据。
