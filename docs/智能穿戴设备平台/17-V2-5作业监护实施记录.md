# V2-5 作业监护实施与验证记录

日期：2026-09-19。结论：纯前端作业监护演示闭环完成，不代表真实业务、工作许可或真机验收。

## 实现范围

- 七菜单不变，开放 `/supervision` 与 `/supervision/:workId`。列表支持区域、关键词、来源状态、本地监护状态、UTC来源计划时段和分页；右侧摘要及当前页时间窗使用同一数据。
- 每个有数据厂站25项来源作业。来源单号、状态、计划和许可保持只读；本地监护独立保存人员、监护人、版本、人工检查和时间线。
- 演示负责人可安排人员并执行待开始→监护中↔暂停→已结束。核验员、只读查看员只读。开始/恢复要求有效监护人和参与人员；结束二次确认未完成事件数，不自动关闭事件，也不允许重开。
- 人员、三类装备与专属报告、按人展开的人形生命体征、事件、视频、位置和资料复用现有模块。人工检查与设备报告分开；未知、冲突、过期不被解释为安全许可。
- 工作台、人员作业摘要、事件和视频关联同步读取同一监护关系；历史归属不随人员安排改变。事件/视频返回恢复来源作业，非法返回地址回退安全目标。
- 内存事务、版本冲突、操作幂等、请求取消、会话/厂站隔离以及未保存离开确认；刷新恢复初始种子。未接入、失败、无权限和空结果分别处理。

## 演示步骤与限制

启动 `npm run dev:mock`，访问 `http://127.0.0.1:5179/#/supervision`，选择演示负责人。一号站作业1安排监护人及参与人员，记录人工检查，开始、暂停、恢复；进入关联事件认领后返回，确认结束。事件仍保持自身处理中状态；刷新作业恢复待开始。

本轮未修改后端、数据库、原PC或依赖；未启动/停止相关后端服务。来源授权、真实工作票、现场许可、设备报告与生产并发仍未验证。人形体征仅展示既有模拟能力，不提供诊断或自动安全结论。

使用 frontend-design 与 UI/UX Pro Max 延续现有深蓝布局、明确状态与禁用原因；使用 Playwright 验证页面交互和两种视口。下一阶段为 V2-6 调度协同与SOS，本轮未提前实施。
