# 智能穿戴设备平台 · 前端开发执行计划 V2

进度修订日期：2026-09-20。依据：[前台业务重组与开发方案V2](09-前台业务重组与开发方案V2.md)，设备资料证据及待确认项见其第九节。V2-0至V2-7前端演示增量已实现，验证以实施记录为准；领导评审待执行，不自动确认正式业务权限或启动真实接入。

## 1. 目标、范围与实施原则

交付覆盖七个工作入口、可操作且跨页面关联的前端演示原型，供领导确认业务流程、界面和字段；确认后另行推进真实后端与设备接入。

固定边界：

- 只修改新前台工程及相关文档、测试；原 PC、安卓、后端、数据库、Redis 和数据库演示工程不动。
- 沿用 Vue 3、JavaScript、Vite、Pinia、Vue Router hash、Element Plus、Axios、Sass、OpenLayers 和现有播放器，不更换技术栈、不默认升级依赖。
- Mock 数据存于页面内存，Pinia 管理交互上下文；页面内导航共享数据，刷新恢复初始数据与场景。
- 不引入 IndexedDB，不用 localStorage 持久化业务记录；sessionStorage 只保存独立模拟身份。
- Mock 使用 5179，构建产物为 dist-mock，预览使用 5180；保留现有正式和数据库 demo 模式。
- 正式构建不能包含模拟身份、种子、合成媒体或场景控制；新操作在正式模式明确未开放，不能调用猜测的后端端点。
- 所有命令结果均来自内存业务处理，不用“弹出成功提示”替代数据更新；所有设备、通信和回执明确标注模拟。

### 已有基线

## 3. 公共数据、交互与服务约定

### 3.1 单一业务数据来源

V2-1已分离设备、人员、有效领用关系和历史流水；继续使用该唯一来源，列表/详情/视频当前人员关联由查询适配器派生，不分别修改副本。新增型号与能力引用设备ID，不复制领用关系。过去事件、资料的历史归属使用独立证据，不随当前领用或能力配置变化。

新增模块依次使用统一实体和关系：作业成员、监护记录、事件负责人、核验版本、资料元数据、文件Blob、会话成员和广播记录。ID保持字符串，各实体明确siteId；模拟身份ID与业务人员ID分开。

每次成功写操作递增业务修订号。活动页面仅在相关实体变更时重新读取，统计和待办使用相同数据来源。切换页面不会新建种子；刷新则整体重新初始化。新建记录使用独立前缀及页面内递增序号，不用数组下标作为身份。

### 3.2 查询与命令分离

保留现有18个只读接口的字段、分页、状态和错误封装；所需字段采用兼容扩展。新增前端业务服务，不等于新增真实后端API：

| 服务组 | 计划提供的能力 |
| --- | --- |
| 工作台/统计 | 概况查询、本人待办、分类统计、对应明细 |
| 人员装备 | 设备分页/详情、可领用设备、领用、归还、领用流水 |
| 围栏/资料 | 围栏草稿校验、保存/启停/删除/版本；本地导入、Blob读取、资料关联 |
| 事件 | 认领、转交、转核验、草稿保存、核验提交、本地完成、回执模拟 |
| 作业 | 列表/详情、监护人安排、开始/暂停/恢复/结束、监护记录 |
| 调度 | 创建/结束会话、参与者模拟响应、广播记录、SOS协同 |

页面通过服务操作，不能直接修改种子或集合。Mock命令统一检查身份、厂站、对象范围、能力和当前状态。列表默认20条、上限100，既有详情和视频分页保留现有约定。

命令携带站点、对象ID、expectedVersion、operationId和输入。重复operationId且输入相同返回原结果，不重复生成流水；同键不同输入拒绝。版本过期返回409；输入错误400、无权403、不可见404、来源失败503；保留errorCode/requestId。仅保证单页面内的模拟一致性，不声称实现了服务器并发安全。

内存更新先校验，再更新副本，全部成功才替换数据及记录操作时间线。失败不提交、不关闭表单，保留输入供重试。一个待提交操作重试沿用operationId，用户改变内容后创建新的操作。

### 3.3 模拟角色默认值

以下仅用于原型，不替代正式权限设计：

| 操作 | 演示负责人 | 演示核验员 | 只读查看员 |
| --- | --- | --- | --- |
| 授权范围内基础查询 | 允许 | 允许 | 允许 |
| 查看核验记录 | 允许 | 允许 | 拒绝 |
| 领用/归还、围栏编辑、监护安排与状态操作 | 允许 | 拒绝 | 拒绝 |
| 本地资料导入、关联、证据选择 | 允许 | 允许 | 拒绝 |
| 认领 | 允许 | 允许 | 拒绝 |
| 转交、转现场核验、完成本地跟进 | 负责人对分配给自己的事件可操作 | 拒绝 | 拒绝 |
| 保存/提交核验 | 允许 | 允许 | 拒绝 |
| 发起调度、广播和SOS协同操作 | 允许 | 拒绝 | 拒绝 |

转交只能选同厂站的有效模拟负责人；核验员可认领后提交给负责人跟进，不能因此获得完成权限。首次演示应提供明确负责人分配和核验员关联样例。

回执和参与者响应由独立演示控制面板触发，视为测试工具而非用户业务权限。界面禁用同时展示原因，Mock服务层再次拒绝越权命令。

### 3.4 生命周期

- 筛选、分页和合法选中项进入query；Pinia只保存跨页共享上下文，不保存第二份实体事实。
- 页面内切换位置/视频保留厂站和合法对象；轨迹仍由设备+时间主动查询，不能自动套当前人员归属。
- 切厂站清除旧选择、地图图层、播放器、轨迹播放和未完成请求；迟到响应不能覆盖新状态。
- 未保存表单在页内离开时确认；浏览器刷新可用beforeunload提示，但不能承诺一定拦住刷新或关闭。
- 已保存模拟记录仍只在内存，界面持续提示刷新丢失。退出身份保留当前页生命周期的业务数据，清除身份及临时上下文；显式重置清空全部Mock数据并退出。

### 3.5 型号、能力、观测与事件约定（V2-1A建立）

- 类型、型号、固件版本分别表达；型号未知允许为空，保留原文型号别名及来源，不能把全部安全帽映射为同一种能力。
- 能力采用兼容扩展：分别保存文档声明（已声明/选配/未声明/存在差异）、实例装配（已装/未装/未知）、接入情况、验证情况与数据来源。字段命名在V2-1A契约测试中冻结，不直接改坏已有DTO。
- “文档未声明”不等于“不支持”；模拟配置已启用不等于真机已验证。正式运行继续未开放；只有Mock专属提供器及明确合成配置才能启用后续模拟操作。
- 统一能力判断工具返回允许与否及原因；页面和Mock服务都调用，不写“安全帽一律可视频”或“有麦克风即可RTC”等快捷规则。视频隐私、播放状态、通信、领用、新鲜度独立判断。
- 专属观测携带值、来源证据、源时间、接收时间及模拟标识；未知值为空。设备CPU温度、人体温度、设备工作时长、人员作业时长不能共用同名字段。
- 事件分类ID仅为平台内部演示字典，不冒充厂家事件码。事件由明确的合成记录/场景触发，不能从电量、通信、姿态读数擅自推导告警或自动完成核验。
- 安全带可展示需求模拟的锁扣、单钩、姿态和相关报告；不推导安全结论，不新增自动锁止、阈值设置、固件或设备控制。手表按用户新增要求增加生命体征人形模拟展示，真实能力仍未知；选配手环另记为安全帽外设声明，不作为独立手表规格。

任务：

#### V2-1A新增任务包：人形生命体征面板

依据整体方案9.5及用户提供照片的左下角；在本阶段实现，不延迟到最终统计阶段。只更新新前台Mock及共享展示组件，正式模式仍按真实契约返回未知/未接入，不新增真实接口。

1. **组件与素材：** 建立可复用的人形体征组件，建议名 `VitalSignsPanel`；自绘本地SVG正面人体轮廓、青蓝发光边缘、底部光环和两侧指标卡。必须有人形实物效果，不以文字空态替代整个面板；无数据时保留中性轮廓。装饰图形不承担唯一信息表达，不增加3D依赖。
2. **数据模型：** Mock独立保存体征观测，不塞进领用关系或设备通信状态。候选指标为心率、血氧、体温、血压；血压明确两个值。每条有字符串观测ID、siteId、deviceId、可证实的personId/归属证据、指标及单位、源时间/接收时间、可用性/新鲜度和模拟来源；缺失为空，合法0值不能用真假判断误当缺失。值域和健康阈值不从截图推导。
3. **样例与边界：** 确定性场景包括合成读数、部分指标缺失、未接入、过期、关系未知、无权限和请求失败；不随机跳数、不生成假心电曲线。读取经过厂站/对象/权限检查，沿用公共请求取消、版本检查及模拟提供器隔离；不发真实健康接口请求。
4. **接入页面：** 人员详情放完整面板；手表装备详情复用面板并显示来源设备及有证据的观测归属；人员右侧摘要只呈现紧凑指标和详情入口。无手表与关系未知分别解释，不能拿厂站首个手表数据补位；切人员/厂站、会话失效立即清除上一对象读数。
5. **关系一致性：** 领用/归还只改变当前关联，不迁移历史观测。新人员领到曾有读数的手表时显示暂无属于该人员的观测；设备历史读数若有权限展示必须明确原观测归属，不用当前绑定重写测量人。不得通过领用操作生成一次新的模拟测量。
6. **视觉与交互：** 中央人形两侧各两张候选指标卡，文字包含名称、值/单位、时间及状态；全区持续显示“模拟体征，非真实测量；手表能力待确认”。小容器改为上人形下指标；文字对比度至少4.5:1，状态用文字+图标，不仅红绿。详情入口支持键盘，装饰人形可从辅助技术中隐藏而保留完整文字读数，遵守减少动态效果偏好。
7. **后续复用：** V2-5作业所选人员展示同一组件；V2-7工作台提供紧凑预览/入口，默认未选人员不放入某人的读数。授权有数据人数与个人数值分开，不计算“健康人数”或多人混合体征。

**新增验收：** 1440×900、1672×941及1920×1080检查人形完整、两侧卡片不重叠、单位与长姓名可读；局部窄摘要区可正确换行。覆盖部分缺失、未知、过期、无权限、切人竞态、手表转领历史不串人；无权限无读数泄露。正式构建不包含合成体征种子，Mock允许展示合成数值但始终标识来源；不新增健康告警或改动68→69→68基线。

## 5. 测试与交付制度

每个阶段必须有三类测试，不把下一阶段当作当前阶段的补测：

| 测试层 | 内容 |
| --- | --- |
| 纯逻辑 | 契约、状态流转、范围权限、字符串ID、重复提交、版本冲突、时间未知、统计口径 |
| 浏览器流程 | 使用应用内Mock服务，不用网络拦截替代Mock业务；完成点击、筛选、详情、操作、返回和刷新 |
| 隔离回归 | 正式模式认证/只读行为通过测试夹具验证；明确是隔离测试，不写成真实后端联调 |

每阶段执行 `test:unit`、`lint`、`build:mock` 及Mock预览。涉及路由、共享组件、请求入口时追加 `build:prod`、`build:stage`、`build:demo` 回归。最终阶段全部执行，检查正式产物无Mock种子与控制代码。

浏览器验收统一检查1440×900、1672×941、1920×1080；表格允许局部滚动，不允许整页意外横向溢出。可交互组件有键盘入口、焦点和明确禁用原因；上传/保存/提交有处理中状态，失败保留输入。

每阶段交付：页面与Mock服务、逻辑测试、浏览器脚本、截图、README增量、阶段验证记录。记录逐项区分“已实现、测试通过、阻塞、未验证”，不能用总体完成掩盖未通过项。

设备资料增量必测：同类型不同能力、选配未装/装配未知、资料冲突、隐私中断、CPU温度与体温分离、锁扣状态不等于安全结论、SOS无会话、历史证据不随配置变化。V2-1A保留当前默认统计；后续新增事件样例若调整种子数量，必须同步更新基线、计算口径和演示脚本，不静默改数。

### 必须贯通的四条最终演示

1. 人员领用 → 设备归属 → 作业查看 → 归还 → 领用历史。
2. 工作台待办 → 事件认领 → 现场查看 → 证据核验 → 显式本地完成 → 统计追溯。
3. 模拟视频 → 抓拍/录像 → 资料预览 → 核验证据引用 → 固定版本查看。
4. 模拟SOS → 人员位置 → 调度逐成员响应 → 结束协同 → 事件后续跟进。

## 6. 评审节点与执行约束

- V2-0结束：确认七菜单、默认首页和监看视图切换；未确认不大规模改动模块业务。
- V2-1结束：确认领用归还由谁操作、装备详情字段与前后台职责。
- V2-1A结束：评审型号、选配、专属状态和禁用原因；带表协议未知不阻塞需求模拟，未确认项保留为空或标注待确认，不自动成为生产规则。
- V2-4结束：确认事件负责人、核验结论、必填项和完成规则；本计划的模拟默认值可在此调整。
- V2-7结束：完整演示评审，形成已确认需求、变更清单和下一期真实接入任务。

每个阶段按“公共服务及测试→页面交互→模块闭环→回归→评审”推进。用户要求继续某阶段时，仅实施该阶段及必要前置修复，不擅自扩大到后端、真实设备或数据库。

本计划不承诺未经估算的日历工期，安全带资料中的硬件成本/周期也不作为前端工期依据。以阶段验收而非菜单完成数量衡量进度；复杂媒体兼容和业务规则变更单独登记。V2-1A至V2-7前端演示增量已实现；阶段验证以记录13至19为准。领导评审和真实接入验收仍独立，不自动开始后端开发。
