# 后台 A4：维修、停用恢复与报废实施记录

日期：2026-09-20。仅修改原 PC 工程 `pc前端代码/melhat_pc-main` 的后台 Mock 源码、测试、启动说明及后台专属文档。未修改另一前台、后端、安卓、数据库、设备配置或依赖锁文件；未启动、停止或重启后端服务。

## 1. 已实现范围

- “装备资产 → 维修与退役”包含运维设备、维修工单、生命周期记录。支持类型、区域、生命周期、关键词、活动/关闭、处理阶段、我负责的及分页；合法筛选进入 query，空页回退最后有效页。
- 既有维修单路由升级为完整详情，A3归还历史链接保持有效，返回恢复发放或维修来源列表。非法站外返回地址回退维修工作区。
- 设备台账、设备档案和运维工作区共用库存送修、停用、恢复、报废面板；工单共用接单、检测、重新指派、无法修复并报废面板。
- 指定且仍启用、有本设备资产办理权限的处理人才能接单和检测。管理员不能绕过处理人限制，需先显式指派给自己。
- 管理员接管和报废按受保护的系统身份／内置厂站管理角色自身范围判断，普通资产角色、相同角色名称或跨角色组合不能扩权。
- 使用A3已有工单集合；损坏归还只建原来的一张工单。旧工单缺少处理人显示待指派，缺少时间保持未知，不补造历史。
- 检测失败独立追加过程记录，设备及工单保持维修中；检测通过需模拟验收确认，同一事务关闭工单并回库存。记录检测不是设备安全认证。
- 库存停用与检查确认恢复；库存/停用报废；维修无法修复并报废。报废复输编号区分大小写、忽略首尾空白，二次核对视图明确不可恢复。
- 生命周期操作要求明确未领用且没有有效绑定。使用中先A3正常归还；未知/冲突、多张活动工单、设备与工单状态不一致均拒绝，不自动修复。
- 维修过程、生命周期、领用归还历史分别保存。记录冻结设备和经办/处理人名称；当前档案显示当前事实，不把现在使用中解释为旧工单未关闭。
- 模拟操作时间由服务生成并显示UTC，不改变设备通信、源时间、型号能力或真机验证状态。

## 2. 服务与事务

`maintenanceData.js` 新增四类前端查询：`maintenanceOrders`、`maintenanceOrder`、`maintenanceRecords`、`deviceLifecycleHistory`。兼容A3 `maintenanceSummary` 和 `repairAssignees`。

八个专用命令：`maintenance.create/assign/start/inspect/scrap`、`devices.disable/restore/scrap`。没有新增真实HTTP接口。

- 查询默认20条、最多100条，ID保持字符串；沿用AbortSignal、错误码和requestId。
- 命令携带设备版本；已有工单携带工单版本；选择处理人携带账号版本。在事务副本内校验后，一次提交设备、工单、过程、生命周期、审计和修订通知。
- 幂等键按当前账号、命令和operationId隔离；同输入重试返回原结果，不重复追加记录。重试仍复核当前权限，同标识不同输入409。
- 提交前取消、切站或身份/授权变化不提交；失败不留下半条工单或成功历史。订阅通知异常不回滚已完成提交。
- A2白名单仍禁止修改生命周期；A3可领候选与工作台采用同一活动工单及可领判断。
- 送修可领减1、活动单加1；维修通过反向更新；维修报废只减少活动单、不增加可领。报废保留资产档案，不减少资产总数。

上述保证仅限单页面内存模拟，不是数据库事务或服务器并发控制。

### 主链路（开发5181及生产预览5182均通过）

1. 将初始在用安全帽经A3损坏归还，原关系开始时间未知不补齐，新工单追加损坏归还来源。
2. 处理人接单、第一次检测未通过、第二次通过；未勾验收确认被拒绝且输入保留，错误摘要获得焦点。
