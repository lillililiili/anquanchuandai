# PC后台管理中心：纯前端开发执行计划 V2

日期：2026-09-19。状态：待实施；本文件不是完成记录。

依据：[后台整体改造方案V2](01-PC后台管理系统整体改造方案V2-纯前端Mock.md)。本计划将其拆成A0～A7任务包，不恢复旧方案中的前后端同步建设。

## 1. 交付目标与固定边界

在原PC工程中形成独立运行的浅色管理中心Mock模式，可向领导演示人员组织、设备资产、发放回收、维修退役、账号授权、协助组、模拟接入及审计的完整管理流程。

- 应用修改仅限 `pc前端代码/melhat_pc-main`，另附后台专属测试和文档；不改另一会话的 `pc前台代码/wearable-portal-web`。
- 后端、安卓、数据库、Redis、容器及服务保持不动，不执行真实登录、同步、上传、通知或设备命令。
- 保留现有Vue 3、Vite、Pinia、hash路由、Element Plus及JS/TS写法，不重建工程、不批量迁移语言、不自动升级依赖。
- 业务实体、草稿、场景与历史仅存页面内存：切页保留，刷新恢复种子。不使用IndexedDB或localStorage持久化业务；模拟身份使用独立sessionStorage键。
- 六个一级入口：管理工作台、装备资产、人员组织、权限协作、接入配置、审计记录。PDF仅供页面构图参考，不恢复原九菜单。
- 两端Mock独立，无跨端数据自动同步或免登；后台操作只同步本后台页面。不写“前后台已联调”。
- 每次用户要求某阶段时，仅执行该阶段及必要前置修复；未通过项留痕，不以开发下一阶段掩盖缺失。

### 当前基线

原PC具有系统管理、设备、群组及监看代码；原模式使用5175并代理18084，认证后会初始化WebSocket。当前只有后台V2方案，本计划不认为新后台Mock已建好。前台V2实施记录不能用来证明后台已完成。

已发现Vue与compiler-sfc声明不一致、bun/npm双锁文件及已有未提交权限修改。A0记录实际依赖、可用包管理命令和基线测试；不删除锁文件、不覆写既有修改。若必须调整依赖才能运行，应单列影响和最小变更，不能默认升级。

## 2. 公共实现约定

### 2.1 运行、路由和模式隔离

| 命令/模式 | 约定 |
| --- | --- |
| `dev:mock` | Vite的admin-mock模式，127.0.0.1:5181，strictPort，无业务代理 |
| `build:mock` | 独立输出dist-admin-mock，不覆盖正式产物 |
| `preview:mock` | 127.0.0.1:5182，strictPort，预览Mock产物 |
| 原dev/build:prod/build:stage/preview | 保留原模式行为，不改变真实认证契约 |
| `test:admin-mock`（新增） | 使用现有Vitest执行后台Mock测试集，不升级测试依赖 |

A0优先使用现有安装直接执行脚本；需要安装时先核对锁文件和当前环境，不在两个包管理器间来回重写锁文件。端口冲突明确报错，不停止其他会话进程。

构建期别名选择应用bootstrap、认证/路由和服务提供器。Mock入口不能导入会连接WebSocket的旧用户Store、RTC、外部地图、上传和同步模块；不能只在按钮处禁用。对确实复用的旧页面调用做适配，不先实现整个若依Mock服务器。

新增后台页面在正式服务未接入前不开放；保留原正式路由。Mock中旧监看链接进入职责说明页，不执行旧监看组件。生产/预发布包不包含Mock种子、身份及控制面板，不以失败回退进入演示。

| 工作区 | 路由基线 |
| --- | --- |
| 入口 | `/admin/login`、`/admin/overview` |
| 装备资产 | `/admin/assets/devices`、`/admin/assets/devices/:deviceId`、`/admin/assets/assignments`、`/admin/assets/maintenance`、`/admin/assets/maintenance/:orderId` |
| 人员组织 | `/admin/people`、`/admin/people/:personId`、`/admin/organization`、`/admin/sites`、`/admin/duty` |
| 权限协作 | `/admin/access/accounts`、`/admin/access/roles`、`/admin/access/groups` |
| 接入配置 | `/admin/integrations`、`/admin/integrations/:connectorId`、`/admin/integrations/jobs/:jobId`、`/admin/integrations/settings` |
| 审计 | `/admin/audit`，详情用侧面板 |

路由与菜单独立。A0注册入口及工作区占位，业务详情随阶段开放；未实现操作注明阶段。query白名单按模块保存siteId、keyword、合法状态、pageNum/pageSize和选中ID，详情returnTo仅接受该模块合法站内列表。外部或非法返回回退所属列表。保留字符串长ID，不强制转Number。

### 2.2 仓库、服务和一致性

仓库按组织、厂站区域、人员、账号、角色授权、班次名册、设备、有效领用关系、流水、维修单、协助组、接入配置/任务、审计分集合。A0定义核心关联和最小种子，后续阶段添加操作而非重建另一套数组。

设备生命周期、领用关系、通信、新鲜度、能力独立。正常设备的“使用中”由有效关系派生；发现遗留状态与关系矛盾显示冲突并拒绝操作，不能选一边静默覆盖。人员装备、设备使用人、可领库存、工作台和协助组当前终端都从同一关系派生。

服务接口分查询与命令：

- 查询采用 `query(input, { signal })` 语义，统一分页和范围过滤，返回数据及requestId；默认20条、最大100条，空列表与未接入区分。
- 命令采用 `execute(input, { signal })` 语义，携带对象ID、siteId、expectedVersion、operationId；批量操作逐对象验证版本。创建校验唯一性，不能要求不存在对象的版本。
- 校验身份、范围、状态、版本和取消状态后，事务副本一次提交；同步生成实体变更、业务流水、脱敏审计及修订通知。
- 幂等记录按身份+操作类型+operationId隔离，同输入返回原结果、不同输入拒绝；每次重试仍检查当前身份和权限，不能靠旧结果绕过授权。
- 固定200ms延迟，提供下一次查询延迟3秒的确定性场景；错误保留errorCode/requestId，取消不提示失败。400/401/403/404/409/503分别表示参数、会话、权限、不可见、冲突和来源故障。
- 提交前账号/上下文变化或取消不得提交；提交完成后关闭弹窗不自动回滚。失败保留输入，不自动换对象或盲目重试。
- 成功审计与业务原子提交；被拒绝的尝试可单独追加安全脱敏的失败审计，但不得产生业务流水或泄露不可见对象内容。

### 2.3 身份、授权与演示数据

使用 `Wearable-Admin-Mock-Token`；不读写旧Admin-Token及前台Token。身份选择显式标注不是真实认证；不索要真实密码。

种子提供演示系统管理员、厂站管理员、资产管理员、审计员四种身份，两个有数据厂站和一个空厂站。系统管理员全演示范围，厂站/资产管理员仅一号站，审计员查看一号站和空站、无业务写权。个人、账号和角色分离，组成员不授予数据权限。

授权以每个角色的“操作+范围”组合判断后取并集。区域受限授权不能访问区域未知对象；只有明确全厂范围才覆盖该厂站全部对象。厂站管理员只能分配A1预置的可委派角色，范围不能超过自身，不得授权系统管理/角色编辑/集成配置；内置系统管理员受保护。

刷新重建种子，不保留新增账号；sessionStorage所指身份不存在时回登录。登出/切换身份清临时选择及缓存，保留本页仓库。重置需二次确认，清本后台仓库和身份，不能调用全局storage.clear影响其他模式。

种子名称明确“演示”，包含无账号人员、未领用、关系未知/冲突、通信离线/未知、过期、维修、停用、报废以及长ID。主要业务列表至少一组超过20条；固定角色/连接器无需凑20条。时间取固定演示基准并标明，不能以当前时钟把旧观测刷新为新报告。

## 3. 分阶段任务包

### A0：基线、独立Mock入口与管理骨架

**目标：** 不需要后端即可进入有内容的后台，并证明隔离成立。

1. 记录工作区修改、现有命令/依赖、可复用组件及所有自动网络入口；登记旧功能保留/适配/迁往前台/待确认去向。
2. 增加admin-mock构建选择和独立启动、预览命令，切断旧登录、动态菜单、字典请求、WS和设备同步自动链路，保留旧正式模式。
3. 建立内存仓库、ID/时间/枚举、统一查询和命令基础、授权判断、错误封装、审计及修订通知。此阶段用测试命令验证事务，不开放完整业务编辑页。
4. 建立身份选择、退出、安全登录恢复、401/404及六菜单浅色布局；持续提示模拟与刷新重置。
5. 简版工作台显示授权资产总数、可领设备数、在用关系数、活动维修单数及最近管理变更；未知/冲突单列。可领=库存且明确未领用，不因离线剔除；统计用完整范围，不用当前页数量。
6. 工作台未完成模块入口显示建设阶段，不假装可办理；已有最小数据明细可以侧面板核对，不加载旧真实业务页。
7. 演示面板支持正常、未接入、失败、分区无权限、迟到响应、会话失效与重置。保护其他端会话。

**验收：** 三厂站/四身份可切换；刷新重置可解释；后端不可访问也可运行；除本地静态资源/HMR外无请求。正式/stage产物不包含Mock；旧权限修正保留。

**交付：** 启动说明、基线及风险清单、仓库/隔离测试、A0验证记录。依赖阻塞如实记录，不跳过隔离门槛继续做业务。

### A1：组织、厂站、人员、账号与基础授权

**前置：** A0通过。此阶段提供可用主数据及权限，不等待A5。

1. 组织班组与厂站区域双树，分别新增/编辑/启停、配置关联；树移动禁止循环；已有引用不允许删除，展示影响清单，不做级联删除。
2. 人员列表/详情、新增/编辑/停用；编号与姓名分开，重名不合并，无账号可存在。人员选择器使用同一服务；有有效领用不能停用。
3. 班次及当班名册手工维护，起止合法、厂站明确、成员不重复；时间保存UTC，界面采用明确厂站时区，无配置标UTC。无名册不推算当班人数。
4. 实现模拟账号新增/编辑、关联人员、启停，以及基础角色新增/编辑、功能和范围授予。新账号默认无授权，可在身份选择中验证；不收集真实密码。
5. 服务层落实系统管理员和厂站管理员可委派边界；账号停用不自动归还装备，当前账号失效清会话。账号/人员初版停用保留记录，不提供物理删除。
6. 修改结果同步本后台选择器、名册、角色用户列表和审计；历史名称使用快照，不被改名覆盖。

**验收：** 无账号人员可建立且能成为后续领用候选；空厂站建立人员后列表同步；新账号授权后切换身份可见一号站、不可越站；账号停用不删人员历史；无权服务直接拒绝。

**不做：** Excel导入、自动排班、真实密码策略、前台权限联动、复杂组织审批。

### A2：三类设备台账与档案

**前置：** A1基础人员/厂站/权限可用。

1. 台账按类型、编号/SN关键词、厂站、生命周期、领用及通信状态筛选分页；新建抽屉和详情复用统一选择器及状态组件。
2. 创建设备校验平台编号唯一、厂商+SN唯一；新建库存、明确未领用、通信未接入、能力待确认。重复提交不重复建档。
3. 编辑基本信息记录差异；厂站/类型不作为普通编辑字段，关键身份在使用中不可改，报废全档案只读。不开放物理删除，退役使用A4报废流程。
4. 公共档案头卡和基础/当前关系/历史/能力/接入摘要分区；安全帽按型号选配、安全带展示需求说明、手表真实能力待确认，未接入不显示伪观测。
5. 模型声明、实例装配、接入和验证分开；模拟档案配置只改变模拟配置，不改变通信时间或显示真机验证通过。设备图使用本地素材/示意，不访问外部地址。
6. 原影像、定位、通信动作不执行；显示职责说明和可信前台入口。入口默认前台首页、独立登录、两端数据不互通。

**验收：** 新建三类设备→列表/详情/工作台及审计一致；不同型号能力不同；SN冲突、越站编辑、旧版本拒绝；无设备平台请求。

### A3：发放、部分归还及历史闭环

**前置：** A2；A0已包含维修单结构，为损坏归还准备最小工单读取能力。

1. 当前领用、归还记录、全部历史共用关系和流水；人员/设备入口打开同一办理组件，固定来源对象、选择同站候选。
2. 一人最多帽/带/表各一件，多类型一次领用整单校验与提交；同设备唯一关系、同人同类唯一关系。未知/冲突禁止，离线/通信未知/过期允许但提醒。
3. 检查人员、设备及关系版本，操作期间防重复点击；成功生成按设备明细的流水和共同办理号，初始绑定快照不补造起始时间。
4. 按设备明细部分归还。完好回库存；需检修必须填写故障说明和有效处理人，原子关闭关系、进入维修、创建工单；混合归还整次提交全部成功或全部失败。
5. 更新列表、人员/设备详情、可领库存、工作台与审计；变更导致当前页空时回到合法末页，其他筛选保留。
6. 未提交选择离开需确认，失败保留输入；注销/会话失效不跨身份保留草稿。已提交结果不因关弹窗回滚。

**验收：** 新建人员→领用三件→归还一件→另两件仍有效→历史分别可查；重复领用/幂等重试/批次中一件冲突均正确；损坏设备不出现在可领列表，并可看最小维修摘要。

**不做：** 强制解绑、跨站领用、同类多件、补登记、历史更正、前后台Mock同步。

### A4：维修工单、停用恢复与报废

**前置：** A3。

1. 运维设备列表、维修工单列表/详情、维修历史；A3损坏归还直接进入相同工单数据，不补建第二单。
2. 库存送修：原因/负责人必填，创建工单、设备维修中；同设备最多一张活动维修单。
3. 维修记录结果与检测说明；通过关闭工单回库存，未通过追加记录并保持维修中。流水保留，不覆盖上次检测。
4. 库存停用填原因，停用恢复须检查通过且无活动工单。使用中、关系未知/冲突拒绝送修/停用/报废。
5. 报废要求原因、编号复输、二次确认；库存/停用无活动关系和工单才允许。维修中报废使用“无法修复并报废”原子操作，关闭工单同时报废。
6. 报废不可普通恢复，档案、关系历史、维修和审计可查；所有旧办理入口再次验证状态，不仅隐藏按钮。

**验收：** 损坏归还→维修通过→再次领用；维修失败→报废→再次领用被拒；报废重复提交仅一条业务结果；工单无孤立，历史不丢。

### A5：授权效果、账号状态与协助组完善

**前置：** A1基础授权已生效，A3当前关系可供终端解析。

1. 完善角色列表、用户分配、操作/范围授权及变更前后预览；预览展示可见厂站/允许操作，不把前台权限配置称为已影响另一前台。
2. 授权变更递增修订，清缓存并重算当前范围；失去当前厂站跳有效入口，无可用范围显示明确无授权，不默认全部厂站。
3. 模拟密码重置只变更凭据版本和脱敏审计，失效相关模拟会话；不处理真实密码或声称完成真实认证安全。
4. 协助组新建/编辑/启停、成员选择、负责人更换和SOS范围保存；负责人必须是成员，先更换再移除。已有历史保留，首版采用停用而非硬删。
5. 人员终端摘要由账号及当前设备关系派生，按人员去重；归还旧设备后不作为该人员当前终端，历史会话快照不改。
6. 分组不授予数据权限，PC/APP/安全帽可达仅模拟摘要；无呼叫/广播/自动接听/真实SOS按钮。

**验收：** 两角色操作/范围不交叉扩权；厂站管理员不能自提权；新账号授权、禁用和重置效果可演示；组负责人/成员约束可验证，换领后终端摘要一致。

### A6：模拟接入、同步任务与审计界面

**前置：** A1～A5主数据和审计写入已稳定。

1. 六类连接器配置及记录工作区，提供受控示例地址、映射和不可编辑的假凭据占位；保存仅本页内存，不允许真实密钥输入或向地址发请求。
2. 模拟测试成功/超时/字段不匹配由确定性场景决定，记录配置版本及每次尝试；成功标签为“模拟测试通过”，不变更真实接入状态。

## 4. 测试门槛与交付制度

### 每阶段必须执行

| 层次 | 最低覆盖 |
| --- | --- |
| 服务/逻辑 | 新规则、正常与失败、长ID、版本和幂等、范围权限、取消、未提交无业务副作用 |
| 页面流程 | 通过应用内Mock操作仓库，筛选分页、详情返回、输入保留、失败提示、切厂站/身份、刷新恢复 |
| 工程隔离 | Mock网络检查、正式依赖图/产物排除、现有功能回归，旧失败与新增失败分别记录 |

浏览器网络拦截可用于探测禁止请求或旧正式模式隔离测试，但不能用拦截“返回成功”替代Mock命令真实修改内存的验收。测试失败记录命令、错误和影响；不自动修复全项目格式、不安装升级依赖来掩盖环境问题。

每阶段运行现有`test`及新增`test:admin-mock`、lint、Mock构建/预览；触及入口、路由、共享组件或配置时必须追加prod/stage构建，A0与A7全部执行。执行命令以A0确认的包管理器为准，不伪造已通过结果。

### 五条最终演示链

1. 组织/厂站/人员/名册→三类设备建档→整单领用→部分归还→历史及审计。
2. 损坏归还→维修→库存→再次领用；无法修复→报废→历史保留。
3. 创建模拟账号→角色及范围→切换身份→允许与拒绝→账号禁用或权限变更生效。
4. 协助组成员/SOS范围→成员换设备→当前终端变化→历史不变，不发送通知。
5. 模拟测试失败→映射修正→同步预览确认→重复任务无重复对象→审计和工作台一致。
