# V2-1 人员装备查询与模拟领用归还

实施日期：2026-09-18。范围仅新前台、前端测试及本文档。未修改或启停后端、数据库、缓存、原 PC、安卓及设备服务；没有新增依赖。

## 交付范围

- 七个一级菜单不变，人员装备工作区开放“装备查询”。新增装备列表、独立详情、筛选/分页 query 与安全返回；登录恢复支持装备地址。
- 人员列表右侧两处装备摘要、独立人员详情、装备列表/详情共用 Mock 弹窗。原数据库 demo 领用组件不变，Mock 没有调用它的写请求。
- 仅演示负责人可操作。未知/冲突关系禁止操作；离线、通信未知、过期仅提示。带表不生成传感能力，不发送命令。
- 未提交选择关闭/离开前确认；失败保留选择；版本冲突必须重新读取，不自动重试或换绑。提交中按钮禁用；账号、厂站或会话变更清空弹窗并取消请求。
- 操作完成刷新人员、装备、历史、视频当前关联及工作台。装备筛选导致当前页变空时回退最后有效页。历史事件、资料、轨迹及种子流水保持不变。

## 内存数据与服务

主数据位于 entities.people/devices；人员类型槽位、设备各有版本及明确的关系来源证据。relations.assignments 保存当前/关闭关系，relations.history 保存独立操作流水。关系未知与无关系但明确未领用分别表达。种子当前绑定标记 CURRENT_SNAPSHOT_ONLY、开始时间为 null，不伪造新增流水。

mock/assignment-model.js 统一派生人员三类装备、设备当前领用人、视频 CURRENT 关联；工作台从相同投影计算数量。设备上报时间、通信、电量不会因领用改变。

mock/equipment-service.js 执行查询和命令。Mock transport 在仓库事务副本内再次检查会话、取消信号、厂站/对象、负责人身份、关系及版本，通过后一次提交。相同 operationId 和业务输入重试返回原结果；不同输入拒绝。失败不提交副本，不产生流水；重复成功不增加仓库修订号。

错误包含 code/errorCode/requestId：权限 403、不可见对象 404、版本或关系冲突 409。查询默认 20、上限 100，字符串 ID 不转 Number。该设计仅保证单页面演示一致性，不提供真实服务端安全或多客户端并发保证。

构建期别名 @equipment-provider、@mock-assignment 隔离实现：Mock 使用内存服务；正式/预发布/数据库 demo 使用未开放提供器及禁用说明。不存在接口失败回退、路由开关或新增后端装备端点。

## 演示步骤

1. 新前台目录运行 npm run dev:mock，打开 http://127.0.0.1:5179。
2. 选择演示负责人、一号厂站；工作台已领用装备数为 68。
3. 人员装备中选择“演示人员1-02”，在安全帽卡点击领用，选择 MOCK-1-2-helmet 并确认。
4. 人员装备已领用、历史多一条领取，工作台变为 69；装备查询可查看相同人员/关系。
5. 从该装备详情确认归还，工作台恢复 68，人员历史再增加一条归还。
6. 切菜单保留操作；刷新页面恢复种子和 68。模拟会话单独保存在 sessionStorage；业务数据不写入 IndexedDB/localStorage。
