# 智能穿戴设备平台：PC后台业务重组与纯前端演示方案 V2

日期：2026-09-19。状态：本轮方案稿；尚未实施应用改造。适用工程：`pc前端代码/melhat_pc-main`。

## 1. 本次改变什么

先把原PC工程改造成可以完整操作的管理中心原型，供领导确认功能、流程、字段及权限，再另行开展后端改造。所有业务查询和提交由独立前端Mock服务处理；不要求后端在线，不建表、不迁移、不改后端、不操作真实账号、设备或外部服务。

这不是只画静态页面：建档、领用、归还、维修、报废、人员维护、授权、分组和模拟接入都应更新同一个内存仓库，产生可查询的历史及模拟审计。它也不是生产系统：不承诺持久保存、服务器安全、真实设备能力或跨端一致性。

本稿取代旧《01-PC后台管理系统整体改造方案》的当前实施范围；旧稿保留作为历史和后续正式接入参考。发生冲突以本稿为准，尤其取消以下前提：

| 旧稿安排 | 本次调整 |
| --- | --- |
| 九个一级菜单严格按PDF原图顺序 | 按管理任务重组为六个工作入口；页面参考图不等于菜单需求 |
| 前端与后端身份、表结构、接口同步建设 | 先实现前端演示；后端接口只登记需求，不实施、不调用 |
| 后台独占领用，前台仅查询 | 前台已有领用归还演示；后台保留管理员办理视角，未来共用同一业务服务 |
| 当前做真实登录、数据库事务、WebSocket联动 | 独立演示身份、内存操作、明确模拟结果；真实能力留待后续 |
| 页面差异都以PDF为准 | 视觉参考PDF，导航和交互优先服从已确认的业务流程 |

名称：**智能穿戴设备平台 · 管理中心**。后台服务于资产管理员、厂站管理员、人员/权限管理员、集成人员和审计查看者，不再复制前台监护工作区。

## 5. Mock架构与运行隔离

### 5.1 独立模式，不复制一个新工程

在原PC工程新增构建期`admin-mock`模式，保留原正式入口。使用构建别名选择bootstrap、路由/认证和服务提供器，Mock入口不导入旧user Store及自动WebSocket链路。不能依赖接口失败回退，也不能在URL或浏览器存储中切模式。

计划命令：`dev:mock`为127.0.0.1:5181，`build:mock`输出独立`dist-admin-mock`，`preview:mock`为127.0.0.1:5182；严格端口检查，冲突报错，不占用或停止前台5176/5178/5179/5180和旧PC5175。检查时5181/5182未见监听，实施启动仍需重新检查。Mock无业务代理。

保留原`dev/build:prod/build:stage/preview`行为。新增后台业务在正式模式未完成真实适配前不开放；生产包不得包含模拟身份、种子、控制面板。复用外观组件不等于必须导入其旧HTTP模块；提供器缺少实现时明确返回未接入，不发猜测的接口请求。

### 5.2 数据与服务

- 仅共享页面内存仓库保存实体、关系、历史和配置；Pinia管理上下文和修订通知。切页保留，刷新重置；不保留业务草稿到磁盘。sessionStorage只保存独立模拟身份键`Wearable-Admin-Mock-Token`，不触碰原`Admin-Token`或前台Token。
- 种子包含两个有数据厂站和一个空厂站，人员、账号、组织、区域、三类设备、有效领用、历史、维修、角色授权、协助组、连接器和审计统一关联。每个主要列表至少一组超过20条数据；包含长字符串ID、未知、离线、过期、关系冲突、停用及报废样例。
- 查询默认20条、最大100条；统一取消信号、固定200ms延迟、requestId、业务errorCode。区分400参数错、401会话失效、403无权限、404不可见、409版本/关系冲突及来源失败。取消不弹失败；迟到响应不覆盖新对象。
- 页面只能调用查询/命令服务，不能直接改种子。命令携带siteId、目标ID、expectedVersion、operationId；同键同输入返回原结果，同键不同输入拒绝。
- 权限、范围、状态、版本先在事务副本中校验，成功一次提交实体、关系、流水、审计和修订通知；失败不产生成功流水。提交前取消/切换身份不得落入新身份上下文；提交后关闭弹窗不回滚已经完成的内存操作。
- 明确只保证当前页面会话的一致性，不声称多浏览器并发、服务器事务或防篡改审计。

### 5.3 模拟身份与场景

默认身份：演示系统管理员（全部演示厂站与管理权限）、演示厂站管理员（一号站的人员/资产/协助组维护，不可修改角色授权或集成凭据）、演示资产管理员（一号站建档/发放/运维）、演示审计员（授权范围查询，无写权限）。这是评审默认值，不代表正式岗位授权。

身份选择不是真实密码认证。账号维护可新增一个模拟账号并赋角色，在演示身份选择中验证其权限；不要求用户输入真实密码。密码重置仅修改模拟凭据版本并留下脱敏记录，提示“未修改真实密码”。内置演示系统管理员不可删除、停用或被撤销必要权限，避免原型锁死。

控制面板提供确定性的正常/未接入/失败/分区无权、下一查询延迟3秒、会话失效及重置。重置二次确认，只清本后台内存及模拟身份，不清其他端会话。登出保留本页生命周期业务数据、清选择缓存；刷新后恢复种子，若保存的自定义身份已不存在则回登录。

## 6. 需要打通的管理业务链路

### 6.1 基础资料：组织、厂站、人员和当班名册

组织树和厂站区域树独立，关联不是授权；新增/编辑/启停要反馈到选择器。人员主键与账号主键分开，无账号人员可领用；重名不合并。首次支持手工维护和选择人员形成班次名册，不先做Excel批量导入和自动排班。

厂站/区域/组织存在有效子节点、人员、设备等引用时禁止删除，显示影响清单；采用停用保留历史，但有活动业务时同样要求先处理依赖，不做静默级联。人员有有效领用时禁止停用，先归还；账号停用不自动停用人员或归还装备。当班名册按班次时间与personId去重，名册不等于有权登录的账号列表。

### 6.2 设备建档与型号能力

新增安全帽/安全带/手表，保存编号、SN、厂商、型号、厂站、资产信息及备注；平台编号唯一，厂家身份按厂商+SN判断。不按名称合并，不允许通过编辑基础资料直接修改领用人或生命周期。

新建默认库存、明确未领用、通信未接入、能力待确认。使用中不直接变更厂站、类型或关键身份；库存设备跨站调拨另列后续需求，本期也不借编辑绕过。资料修订保留前后值，报废设备只读。

能力采用文档声明、实例装配、接入情况、验证情况及数据来源多轴结构，与前台概念一致；手工配置不能把真实能力标成已验证。安全帽区分型号/选配；安全带状态仅需求模拟，不发锁止命令；手表体征展示是前台模拟需求，不证明厂家规格。本后台不新增健康诊断或重复的人形大屏。安全带位置不能一律推定来自安全帽，必须有明确来源关联，否则未知。

### 6.3 发放与回收

从人员或设备入口进入同一办理面板。首版一人可选帽/带/表各一件；同人同类最多一件、同设备最多一条有效关系。批量选多类装备整单原子提交，归还允许按设备明细部分归还，每件单独留痕。

只选择同厂站、有效人员及库存且关系明确未领用的设备。离线、通信未知和数据过期只提醒；领用关系未知或冲突禁止办理。历史快照起始时间不明仍为未知，不补造流水。

归还选择完好/需检修。完好关闭关系、回库存；需检修关闭关系并原子创建维修单、进入维修中，避免损坏设备短暂可领。经办人从当前模拟身份取得，操作时间与源时间分开，不提供任意补登记。

成功刷新后台自己的台账、人员详情、当前关系、历史、库存和工作台；不修改过去事件、位置、资料或体征归属，不宣称另一前台已同步。

### 6.4 维修、停用、恢复与报废

| 当前状态 | 允许动作及前置 | 结果 |
| --- | --- | --- |
| 库存且无领用 | 送修，填写原因/负责人 | 维修中，创建维修单 |
| 维修中 | 完成维修并记录检测结果 | 验收通过回库存；未通过保持维修中 |
| 库存 | 停用并填原因 | 停用，禁止领用 |
| 停用 | 检查通过、无活动维修单 | 恢复库存 |
| 库存/停用 | 无领用且无活动维修，原因+编号复输+二次确认 | 报废，只读保留历史 |
| 维修中 | 显式终止维修为“无法修复”，同一操作确认报废 | 关闭工单并报废，双记录，不遗漏活动工单 |
| 使用中/关系未知或冲突 | 禁止直接送修、停用、报废 | 指引先归还或核实，不提供强制解绑 |

报废不是删除、不允许普通恢复；其他关联记录仍可追溯。失败保留表单输入，版本冲突提示重新读取，不自动重试或替换设备。

### 6.5 账号、权限与协助组

账号创建/编辑/停用、关联人员、分配角色；角色由操作和厂站/区域范围组成。按每个角色的“操作∩该角色范围”判断，再取并集，不能把A角色功能与B角色厂站交叉扩大。模拟服务和界面都校验；角色变更清缓存、更新当前可见范围，失去当前厂站返回可见入口。

授权树采用应用及稳定操作码，不把前台旧九菜单标题固化进权限码；前台权限仅配置草稿/预览，不改变另一个会话的权限。系统管理员维护角色，厂站管理员只能给账号分配预设且不超过自身范围的角色，不可自提权。区域范围未知时不默认开放全厂。

协助组按人员维护成员、负责人、启停和SOS通知范围，成员数按人员去重。终端是当前映射的模拟摘要，不是组成员资格或在线事实。负责人必须是有效组成员，移除前先更换；换领设备后当前终端摘要更新，历史参与者不改。不实现后台呼叫、广播、SOS发送。

### 6.6 集成预览与模拟执行

提供安全帽、安全带、手表、人员、工作票、安监六类连接器作为二级配置分类，不作为六个新菜单。表单只保存演示名称、字段映射和受控示例地址，凭据使用不可编辑的示例占位，不收集真实密钥。

“模拟测试”由场景显式返回通过/超时/字段不匹配，记录配置版本与尝试时间，始终显示未访问外部系统；不能写成真正接入成功。模拟同步链路为：读取固定外部样本→映射校验→预览新增/更新/冲突→确认→入库及审计。无厂站映射或身份冲突禁止确认；配置/目标版本变化使预览失效，需重做预览。

同步只更新明确允许的来源字段，不覆盖本地厂站授权、领用关系、生命周期、人工备注或历史。重复执行不重复建档。失败记录重试是新的尝试，关联同一任务/幂等身份，不制造重复资产。

摘要回传和核验回传仅使用本后台明确标注的合成样本展示独立状态，不读取或修改另一前台事件。成功回执不代表原系统结案。真实接口地址、凭据、数据迁移和自动任务全部留待需求确认后。

### 6.7 审计贯穿，不最后补日志

从A0建立公共审计结构，后续所有模拟写命令提交时带上对象、厂站、操作者、动作、结果、requestId/operationId及脱敏差异。A6再完善筛选、详情和导出界面，不到最后才补记录。

成功、业务拒绝和来源失败区分；无权记录不泄露目标敏感快照，取消不伪装成功。不能在审计页改写或清空历史，重置演示数据除外且有明确全局提示。CSV导出只导授权过滤结果，附模拟标记并防公式注入；不包含密码、Token、连接凭据。

## 8. 实施阶段与交付门槛

采用后台独立编号A0～A7，避免与前台V2或旧后端S阶段混淆。每阶段完成可演示的小闭环再推进，不按页面数量认定完成。

| 阶段 | 工作内容 | 门槛 |
| --- | --- | --- |
| A0 隔离与骨架 | 原功能基线、独立Mock入口/身份/路由、六菜单、仓库/权限/审计基础、简版工作台 | 后端不可达仍可进入；无HTTP业务/WS/RTC请求；不改旧正式行为 |
| A1 人员组织与授权基础 | 组织、厂站区域、人员、班次名册；账号、角色及范围的基础操作 | 新建人员可选用；无账号可领用；切身份/厂站权限可演示 |
| A2 设备资产基础 | 三类建档/查询/详情、型号能力和编辑约束 | 新设备库存未绑定，能力不假设；重复身份拒绝，档案及审计一致 |

## 9. 领导演示脚本与测试

### 9.1 必须贯通的五条链路

1. 新建厂站区域/人员→关联班组和当班名册→创建设备→为无登录账号人员领用→查看人物与设备一致的关系→部分归还→历史和审计。
2. 损坏归还→维修工单→验收恢复库存→再次领用；另一设备维修失败→关闭工单并报废→历史可查、禁止再领。
3. 新建模拟账号→分配角色及一号站范围→切换身份→允许动作可办理，越权厂站及写操作被拒绝→授权变更后结果更新。
4. 建立协助组→成员/负责人/SOS范围→成员换领装备→当前终端摘要变化、历史保留→无实际通知请求。
5. 配置模拟连接器→故障测试→修正映射→预览导入→确认生成设备→重复执行不重复建档→已有领用不被覆盖→审计追踪。

### 9.2 自动化和人工验证

- 逻辑：长ID、分页和统计、关系唯一、整单失败、部分归还、版本冲突、幂等、维修状态机、未知通信不阻止台账操作、未知关系阻止操作、角色范围不交叉扩权。
- 生命周期：切站、切人、迟到响应、取消、会话失效、权限撤销、页面切换与刷新重置；自定义身份刷新失效可正常回登录。
- 历史：账号/设备改名、设备归还、成员调整不改过去快照；审计不记录秘密；未知源时间不用操作时间补齐。
- 浏览器：使用应用内Mock真实操作仓库，不用网络拦截代替业务实现；网络检查除本地静态资源和开发HMR外，无业务HTTP、真实WS、媒体、外部地图、RTC或设备请求。
- 工程：原有测试与新增逻辑测试、lint、prod/stage/Mock构建及Mock预览；不自动lint修复全项目。旧基线失败先记录和归因，不能为了通过擅自升级依赖或改后端。
- 并行：后台5181与前台5179可分别打开，独立登录/重置不相互影响；没有前后台数据同步必须明确显示，不把这种独立性当缺陷偷偷引入共享存储。

本期最终结论只能是“PC后台纯前端管理业务演示闭环完成”。不能写成真实认证、数据库事务、真机协议、生产权限或两端联调通过。

## 10. 暂缓与评审事项

### 10.1 明确不做

真实登录/密码策略、服务端权限、数据库/迁移、设备平台同步、文件服务器、WebSocket、RTC、后台视频与地图监控、自动锁止/远程设备配置、正式审计防篡改、跨厂站调拨、补登记纠错、复杂审批、批量Excel导入、前后台Mock自动联动。

原PC源码保留不等于原功能都在新Mock导航继续执行；未迁移的旧模块建立去向清单，真正关闭生产入口必须另行批准和验收。

### 10.2 评审默认值

- 六个入口、浅色管理界面、管理员视角；A0评审导航和工作台，不以“和PDF不一样”为优化目标。
- 同人同类一件、同站领用、离线可办理但关系未知不可办理；A3评审实际办理职责，未来两端规则必须统一。
- 报废不可普通恢复、有依赖不级联删除；A4评审审批责任，原型不冒充正式审批。
- 能力未知允许建档，不等于设备可用于真实高风险作业；手表体征模拟由前台负责，真实能力继续待厂家确认。
- 管理端维护主数据、监护端执行现场业务；真实接入时继续优先共用现有后端，不因两个前端而另造一套数据库和认证。

本轮只交付方案；下一步建议细化并实施A0。所有日期和工期须在阶段任务拆分后估算，不把PDF页数或设备硬件研发周期当开发工期。
