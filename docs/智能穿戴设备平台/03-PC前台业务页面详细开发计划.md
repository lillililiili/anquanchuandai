# PC 前台业务页面详细开发计划

版本：V1.0｜基线：已交付的 wearable-portal-web 基础框架｜状态：待执行的开发计划

## 1. 目标、现状与执行边界

### 1.1 建设目标

将现有九个占位模块逐步建设为真实可用的智能穿戴设备监护前台。界面以领导提供的前台 PDF 为依据，业务围绕“人员—装备—作业—位置/影像—告警—现场核验—追溯”组织，兼容安全帽、安全带、手表。

本计划安排前台开发及其必需的共用后端增量，不把原 PC 后台整体改造、安卓新页面或新建独立后端作为前置工程。后台台账、人员、领用、厂站、授权等主数据能力与前台共用，只建设一次。

本轮仅编制计划，不执行业务代码、数据库迁移、账号创建、设备指令或生产配置变更。后续进入具体阶段时，先明确该阶段涉及的代码与数据范围；真机广播、通话、SOS演练和生产迁移须安排受控验证。

### 1.2 当前真实进度

| 项目 | 当前状态 | 后续动作 |
| --- | --- | --- |
| 独立前台工程、深蓝壳、九菜单 | 已完成基础框架 | 在现有工程增量建设 |
| 登录请求、Token隔离、路由守卫 | 已实现；模拟流程已验证 | 补真实账号登录、角色和退出联调 |
| 业务页面 | 全部为建设中占位 | 按本计划逐批替换 |
| 厂站选择 | 未接入，当前禁用 | 接入授权厂站上下文后启用 |
| 安全帽旧功能 | 源码存在部分接口、地图和媒体实现 | 按实际服务与真机结果确认可复用性 |
| 安全带、手表 | 尚不能根据现有代码推定真实能力 | 获取协议、建立统一身份与能力适配 |
| 作业来源、现场核验、外部回传 | 尚无满足新业务的完整实现 | 共用后端新增领域及接口 |
| 真实测试账号 | 尚未提供；账号创建已按用户要求暂缓 | 进入真实联调前解决，不设置假登录绕过 |
| PDF品牌、航拍背景源素材 | 尚未取得独立正式素材 | 补素材后替换；当前并非像素级还原 |
| 依赖安全 | 前次审计记录Axios和Element Plus告警 | 上线前安排兼容升级及复测，不自动升级旧工程 |

框架既有48项浏览器检查不等于业务验收，也不能作为真机或生产联调已经完成的依据。

### 1.3 与早期整体方案的差异处理

以用户已确认并落地的框架为准：继续使用 Vue 3、Composition API、JavaScript、hash 路由、独立 sessionStorage Token；本计划不切换 TypeScript、history 路由或跨端免登。

保留现有 `/personnel`、`/supervision`、`/alarms` 路由命名，不因早期方案使用 `/people`、`/work`、`/events` 而重命名主菜单。后端资源名可独立使用 people/work/events，但通过 API 模块映射。

当前不依赖不存在的 `portal:access`。后续应用权限必须先完成后端实现、存量角色映射和账号验证，再启用前台入口限制；不能先加判断造成所有用户无法进入。

## 2. 建设原则与业务红线

1. 共用一个业务后端与权威数据源，不复制用户、设备、人员和领用关系。
2. 复用接口、算法、协议和已验证组件，不把旧页面整页复制后只改配色。
3. 前台围绕监护与协同工作，资产建档、领用归还、报废及系统授权留在管理后台。
4. 设备生命周期、通信状态、数据新鲜度、能力状态与安全核验结论分别表达。
5. 未领用不等于离线，在线不等于安全合规，安全带断连不等于未挂接。
6. 没有证据的能力不启用：不默认手表有心率、定位、视频，不默认安全带有独立位置。
7. 当班人数来自当班名册，不能用系统用户数或在线安全帽数量代替。
8. 历史归属按发生时的有效领用关系解析；今天更换装备不改写昨天的事件和影像归属。
9. 工作票审批、许可和销票继续由来源系统负责，前台不另造审批系统。
10. 认领、核验提交、外部回传及原系统结案是不同动作和状态。
11. 请求受理不等于设备执行成功；视频、广播、通话、抓拍分别展示真实回执程度。
12. 正式应用不在后端失败时降级为模拟成功；模拟数据只用于隔离测试，必须标明。

## 4. 共用数据契约：先统一再做页面

### 4.1 最小领域对象

| 对象 | 必需字段或关系 | 权威来源/约束 |
| --- | --- | --- |
| 厂站/区域 | siteId、areaId、名称、层级、坐标系、权限范围 | 后台维护，服务端鉴权 |
| 人员 | personId、人员编号、姓名、部门/班组、可选userId | 人员不等同于登录账号 |
| 班次 | shiftId、siteId、起止时间、成员 | 排班来源或后台名册，不推算 |
| 设备 | deviceId、type、SN、型号、旧hatId映射、siteId | 三类统一身份，保留旧端映射 |
| 当前领用/历史领用 | personId、deviceId、生效起止、issueId | 单一权威写入口，保证有效关系唯一 |
| 最新状态 | communicationState、battery、sourceTime、receivedAt、quality、reason | 缺字段返回未知，不填0或正常 |
| 设备能力 | capability、支持状态、验证状态、禁用原因 | 支持/待验证/不支持分开 |
| 位置 | 坐标、坐标系、源设备、源时间、精度或质量、有效性 | 未定位不返回虚构原点 |
| 作业 | workId、来源编号、区域、成员、来源状态、本地监护状态、同步时间 | 来源字段只读 |
| 事件 | eventId、来源消息ID、类型、发生时间、人员/设备快照、状态、版本 | 原始告警与衍生事件可区分、去重 |
| 核验记录 | eventId、版本、结论、现场情况、措施、证据、提交人/时间 | 草稿与正式提交不同；正式记录可追溯 |
| 资料 | fileId、类型、拍摄/接收时间、源设备、发生时人员、关联对象 | 文件身份复用，引用不重复复制 |
| 通信任务 | sessionId/taskId、参与人及终端、逐端状态、回执、模式 | 不以整体HTTP成功替代成员结果 |

先审查已有实体和数据约束，再决定新增表或扩字段，不根据上表直接执行一整套建表。历史关系缺失时标记未知，不能编造历史领用时间。

### 4.2 响应及错误处理

- 旧接口保留原路径、字段与分页契约，安卓不被迫同步升级。
- 新接口建议统一到 `/api/portal/v1`，这只是共用后端中的接口命名空间，不是新后端工程。
- 新列表约定 `{ code, msg, data: { items, total, pageNum, pageSize }, requestId }`；新详情为 `{ code, msg, data, requestId }`。最终字段在第一阶段冻结。
- 原接口的 `rows/total`、嵌套响应等只在适配器中转换；页面组件不得自行猜测多种结构。
- 日期使用带时区的ISO时间或统一毫秒时间戳，契约固定一种；查询区间约定左闭右开，展示使用业务厂站时区。
- 状态字段给出稳定枚举与未知值处理；空数组、无数据、数据源失败、未接入是不同结果。
- 写入携带实体版本或幂等号；冲突返回可识别错误，前端保留输入并提示刷新，不静默覆盖。
- 页面保留 `asOf`、数据来源和过期信息。聚合接口部分失败应明确失效分区，不用0代替。
- 列表分页、排序、导出与数据范围过滤在服务端完成，避免全量拉取后前端分页。

### 4.3 前台工程增量目录

沿用现有 `api/assets/components/layouts/router/store/styles/utils/views`。新增 `api/adapters` 处理旧接口映射、`components/domain` 放领域组件、`composables` 放查询/地图/媒体生命周期、`contracts` 放JS枚举与JSDoc契约、`tests` 放单元及契约测试。无需整体搬目录。

公共组件按实际页面抽取：`FilterBar`、`DataState`、`DeviceStatusBadge`、`EquipmentTriplet`、`DataFreshness`、`PersonSummary`、`EventSummary`、`MapViewport`、`VideoPlayer`、`VerificationForm`、`ExportTask`。复用现有 `PortalPanel`，不重新造布局框架。

全局状态仅保存用户、授权厂站上下文、必要订阅和进行中的通信会话；列表筛选优先进入路由查询参数，普通详情数据留在页面查询层，避免把所有响应存入Pinia。

## 6. 分阶段执行计划与完成门槛

各阶段的“完成”同时要求页面、契约、异常状态、测试与记录完成；只做UI或只接模拟数据不算真实业务交付。

### S0：开发准备与契约冻结

任务：

- DEV-001：记录新旧工程基线、现有未提交修改、旧功能去向；不覆盖工作区已有修改。
- DEV-002：建立17页设计对照表，确认素材差异及每页目标状态。
- DEV-003：盘点只读接口、写接口、演示接口和设备命令；给出字段样本与权限要求。
- DEV-004：冻结首批人员/设备/厂站DTO、分页、状态字典、错误码、时间和坐标约定。
- DEV-005：确认真实测试账号、授权厂站和至少一套安全帽联调设备；新设备资料列入依赖清单。
- DEV-006：制定依赖升级方案与回归范围，不在业务开发中无计划执行批量升级。

交付：接口矩阵、字段字典、状态字典、PDF页面清单、风险与依赖表。

门槛：首批页面字段均有来源或明确“未接入”的处理，不能存在靠猜测得到的人员、设备状态和厂站数据。没有账号时可继续UI与契约测试，但真实联调状态保持未完成。

### S1：公共业务底座 + 人员与装备（第一批重点）

前台任务：

- DEV-101：授权厂站下拉与加载/空授权/错误状态；切换时取消旧请求、清理旧数据，晚到响应不得覆盖新厂站。
- DEV-102：统一筛选、分页、状态徽标、三件装备展示及时间新鲜度组件。
- DEV-103：按F07实现人员列表、右侧人员/装备/作业/事件标签与选择态。
- DEV-104：按F03实现人员详情、三设备卡、当前作业、事件摘要、领用历史和能力受控入口。
- DEV-105：保存列表筛选与选中上下文，详情返回不丢筛选；扩展详情路由登录恢复。
- DEV-106：总览只建立F17布局骨架；未接入分区保留清晰状态，不写固定指标。

共用后端任务：

- 提供授权上下文、人员聚合列表及详情；复用真实安全帽身份，建立或复用三类设备统一映射。
- 梳理人员与账号、当前领用与历史领用；不能仅把登录用户表当全部现场人员。
- 对接当班名册；未接入前，F07“当班”数量显示数据未接入，不将设备关联人员冒充当班人员。
- 保证列表与详情数据范围一致；厂站选择不是权限控制本身。

门槛：真实安全帽能关联正确人员；未领用、未知、离线、过期、能力未确认分别显示；换厂站无串数据；设备换人后历史归属不被重写。安全带/手表协议未齐时可以展示真实档案和领用关系，但不得显示未经验证的遥测状态。

### S2：定位、轨迹、围栏与现场资料

任务：

- DEV-201：封装地图容器、图层、坐标转换、尺寸变化和卸载清理。
- DEV-202：F10实时定位：人员列表、位置来源、最后更新时间、区域和围栏图层、人员详情跳转。
- DEV-203：F09轨迹：设备/日期筛选、有效分段、数据缺口、事件节点、播放暂停和倍速。
- DEV-204：F06围栏：列表、绘制、节点编辑、撤销、表单、启停和历史版本；写权限未就绪时先交付只读。
- DEV-205：F05资料：类型筛选、卡片、详情、照片/录像预览、受控下载；保留原录音的检索入口。
- DEV-206：上传和资料引用基础，为下一阶段核验证据复用。

后端依赖：位置质量/时间字段、历史领用解析、地图坐标说明、围栏版本/适用范围、附件对象权限与上传服务。

门槛：无可靠位置不标点；轨迹缺口不插值连线；围栏历史不随编辑覆盖；下载和原图地址不能绕过对象权限；失败上传不能生成可引用的“成功证据”。

若厂区底图未配准，先验证真实地理底图或无地图数据状态；不得把真实经纬度任意投放到PDF示意底图。

### S3：视频监看

任务：

## 8. 实时更新与跨页联动专项

先提供可靠快照，再按能力增加受控轮询或推送。推送未就绪时不得显示“实时连接正常”。

1. 请求上下文携带厂站、筛选、版本；切厂站立即取消旧请求并清除旧视图。
2. 首次获取快照，再接收增量；使用游标或版本解决快照与订阅之间的数据空隙。
3. 消息包含messageId、siteId、entityId、version、发生/接收时间；去重、乱序保护、断线重取快照。
4. 前后台使用独立应用和会话身份，不能照搬旧PC/APP连接键造成连接覆盖。
5. 服务端按角色和厂站过滤，不能直接复用全量广播方式推送RTC凭据或敏感事件。
6. 页面更新不得抢走核验输入焦点，不自动改变选中人员，不在用户阅读时强制跳页。
7. 页面隐藏时暂停不必要轮询，恢复后重取快照；失败退避，避免每行人员分别请求导致请求风暴。
8. 人员到轨迹携带personId、设备和时间范围；事件到影像优先按发生时设备/时间查询，不只找当前装备。

### 11.2 关键业务验收场景

1. 人员只领用安全帽，安全带/手表显示未领用，不显示离线。
2. 安全带经网关失联，显示来源及最后数据，不直接判挂接违规。
3. 人员更换设备，实时关联变化，历史轨迹和事件保持发生时归属。
4. 切换厂站，旧请求晚到不覆盖新数据；伪造详情ID、媒体URL、下载参数被服务端拒绝。
5. 轨迹有缺口、设备时钟异常、位置过期时如实展示，不插值伪造。
6. 设备在线但视频断流，显示流中断而不是持续直播。
7. 两人同时认领、重复提交核验均只产生合法单一结果。
8. 草稿未提交不增加已核验统计；无法确认仍需跟进。
9. 摘要回传成功、核验回传失败分开展示，重试不重复创建外部事件。
10. 作业来源更新失败保留上次快照，不能自动显示已许可。
11. 群呼部分接通、广播仅受理时逐成员/逐端如实显示。
12. 演练不混入真实首页指标，不自动触发真实安监回传。
13. 上传失败或无权文件不能被核验引用，正式证据变更有版本和审计。
14. 相同过滤条件下总览、统计、明细、导出一致；无历史在线记录则标记不足。
15. 前后台同时登录不覆盖连接，旧安卓接口返回契约保持兼容。

### 11.3 性能与稳定性

S0确定厂站/人员/设备规模、位置频率、轨迹最大区间和视频并发，再冻结性能指标。可先以普通分页请求P95不高于2秒、核心列表可操作时间不高于3秒作为待评审目标，不作为已测结论。视频起播和通信建立需按厂家链路单独设目标。

进行连续值守、反复切页/切厂站、视频布局变更、推送断线重连和导出压力测试；检查播放器、监听器、定时器和请求数量不持续增长。首轮长稳测试可按8小时安排，正式值守要求更长时再延长。

- 不提交密码、厂商密钥、RTC长期凭据、真实敏感人员fixture。

## 12. 数据迁移与发布保护

开发环境迁移先验证表结构与历史数据，再备份、演练、核对记录数和映射。只执行经过评审的增量脚本，不重跑含DROP TABLE的初始化脚本。

当前领用关系只有一个权威写入口；旧绑定接口通过兼容层进入同一服务，不能新旧系统分别双写。迁移不能伪造历史绑定时间或自动合并同名人员。

发布按厂站灰度。回退前台版本不回滚已经发生的真实领用、核验和通信记录；后端需保持兼容读取与幂等。破坏性数据库回退不得作为常规发布回退方式。

本轮开发继续使用独立登录，管理中心不传长期Token。HTTPS网关、短时媒体访问、下载有效期、会话撤销、角色变更生效策略在上线前共同验收。

| 依赖 | 提供方/责任角色 | 最迟需要阶段 | 未就绪时可继续什么 |

## 14. 本计划的执行结论

推荐立即进入S0及S1的契约/页面部分，优先完成F07人员与装备、F03人员详情。后续按空间与资料、视频、事件核验、作业、通信、总览统计推进。

完整业务开发必然涉及现有后端增量，不能只靠改前端完成三类设备、厂站授权和核验闭环；但无需新建第二套后端，也无需先完成原PC后台全部重构。
