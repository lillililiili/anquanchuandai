# 后台 A3：领用、归还与损坏转维修实施记录

日期：2026-09-20。范围：原PC工程 `pc前端代码/melhat_pc-main` 的admin-mock入口、测试和后台专属文档。未修改前台、后端、Android、数据库、设备配置或锁文件；没有启动、停止或重启后端服务。沿用既有六菜单、浅色布局与依赖。

## 已实现的业务链路

- 发放与回收工作区：当前领用、归还记录、全部历史，人员/设备关键词、类型、办理号及分页；合法query、详情返回、登录恢复与安全返回过滤。
- 人员列表/详情、设备台账/档案和工作区使用同一个领用归还面板。人员入口办理1–3件不同类型，设备入口只办当前设备。
- 领用校验人员启用、槽位明确未领用、设备库存/未领用、无有效关系/活动维修单。通信、过期、资料和能力待确认集中提醒，提交必须确认模拟边界。
- 支持单件、部分或全部归还；按件完好或需检修。完好回库存；需检修同步关闭关系、转维修并生成独立活动工单，不出现可领中间态。
- 处理人来自启用且具有该设备资产办理权限的账号，只返回ID、名称和用于乐观版本检查的版本，不返回角色/授权档案。每件损坏设备独立选择；账号不必绑定人员。
- 新增维修单只读摘要，展示故障、设备、处理人快照、创建时间和来源办理号。旧种子缺失字段保持未知；维修处理留待A4。
- 当前关系由唯一集合派生；人员三槽位显式表达未领用、未知、冲突、不可见。A1新建人员三槽位明确为空，已有异常样例与初始指标保留。
- 按件独立流水、共同办理号；冻结人员/设备/经办人名称，归还追加而非覆盖。旧关系开始时间未知不补造领用流水。A1人员及A2设备历史统一范围和分页来源。
- 成功同步人员、设备、工作台和最近管理变更；历史不随当前姓名或关系重新归属；设备通信、源时间和型号能力不被办理命令改写。

## 服务及事务边界

新增的均为前端函数调用，不是真实HTTP接口：

| 分类 | 服务 |
| --- | --- |
| 查询 | assignments、assignmentHistory、assignmentCandidates、repairAssignees、maintenanceSummary |
| 命令 | assignments.issue、assignments.return |
| 关系模型 | relations.js统一device关系及person槽位；有效关系保存source/startedAt/endedAt/version |
| 历史及工单 | 每件history，整单batchId；需检修生成maintenanceOrders，保留来源关系及办理号 |

查询默认20、上限100，字符串ID、requestId、取消及独立错误状态。办理要求人员及每台设备可读，且人员区域与设备区域都具备assets:write；角色操作与范围成对判断，不拼接扩权。厂站拒绝403、不可见对象404、权限拒绝403、关系/版本/幂等冲突409。

命令携带人员、设备、关系及处理人相关版本；事务副本内完成全量校验，之后一次提交关系、设备状态、流水、工单、审计与修订。任一失败不留下部分数据。operationId同输入重试返回原结果，重试前仍检查当前权限。订阅者异常不会反过来把已提交操作报告成失败。

提交前取消、身份/厂站/授权变化不提交；面板对迟到查询和提交结果另作版本检查。注销/失效直接清除输入，未保存关闭/路由离开/切站受leave guard确认。关闭后恢复触发位置焦点；错误摘要可聚焦并链接字段，失败保留输入。

历史同时检查可见设备与人员范围；不可见人员快照不泄露。A3审计只存办理/流水/工单标识和结果，人员设备快照通过受范围限制的历史查询读取。仅模拟权限，不能作为真正安全隔离。

## 核心验收结果

通过浏览器界面在空厂站创建区域、人员和帽/带/表，实际调用页面内存服务（无网络拦截替换业务）：

| 步骤 | 可领 | 有效领用 | 活动维修 |
| --- | ---: | ---: | ---: |
| 三类库存设备建档 | 3 | 0 | 0 |
| 一次领用三件 | 0 | 3 | 0 |
| 安全帽完好归还 | 1 | 2 | 0 |
| 安全带完好、手表需检修归还 | 2 | 0 | 1 |

产生三条领用、三条归还，共六条按件流水；第一次领用共享一个办理号，最后两件归还共享另一个办理号。维修摘要关联故障及处理人；维修设备不出现在可领候选。另验证设备入口再次领用单件，刷新全部恢复种子。
