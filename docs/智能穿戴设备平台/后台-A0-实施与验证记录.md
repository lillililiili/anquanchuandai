# 后台 A0：实施与验证记录

实施日期：2026-09-19（本机时区）。范围：原PC `pc前端代码/melhat_pc-main` 及后台专属文档。结论以本文件实际验证结果为准，不等同于真实认证、设备或后台接口验收。

## 1. 基线与改动边界

- 原工程 Vue 3.5.12、Vite 5.4.21，保留JavaScript、Pinia、hash路由；未安装或升级应用依赖，未修改bun/npm锁文件。
- Vue与compiler-sfc 3.2.45不一致，列为后续统一依赖风险，不在本轮调整。
- 使用现有Node22.19/npm10.9和已安装依赖。node_modules是指向原代码目录的联接，避免重装污染共享依赖。
- 开始前存在原PC权限Store/菜单可用性改动和后端未提交改动；均保留。未修改前台工程、后端、安卓、数据库、账号或设备配置，未启停其服务。
- 增量改动为package脚本、Vite条件配置、独立Mock源码、测试、README和本记录。原HTML/原App/正式认证入口保持不变。

## 2. 交付内容

独立admin-mock入口、四身份、三厂站、六菜单、浅色管理骨架、管理指标及只读明细侧面板、确定性场景控制、双确认重置、权限占位与错误页面。

身份与范围：

| 身份 | 范围 | 权限边界 |
| --- | --- | --- |
| 演示系统管理员 | 一号、二号、空站 | 管理权限；A0无业务写按钮 |
| 演示厂站管理员 | 一号站 | 只读模块及后续人员/资产/协助组操作权限 |
| 演示资产管理员 | 一号站 | 概况、资产、人员、审计读取；无权限协作/接入配置权限 |
| 演示审计员 | 一号、空站 | 只读 |

每个有数据厂站含25名人员、36台三类装备。四个指标为36/17/12/3，未知与冲突各1。空厂站均为0。离线设备不从明确可领设备中剔除；不把未知解释成未领用。初始领用流水、管理审计为空；有效关系为开始时间未知的快照。

仓库保存独立人员、账号、范围授权、资产、有效关系、历史、维修、协助组、集成和审计集合。工作台、明细和当前领用人员由同一关系集合派生。未来命令只能经事务副本提交，具备版本、幂等、取消和脱敏审计基础；A0未注册任何业务命令。事务测试使用隔离命令，不进入页面。

| 原功能/入口 | 本次处理 | 后续方向 |

## 5. 旧基线问题与未验证能力

完整lint阻塞：ESLint8.57.1加载`@typescript-eslint`时，`ts-api-utils`报告`Cannot read properties of undefined (reading 'Intrinsic')`。开始实施前已存在；未通过升级/重装依赖修复。日志在原PC的`a0-baseline-lint.log`、`a0-lint.log`。本轮新增源码使用独立无TS插件配置检查通过。

原正式业务没有真实账号/设备联调；未证明生产权限、数据库、设备协议、RTC、文件存储和外部系统可用。模拟身份和客户端范围判断不构成生产安全隔离。后台与前台内存不能自动同步。A0没有建档、人员维护、领用归还、维修报废或通用修改按钮，也不生成模拟成功流水。

后续进入A1前，应沿用此内存服务、角色与范围组合判断、取消及事务基础，不能连接原写接口；原全量lint依赖治理需单独确认，不扩散到前台或后端工程。

## 6. 使用入口

启动和目录职责见原PC的`README-admin-mock.md`。打开 `http://127.0.0.1:5181/#/admin/login`，选择演示身份，无需账号密码。刷新即恢复种子；演示控制的重置只作用于本后台Mock。
