# 统一接口约定草案（S0）

版本：S0-draft　状态：冻结约定，尚未把全部旧接口改到 `/api/v1`  
适用：后端、PC、Android 新接口。旧若依 `AjaxResult` / `R` 暂并存。

新业务接口从 **S1** 起使用 `/api/v1`，并遵守本文件。S0 不批量改旧路径。

## 1 响应外壳

新接口使用：

```json
{
  "code": 200,
  "msg": "ok",
  "data": {}
}
```

- `code` 为业务状态，不是 HTTP 状态的别名。HTTP 仍应反映认证与网关错误（401/403/409）。
- 成功：`code = 200`。
- 旧接口可能把分页字段放在外壳上（`rows`/`total`）。新接口分页一律放在 `data`。

## 2 分页

请求：

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `current` | 页码，从 1 开始 | 1 |
| `size` | 每页条数 | 10，服务端上限另定 |

响应 `data`：

```json
{
  "records": [],
  "total": 0,
  "current": 1,
  "size": 10
}
```

- 空列表：`records` 为 `[]`，`total` 为 `0`，`code` 仍为 200。空数组不是失败。
- 不要用 `null` 表示“没有数据”。

## 3 标识与时间

- 对外 ID（人员、设备、事件、厂站、领用）以 **字符串** 返回，避免 JavaScript 丢失 `long` 精度。
- 旧若依数字 ID 在过渡期可能仍是 number；新 `/api/v1` 必须是 string。
- 时间使用带时区的 ISO-8601，例如 `2026-09-08T12:00:00+08:00`。旧接口的 `yyyy-MM-dd HH:mm:ss` 视为未迁移。

## 4 写操作与版本

- 写操作成功后返回受影响对象的 `id` 与 `version`（乐观锁）。
- 客户端提交过期 `version` 时返回 **409**，不要静默覆盖。
- 重复提交使用幂等键（后续模块在契约中声明）；重复成功不得再写一条业务记录。

## 5 错误码

| HTTP / code | 含义 | 客户端提示方向 |
| --- | --- | --- |
| 401 | 未登录、令牌无效或已过期 | 未登录或登录已过期，请重新登录 |
| 403 | 已登录但无权限或超出厂站范围 | 没有权限执行该操作 |
| 409 | 状态冲突、版本冲突、重复领用等 | 当前状态冲突，请刷新后重试 |
| 400 | 参数错误 | 使用服务端 `msg` |
| 404 | 资源不存在 | 访问资源不存在 |
| 500 | 未分类服务端错误 | 不要把堆栈给最终用户 |

隐藏按钮、前端校验不代表服务端已授权。服务端必须再次校验。

## 6 权限与范围

- 厂站、对象范围以服务端校验为准，不信任客户端自报。
- 列表、详情、导出、下载、通信、批量 ID 使用同一套范围规则（S1 起落地）。

## 7 数据来源

响应可带 `source`（可选）：`live`（真实接入）、`db`（库内记录）、`demo`（明确演示）。  
`demo: true` 的数据不得当作生产业务结果。演示接口不得在 `prod` 加载。

## 8 敏感字段

- HTTP JSON **不得** 出现 `password`、盐、内部令牌明文。
- 日志不得打印 password、Authorization、回调凭证明文。

## 9 与旧接口并存

| 类别 | 现状 | 迁移 |
| --- | --- | --- |
| 登录 `/login`、`/getInfo`、`/logout` | 若依 `AjaxResult` | S1 起 `getInfo.user` 已改为安全 DTO，路径暂不改 |
| 帽子业务 `/hat/**` | `R<T>` | S3 起映射到 Device |
| 演示兼容 `/system/space` 等 | 本地模拟，带 `demo: true` | 仅非 prod 且 `melhat.demo-mode=true` |

Android / PC 在 S1 前继续走旧登录路径；新模块不要再扩展旧分页字段位置。
