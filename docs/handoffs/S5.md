# S5 交接单（给 Android 协作者 B）

日期：2026-09-09  
契约：[s5-events.md](../contracts/s5-events.md)  
依赖：S1–S4。测试库再执行 `V005__safety_event.sql`。

统一安全事件是接警与处置的业务记录。旧 SOS/实时告警/围栏接口仍给旧页使用，不要当本模块真相。

## 联调

- `GET /api/v1/events`：默认未关闭；`type/status/personId/severity/updatedAfter`
- `GET /api/v1/events/{id}`、`GET /api/v1/events/{id}/actions`
- `GET /api/v1/events/inbox/count` → `{ count }`
- 认领 `POST /api/v1/events/{id}/claim` `{ version }`：条件更新，冲突 **409**「已被认领，请刷新」
- 处置/转交/关闭/重开见契约。高风险须复核员关闭。
- 模拟器（仅非 prod + demo-mode）：`POST /api/v1/events/simulate`

WebSocket 通知（不是存储）：

```json
{ "type": "wear.event", "eventId": "1", "siteId": "1", "severity": "high", "demo": true }
```

发到 `{userId}_1`（PC）和 `{userId}_2`（App）。断线后用 HTTP 列表/`updatedAfter`/`inbox/count` 补齐。

## 样例账号（密码 `admin123`）

- `siteA_duty` / `siteA_team_lead`：可认领 A 站
- `siteA_reviewer`：高风险关闭
- `siteA_readonly`、`wear_admin`：认领 403
- `siteB_duty`：看不到 A 站事件

种子：`seed-sos-a`（A 站 SOS）、`seed-fence-a`、`seed-sos-b`、`seed-closed-a`，均为 `demo: true`。人员快照来自领用时刻，不是当前绑定。
