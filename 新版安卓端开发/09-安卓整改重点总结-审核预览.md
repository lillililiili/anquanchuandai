依据客户《智能穿戴管理平台-整体设计方案》V1.0，安卓定位为**找人通话、接收告警、现场协助**。服务班组长与获授权接警人员；资产、人员建档、围栏配置等管理工作归 PC。完整两票、巡检工单不因换到 PC 就进入一期。

## 1. 推荐的新页面结构

| 主入口 | 负责什么 | 子页面 |
| --- | --- | --- |
| **通讯（默认）** | 按人找对象，选择可用终端，发起联系 | 人员详情、装备详情、呼叫准备、通话、TTS、通话记录；位置和作业仅作关联上下文 |
| **告警** | 统一接收帽、带、气体、围栏等告警，默认未处理 | 告警详情、发生时位置、关联人员、授权确认与处置说明；SOS 可从任意页进入同一详情／通话 |
| **我的** | 身份、本人装备、接警状态与个人设置 | 我的装备、接警设置、帮助；值班交接作为待审核兼容项 |

三入口是**安卓适配建议**，客户原文 §10.3 明确的是“App 做通话 + 收告警”，没有指定 Tab 数。原“现场”首页的信息分别归入上述页面，不再另造一个聚合管理首页。

## 2. 重点冲突及调整

| 冲突 | 本稿处理 |
| --- | --- |
| 现场首页堆管理工具，当前作业重复两遍 | 取消独立管理首页；作业合并为人员／告警的只读关联，指标归告警筛选 |
| 我的装备跳全站设备，同人和设备被算成多个联系人 | 本人装备归我的；通讯按人聚合，设备作为可选终端，人数与设备数分开 |
| “多选组呼”“安全帽发起”外观与真实行为不符 | 保留客户目标；依赖未完成时明确不可用，禁止暗中改单呼或手机发起 |
| 设备 TTS 与对讲落到同一无区分页 | 共用通讯业务，但分别进入播报编辑和呼叫准备，保留对象与动作意图 |
| 消息／SOS／异常核验易形成多套流程 | 统一告警详情和历史；手机优先接警、通话、确认，复杂复核／转交等按角色审核，优先归 PC |
| 固定人名、票号、装备、断连、重置成功混入正式界面 | 正式展示必须有事实依据；缺数据为空或未知，演示须显著标识 |

完整冲突表含 **19 项**，并给出每页职责、旧功能去向、父子关系、目标跳转图和返回规则，见 [07 页面职责与冲突整改方案](07-安卓页面职责与冲突整改方案.md)。

## 4. 保留目标与审核重点

**必须保留但仍需联调：**真实语音／视频、组呼、帽端发起、安全带未系／未挂钩、区域及楼层定位、后台接警、气体与扩展设备能力。无通信能力的告警来源设备应联络同一人的可用终端；来源记录不被替换。不能把“当前没做”写成“客户不需要”。

本稿建议审核以下三点：

1. 采用“通讯／告警／我的”三入口，按本文重新归属重复功能。
2. 采用客户暖石深色基线及配套浅色，以客户原则裁决参考图装饰冲突。
3. 值班交接、轨迹及复杂处置按角色和现场必要性决定兼容入口；不默认把旧管理功能全部搬回手机。

**后续架构约束：**客户 §10.1 明确“不复用脚手架”。实现前须单独确定新工程与旧接口、字段、数据的迁移边界，不能将本稿解释为只在原工程换皮即可合规。本轮不启动重写。
