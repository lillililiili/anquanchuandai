1  设计目标
1.1  为什么重做
原系统是「分体式智能安全帽」三端代码：若依后台、Flutter 管理端、第三方头盔平台胶水层。问题不在功能清单，而在产品被做成了帽子后台：表叫 hat，告警绑 hatId，App 和操作手册对不上，立体位置缺失，安全与完成度不合格。
重做不是换皮。产品要从单品后台，改成电厂能用的智能穿戴管理平台。
1.2  一句话
值班室看的是人：谁在第几层、身上戴了什么、有没有票、现在出了什么事。穿戴设备是入口，不是品类商城。

2.4  设计气质
三个词：专业、舒适、严谨。值班室灯光偏暗，界面默认深色暖石色，不要创业公司渐变，不要若依后台模板，不要游戏沙盘。参考：布朗仪器、无印良品的克制、航空座舱的信息密度、医用监护的可信。告警要能切开层级，但不要闪成恐慌屏。
3  设计原则
人是主对象。地图、告警、通话默认落到人。设备是人身上的槽位。
能力决定界面。有视频才出监控格，有对讲才出呼叫，有挂钩才出未挂钩。禁止 if (类型==帽子)。
位置必须分层。经纬度不够。电厂危险差在高度和封闭体：28m 空预器层、92m 轮毂、氨区罐区。
立体厂区是视图。和二维平面共用同一套人 / 设备 / 告警。不做每座厂的 BIM。
精确先于装饰。每个视觉元素要有职务。不用毛玻璃、大色块 KPI 墙、装饰动效。
告警一条河。帽、带、气体、近电、无票都进同一流水，用类型和等级区分，不拆三套告警中心。

4.2  不要做成这样
安全帽管理、安全带管理两套菜单。
首页一排在线率、告警数、正常率大数字卡片。
立体厂区做成独立「数字孪生系统」。

4.3  跨页状态
顶栏厂区选择影响监控、立体厂区、告警过滤。点告警可跳到监控或立体厂区并定位到该人。SOS 在任何页都能以顶条或弹层出现，主操作是「加入通话」。

6  页面设计
6.1  登录
一屏一张卡片。品牌 ROLLING，标题「智能穿戴管理平台」，说明「电厂作业现场 · 安全帽 / 安全带 / 后续穿戴设备」。主按钮文案是「进入值班台」，不是「登录」。不做插画、不做全屏视频。
6.2  实时监控（默认首页）
这是值长台的主屏，左右结构，不要做成报表首页。
顶条：SOS 时出现，文案含人、区域、设备号。操作：稍后 / 加入通话。
左：在线安全帽画面格（2×2 或 2×3）。格上是区域，格下是人名和编号。无视频能力的设备不出现。
右：当前厂区平面。锅炉、汽机、升压站、氨区等色块 + 人员点。红点对应未处理高告警。
底：本厂区未处理告警表，跳到告警页处置。
风电场切换后，平面改为塔基 / 箱变 / 塔筒投影，不沿用火电色块。
6.3  立体厂区
沙盘，不是数字孪生。只回答「在第几层、在不在筒里」。
火电：锅炉零米 / 12m 运转层 / 28m 空预器层，汽机运转层。人标在层上，未挂钩用告警色。
风电：地面、休息平台 46m、轮毂 92m、箱变。
一期用清晰剖面（SVG / 低面数示意）即可。禁止把 Three.js 实验沙盘当首页。重孪生若融瓴已有，二期嵌入，不挡一期。
6.4  设备
一张表，类型页签：全部 / 安全帽 / 安全带 / 气体胸卡 / 室内工牌。列：类型、编号、绑定人员、分组、状态、电量。操作：登记、详情、报废。未绑定显示「未绑定」，不要为每种设备做一套 CRUD 页。
6.5  人员
看人。列：姓名、岗位、部门 / 队伍、作业票、当前位置、穿戴。无票用告警色，不另做标签体系。点开才展开身上设备槽位。
6.6  告警
左表右详情。默认只看未处理。详情含类型标题、人、设备、位置、时间、处理说明、确认处置。不要把气体、挂钩、近电拆成三个菜单。
6.7  电子围栏
左列表右示意。围栏名称要能读懂区域，如「升压站带电区」「12 号风机塔基 15m」。规则：进入告警 / 离开告警。无票进入高风险区，等级高于普通越界。一期可先做多边形，圆形后补。
6.8  对讲广播
左：通话记录（单呼 / 组呼 / SOS）。右：广播编辑与范围（单人 / 分组 / 机组）。按钮：手机呼叫、安全帽呼叫、下发播报。安全带无对讲能力则不出现呼叫入口。帽端挂断按操作手册：长按 SOS 约 3 秒。
7  关键交互
7.1  SOS
帽端按下 → 平台记录 → 值班台弹层（人、位置、设备）→ 值长点「加入通话」→ 走音视频（现网为声网凭证模式）→ 结束。若 SOS 来自无视频设备，弹层改走同人已绑定且在线的帽子画面，不要空白接听。
7.2  未挂钩
安全带上报挂钩断开 → 告警进流水，等级高 → 立体厂区该层标红 → 值长可呼叫同人帽子或手机。高处（锅炉 28m、轮毂）默认高于地面未挂钩。
7.3  一人多设备定位
室外优先有 GPS 的帽子；塔筒 / 主厂房内切工牌或室内源；安全带通常跟人走，不各自打点。同一人在地图上只出一个点。
7.4  厂区切换
顶栏切换机组。监控平面、立体剖面、告警过滤一起变。不要让用户在三个页里各选一次厂。

9  立体厂区专项
9.1  轻在哪里
做：低面数厂区积木、可进的层、人点、告警色、点层看谁在。
不做：每根管子的 BIM、和 SIS 逐点对温度、写实渲染、每座厂扫几个月、Unity 当主界面。
9.2  模板
新厂选模板、填区域与 KKS、标层高。一期两套：火电（输煤 / 锅炉分层 / 汽机 / 升压站 / 氨区）、新能源（风机分层 / 箱变 / 升压站；光伏场区默认二维）。
9.3  与穿戴的关系
穿戴负责人在哪、什么状态；立体厂区负责让值班室看见在第几层。没有实时人员的沙盘是模型；没有层信息的穿戴在电厂是瞎子。
10  与原系统、硬件的关系
10.1  原代码怎么用
原 Android / PC / 若依后端只作接口与字段参考，不复用脚手架。操作手册 V1.2.1 仍是安全帽闭环的验收底：资产、监控、围栏、告警、SOS 通话、App 呼叫。手册未写的 AI 助手、打卡 mock 不进一期。
10.2  设备接入
帽子现网走第三方平台回调与控制（TTS、对讲、声网）。安全带几乎一定是另一协议。平台只认统一事件：上线、电量、定位、告警、媒体、通话凭证。厂商差异关在适配器。设备回调必须鉴权，禁止原 /ext/* 裸奔。
10.3  App
手册中的 App 是通话调度（选人 / 选帽、手机或帽子呼叫），不是四栏管理端。一期先交 PC 值班台给评审；App 按手册做通话 + 收告警，不把 PC 菜单搬到手机。
11  一期范围与验收
11.1  做
平台骨架：类型、能力、一人多设备、统一告警与位置。
安全帽：资产、监控画面、对讲 / TTS、SOS 通话。
安全带：入库、绑定、未系 / 未挂钩进流水，立体厂区能落到层。
火电 + 风电各一套区域模板与演示数据。
本文 8 个 PC 页面可走通主路径（含 SOS 弹层、告警处置、厂区切换）。
11.2  不做
每种设备一套后台。
完整电子两票、巡检工单、重型数字孪生。
AI Copilot、签到。
头环 / 耳罩 / 眼镜的完整硬件闭环（只留注册位）。
11.3  评审怎么看
