## 数据写入方法规划

1. **主数据和当前动作优先用真实业务接口。** 人员、型号、设备、领用/归还、任务动作、事件认领/处置/复核、交接使用实际权限账号，以触发校验、版本、审计和收件箱。不要每个动作都用超级管理员，否则无法检验权限。
2. **历史数据单独做受控种子批次。** 现有接口未必允许回填30天以前的领用与动作时间。必要时在测试环境通过经审核的历史导入事务创建关联记录，明确标记“历史合成”，不把人工构造的历史当真实曾发生的操作。前后校验领用窗口、状态机、快照和当前指针。
3. **接入流程使用现有重放适配器。** `/api/v1/ingest/replay` 的实验室批次与批量历史采样分开；前者验证原始报文、去重、在线状态、事件和围栏派生，后者提供足够数据量。
4. **不能持久化的 UI 状态不建假表。** 照片草稿、协助组、票据审批、真实 RTC 凭证先按功能边界处理。凭证不放种子文件或文档。

## 本批隔离、映射和重跑

建议批次名 `QA-SMALL-ORG-001`。现有库记录不批量删除或重置；新编号保存到后续批次清单，用业务键查重，并记录实际生成的 site/person/account/model/device/assignment/task/event/fence ID。

特别保留 UI 名称与编号，同时用外部批次清单识别归属。当前设备与人员的 `demo` 派生依赖 `create_by='demo'`，不能简单将 create_by 改成批次名导致合成数据失去演示标识。支持的 remark/payload 可带批次说明；事件/会话等使用本身 demo 字段。没有来源字段的表由批次清单追踪，不能为规划擅自改表。

重复执行应：相同编号已存在则核验归属；属于本批的缺失关联可以补齐；遇到他人同编号记录中止该项并报告。不能以“幂等”为由覆盖现有姓名、授权、任务状态和时间。

回滚按依赖逆序仅处理本批 ID。引用现有人员、厂站或文件的记录先解除关联；对已经参与人工联调的记录默认保留或归档。回滚方案待具体批次生成后给出，本轮不提供或运行清库命令。

## 必须保证的关联与字段规则

| 关系/字段 | 验收规则 |
| --- | --- |
| 登录账号与人员 | `sys_user` 与 `wear_person` 是不同实体，`account_user_id` 显式关联；不能用用户名或相同数字ID猜测 |
| 厂站可见性 | 账号授权、人员厂站关系、设备厂站、任务和事件厂站一致；跨站人员只在授权范围可选 |
| 个人装备 | `account → person → 未归还assignment → device` 可追溯；current_assignment_id 指向同一有效记录 |
| 领用历史 | 同设备区间不重叠，同人同类型有效领用不重复；历史不随人员改名/换帽被重写 |
| 任务 | ownerUserId 指账号、guardianPersonId 指人员；成员有效，装备要求使用支持类型；结束不自动关闭事件 |
| 事件 | 快照与发生时刻对应；event/action/inbox 有有效父记录；高风险待复核和关闭路径符合状态机 |
| 时间字段 | 使用接口真实字段 plannedStart/plannedEnd、issuedAt/returnedAt、occurredAt/receivedAt；不照搬预览别名 |
| 类型与状态 | person.status=0/1；watch 支持完成后才启用；设备 issued 应正确显示；不使用 active 代替资产状态 |
| 能力 | 能力来自型号；有帽不一定支持视频；安全带断连不直接推断违规；无遥测保持 unknown |
| 轨迹 | 只读合法帽样本、正确 WGS84 坐标、领用窗口内；位置未知/陈旧不产生越界判定 |
| 下载文件 | 记录、实际文件内容、文件类型及权限匹配；旧 demo:// 记录是负例，不是成功下载样本 |
| 测试来源 | 合成数据能执行真实数据库流程，但保留 demo / 批次来源；不能靠改标识假装硬件已接通 |
