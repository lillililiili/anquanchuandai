## PC 端目前能看到什么

| 现有 PC 模块 | 当前入口情况 | 使用的数据 |
| --- | --- | --- |
| 人员、组织、区域 | 菜单启用 | /api/v1/people、teams、contractors、spaces |
| 设备、产品型号 | 菜单启用 | /api/v1/devices、product-models、assignments |
| 作业任务、电子围栏 | 菜单启用 | /api/v1/work-tasks、fences |
| 事件记录、文件记录 | 菜单启用 | /api/v1/events、files；文件接口仍桥接旧帽表 |
| 值班台、人员位置 | 代码和接口存在，常规菜单禁用/隐藏 | 不能保证补数据后从当前侧栏进入 |
| 实时对讲、TTS | 常规菜单禁用/隐藏；legacy 路由受开关控制 | 旧页面还使用帽子旧接口，不能视为新版统一链路已验证 |

常规人员、设备、任务页面与安卓使用同一组 `/api/v1` 接口，因此入库后可以共用数据。具体账号还须有角色和厂站授权。**补数据不等于恢复被隐藏的 PC 功能，也不会改变独立网页预览的本地适配器。** 用户此前的“网页展示”继续显示本地演示数据，若希望它访问数据库，需另行规划联网模式。

## 不能用补数据掩盖的功能差异

| 优先级 | 已确认问题 | 后续处理边界 |
| --- | --- | --- |
| P0 | 后端 ProductModelService 和 LedgerImportService 只接受 helmet/belt；PC 选择器同样只有两类 | `watch` 需先改校验、类型查询和 PC 选择器；不能靠 SQL 绕过后声称已支持 |
| P0 | 安卓通用 deviceTypeLabel 没有 watch；assetStatusLabel 没有 issued | 即使库数据正确，可能仍显示“未知类型/未知”；属标签修复，不是数据缺失 |
| P0 | UI 示例字段与真实契约不同 | 人员用 status=0/1；时间用 plannedStart/plannedEnd、issuedAt；实际事件状态用 pending_review 等，不复制预览中的 active、handled、plannedStartAt、assignedAt |
| P0 | 预览 SOS 使用 critical、围栏使用 medium；后端当前规则产出 high/low | 本轮种子遵从后端规则；如要中等级别需先完善规则，不直接塞未知级别 |
| P1 | 安卓照片添加、删除、草稿是本机 UI；file_record 无 event_id 关联 | 可先补可下载文件；事件附件上传/关联需额外接口与存储设计 |
| P1 | SOS 协助组是本地状态，无对应协助组持久化链 | 可建 SOS 与单呼记录，不能用虚构组呼记录声称协助已接通 |
| P1 | 安全带传感、手表生理指标未形成现有可信遥测链 | 保持“未知/待确认”；不以库造值宣称已支持挂钩、心率或血压实测 |
| P1 | Docker 后端 melhat.demo-mode=true | 可测业务流程与演示会话；真正音视频/TTS 到设备须真实配置与终端，不在本轮擅自切换 |
