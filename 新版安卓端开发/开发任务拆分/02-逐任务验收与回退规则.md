# 逐任务验收与回退规则

本文件供后续UI任务使用。本轮不执行以下命令，不构建、不安装、不操作模拟器。验收和生成素材附属于具体T任务，不单列为没有可见成果的开发任务。

## 1. 每个任务开始前

1. 记录当前分支、HEAD、实际工作区差异、正在安装的APK与对应任务。原有用户修改、网络修复、PC内容不归本任务。
2. 打开本任务对应浅色原图（我的使用用户最新图），并保存当前同区域截图。原图内手机外壳、硬件孔和图外阴影不参与应用UI复刻。
3. 记录该任务真实文件范围，保存修改前文件与APK；不要仅记HEAD然后假定工作区干净。
4. 具体场景写在本任务书里；新增功能或缺陷修复先建立能复现行为差异的检查，纯图片和间距则使用原图对照。

## 2. 单任务证据目录

后续每任务保存到项目根目录下：

```text
新版安卓端开发/开发任务拆分/验收记录/T编号/
  说明.md                 本次改动、界面结果、接口状态、未通过项
  文件清单.json           工程相对路径、修改前哈希、新增/修改类型
  before-light.png        修改前同区域截图
  after-light.png         浅色实际截图
  interaction.md          原入口→对象→返回；输入与状态保持
  build-and-install.log   构建和覆盖安装结果
```

这只是后续目录约定，不创建假截图或空验收记录。T13—T16使用既有我的页面整改验收证据，不复制成假独立批次。

文件清单例子（字段定义，不是已执行记录）：

```json

```

## 3. 视觉比对

- 使用当前浅色参考图及相同或可比较的数据状态。先等比对齐手机内应用内容宽度，不能拉伸原图以掩盖偏差。
- 每任务只圈出本区域差异，同时回看相邻区域；参考图上存在的模块、人物、按钮不擅自缺失。
- 原图较长时允许真实滚动，不强压所有内容到雷电一屏；文字保持正常可读，底栏保持原交互。
- 主体位置、模块顺序、导航数量与文字零擅自变化。父目录12的≤4dp、比例≤3%是工程自检目标，不是自由改变布局的额度，也不是自动相似度分数代替人工复核。
- 真实视频／验证码／附件照片保持原色，不做滤镜失真。生成的示意地图持续标非实测。
- 未完成区域在阶段说明列清楚；开发自验与用户审核分别记录，不把局部通过当成整应用完成。T49仅检查具体弹层、空态与系统栏残留问题。

## 4. 功能验证

每任务至少验证对应原入口、正确对象、返回来源、页面状态保持和一种空／错／未知状态。按任务实际内容选择，不制造无意义测试。

有输入时：输入内容→打开子页→返回再进，确认内容或符合原规则的草稿仍在。联系人检查已选人员与终端，事件检查eventId与正文，地图检查视点和索引，通话检查同一会话及媒体对象。

已有接口用原方法、参数、权限和厂站上下文。准备界面打开不自动发真实通话、TTS或处置；实际写操作只对明确测试对象进行。没有接口时验本地交互及清楚的未开通反馈，不把模块删除后写“暂不验收”。

回归优先任务书所列测试。只检查受影响代码和行为；已经通过后不无故重复扩大测试范围。

构建返回成功且APK时间更新后才执行安装；失败不能安装上一次遗留APK冒充本任务结果。

```powershell
& 'C:/leidian/LDPlayer14/adb.exe' -s emulator-5554 reverse tcp:18084 tcp:18084
```

这里复用已确认的本机Docker后端18084与ADB反向端口，不改服务器和数据库。若使用原10.0.2.2方案，按既有 `bin/connect-ldplayer.ps1` 及父目录06记录执行，不能混淆两种地址。连接故障单独记录，不拿UI任务重搭后端。

每任务完成都要在雷电看到该区域实际效果；安装后走原入口，并保存截图。证据目录按任务ID建好后，可以使用：

```powershell

& 'C:/leidian/LDPlayer14/adb.exe' -s emulator-5554 pull /sdcard/ui-check.png build/ui-check.png
```

再把该真实截图放入当前任务验收目录，不能把原预览图或生成图当模拟器截图。

## 6. 失败时怎么回退

1. 停止继续叠加该任务后继；记录是布局偏图、功能错误、状态丢失还是范围超限。
2. 优先修当前区域；如需回退，从**该任务开始前的工作区文件**恢复。不是无条件恢复HEAD，更不是整仓reset。
3. 当前任务新增文件、图片按根目录相对路径移入 `垃圾桶/日期-T编号回退/`，记录来源、目标与哈希；移动前核对绝对路径仍在项目根内，保留恢复可能。
4. 保留此前任务已验收的内容。后继已依赖当前任务时先停后继并核对依赖，不只删一个共享文件让工程失配。
5. 雷电已经安装当前任务版时，覆盖安装该任务前保留的APK并检查界面；没有旧APK则用恢复后的源代码构建确认，不卸载清数据来“解决”。
6. 任务状态记已回退／返修，不能记已验收。

建议一任务一个可识别提交；用户未要求提交时也必须保存工作区级回退包与清单。禁止顺带提交、推送或覆盖不属于本任务的改动。

## 7. 全部完成后的最终交付

逐任务通过后再做一次完整验收：现场、通讯、消息、我的与00—08所对应子视图；再检查厂站、人员、设备、作业列表、监护、围栏、轨迹、接警和交接。每页均核对参考图、原入口、状态保持与背景归属。

最终APK覆盖安装到雷电，记录包路径、SHA256、构建参数、安装结果和冷启动截图。最终收口只修有证据的残留小问题；若再发现新布局需求，应新建小任务，不把最后验收变成一轮整体改版。
