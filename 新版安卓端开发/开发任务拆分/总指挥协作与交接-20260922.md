## 执行顺序与边界

1. 总指挥将用户任务拆成小步，明确目标、允许修改的文件/符号、保留行为、依赖、交付条件。执行者收到具体派工后开始修改；任务名称不等于文件所有权。
2. 同一文件每个阶段只安排一位写入者。共享路由、API、权限、模型、依赖、数据库迁移和公共 UI 由总指挥指定唯一负责人；跨模块需求先回报，确定接口字段、错误行为和交付顺序再写入。互相读取允许，互相代改须先调整分工。
3. 小步微调既有实现，保留用户指定样式与现有功能。发现明显小问题可在获派范围修复并记录；越界问题回传总指挥分配，不自行扩展为重构。保留其他人的未提交改动。
4. 执行者完成后回传文件清单、行为变化、依赖、检查证据和遗留问题，进入待命。部署、安装 APK、重启运行中的 Docker 服务、执行业务库迁移统一由总指挥在整个批次集成完成后执行。Git 暂存/提交/推送由总指挥统一安排，执行者不自行执行。
5. 验收测试由用户完成。执行者和总指挥做必要的静态、编译及明显错误检查；检查通过不等于用户验收通过。部署记录标明源码基线、构建参数、迁移、产物和实际运行状态。
