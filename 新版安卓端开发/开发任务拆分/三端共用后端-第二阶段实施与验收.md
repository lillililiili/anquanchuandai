# 三端共用后端：第二阶段实施与验收

日期：2026-10-07。对应用户确认的《安卓优先、三端统一的整改方案》第二阶段。

## 当前交付范围

本阶段完成共用 Spring 后端及 PC 必要配套，保留原有 PC 页面风格。安卓继续使用第一阶段的显式 Mock；真实接口替换、雷电模拟器三端联调属于第三阶段。

- 共用现有后台账号、人员、角色、厂站、区域、设备和领用台账；作业来源保持只读。
- 新增移动端登录、身份、厂站、首页、人员/装备/作业查询及装备办理入口。
- PC 和移动端共用事件查询、认领、现场补充、核验草稿、最终核验、照片及 SOS 协助服务。
- 手机和设备 SOS 保留真实来源，每条事件都有独立协助记录。结束协助不完成核验，不以语音接通作为接警前提。
- PC 后台增加新账号初始密码、真实密码重置及本人业务角色/业务权限；新账号默认没有授权。
- PC 事件和 SOS 改用共用业务接口，旧快照不能覆盖已迁移的事件、协助、核验及照片。
- `新版安卓端开发/音视频网页联调/` 未修改。

## 数据与兼容策略

人员、设备、领用、账号和角色仍以原有 MySQL 后台台账为准。现有 PC 编号保留，后台记录增加稳定的 `portalId` / `portalStation` / `portalDeviceId` 映射；不按姓名匹配，也不另建安卓业务台账。

事件及协助沿用主后端已有的 `guardian-state.json` 持久化，照片沿用后端文件存储；通过同一个 Spring 服务串行校验和原子落盘。后台台账到 PC 的兼容视图由服务端投影生成。此实现适用当前**单后端实例**部署；本阶段没有实现多实例共享文件写入或集群锁。

升级提供一次性、可重复读取的增量默认值：稳定编号、事件 `version`、真实来源、员工补充列表、按事件编号的协助记录及共用业务授权。历史数据和引用保留，不清空业务记录。旧事件无法追溯真实操作人的字段继续显示为历史记录，不伪造人员。

现有账号首次迁移时，将原登录规则对应的原密码转换为 BCrypt 哈希，保持旧账号能登录；之后只验证哈希。新密码至少 8 个字符且 UTF-8 不超过 72 字节，不写入日志或接口回包。重置增加 `credentialVersion`，旧会话随即失效；停用账号、调整角色/厂站/区域授权在后续请求重新校验。

已有工作票、历史影像、位置及装备遥测中仍有原项目的示例资料，保留原有示例标识；共享接口并不意味着这些资料已经接入真实外部来源。

## 接口约定

移动端和监护前台业务前缀为 `/api/guardian/v1`。登录后使用请求头 `X-Wearable-Token`，服务端会话有效期 8 小时。后台管理使用独立的 admin audience，会话不能互相冒用。

| 接口 | 用途 |
| --- | --- |
| `POST /mobile/login` | `{account,password}`，返回 `token`、`identity`、`expiresIn` |
| `GET /mobile/identity`、`GET /mobile/sites` | 当前身份、关联人员和授权厂站 |
| `GET /mobile/home?siteId=…` | 授权范围内事件、作业和装备聚合 |
| `GET /mobile/people`、`/devices`、`/works` | 必填 `siteId`；对应 `/{id}` 查询详情 |
| `GET /mobile/assignments?siteId=…` | 授权范围内领用记录及历史 |
| `POST /mobile/assignments/issue`、`/return` | 复用现有装备领用归还命令及版本检查 |
| `GET /events` | 可选 `siteId/status/type`，`pageNum` 默认 1，`pageSize` 默认 20、最大 100 |
| `GET /events/{id}` | 事件、当前版本、可用权限和本事件协助记录 |
| `POST /sos` | 手机求助，必填 `siteId/requestId`；说明允许为空 |
| `POST /events/{id}/claim` | 认领，待认领/待现场核验进入处理中 |
| `POST /events/{id}/observations` | `{situation,photoIds?}`，员工现场补充，不进入审批 |
| `POST /events/{id}/verification-draft` | 保存核验草稿 |
| `POST /events/{id}/verification` | 提交最终核验，随后只读 |
| `POST /events/{id}/photos` | `{blobId}`，将已上传照片登记为核验照片 |
| `POST /events/{id}/assist-join`、`/assist-end` | 加入/结束该事件协助，独立于核验和通话 |
| `PUT /files/{id}`、`GET /files/{id}` | JPG/PNG 原始字节上传和受权限保护的读取 |
| `POST /call`、`/call/end`、`/broadcast` | 复用现有安全帽语音/文字广播服务，检查实际设备和账号权限 |

除创建 SOS 外，事件写命令都必须携带 `expectedVersion` 和 `requestId`。请求编号使用 UUID 等 8–100 位字母、数字、下划线或连字符。同一次操作断网重试时，保留**同一请求编号和同一请求体**；相同编号不同内容返回 409。不要在请求结果不明时立即换编号重发。

版本冲突返回 HTTP 409，应提示刷新/载入最新草稿，由用户决定如何处理当前填写内容，不能静默覆盖或自动报告成功。越权读事件返回 404，缺少写权限返回 403；过期/停用会话返回 401。已核验记录禁止补充、再次核验、重开和继续修改协助。

最终核验字段为 `conclusion/situation/measures/photoIds`。结论使用现有 PC 选项：设备通信异常、需现场处理、暂无法确认。最终提交要求结论及现场情况；现场情况/措施最长 500 字。已核验仅表示平台记录完成，不改写外部设备解除状态。

手机 SOS 示例：

```json
{"siteId":"site-1","requestId":"8e6da80b-3254-43ec-a2f2-6cb339170431"}
```

手机求助 `source=manual_sos`，不伪造安全帽编号或作业关联。设备上报 `source=device`，沿用实际设备和当时关联资料；带设备时间戳的 SOS 重复回调按设备/类型/时间戳去重。旧协议没有稳定时间戳的回调暂不能可靠区分重试与新的报警。

照片须先生成 `upload-<UUID>` 并上传，再通过现场补充或核验命令关联事件。单张最大 10MB，检查 MIME 和文件签名，最多一次关联 20 张。上传者所有权、事件范围和照片用途由后端验证；已关联照片不能挪到其他事件冒用。

## 权限与账号操作

普通用户使用本人业务角色 `mobile-user`：本人资料/装备/参与作业/授权本人事件、现场补充和手机 SOS。必须关联启用人员；仅隐藏页面按钮不能替代后端校验。管理账号可以不关联人员，但此时不能发起个人 SOS，也不能把管理范围内装备当作个人装备。

服务端求交集检查角色授权与账号 `roleScopes`，同时检查厂站和区域。区域受限账号不会因为记录缺少区域而获得整个厂站权限。

新增共用业务操作码：`self:read`、`works:read`、`events:read`、`events:claim`、`events:observe`、`events:verify`、`sos:create`、`sos:assist`、`communications:voice`、`communications:broadcast`；人员/设备权限沿用原操作码。

PC 后台“权限协作 → 本地账号”操作顺序：新增账号、设置密码、关联人员，再编辑账号分配角色和厂站/区域。权限变更沿用原授权影响预览与确认流程。密码重置通过原账号更多操作入口完成，原受保护系统账号和自身账号保护规则保留。

后台接口仍为 `/api/admin/v1/query` 和 `/execute`。新增账号 `accounts.create` 的 `data.password` 必填；`accounts.resetCredential` 的 `password` 必填，仍要求 `expectedVersion/operationId/reason/confirm`。普通员工不能使用 PC 值守账号代替自己的账号。

## 第三阶段对接注意事项

后端保留原 PC 字符串编号和对象字段。安卓适配层需要区分后台人员 ID（如 `person-1-0`）与兼容展示 ID（如 `P1`）；身份接口同时提供 `ledgerPersonId` 和 `personId`。厂站同理区分 `site-1` 与 `S1`；装备办理使用后台真实 ID 及版本。

装备办理继续使用原命令结构：`siteId/personId/personVersion/items/acknowledged/operationId`；items 包含设备版本，归还还需关联记录版本和设备状况，不能用页面列表序号提交。

按登录和查询 → 装备办理 → 核验 → SOS → 语音广播顺序替换安卓 Mock。真实模式错误直接显示失败；开发预览的 Mock 必须显式开启，不做真实失败后的模拟成功回退。角色按钮使用身份/事件接口的权限信息，同时保留后端权限拒绝处理。
