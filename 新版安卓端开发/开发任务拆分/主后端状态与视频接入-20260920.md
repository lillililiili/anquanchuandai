# 主后端状态与视频接入（2026-09-20）

## 数据流

联调控制台仅提交修改；安卓不再读取联调进程的 roster/presence 内存数据。

- 联调控制台 → 主后端 `POST /api/v1/simulation/devices/{id}/state`。
- 主后端校验登录、模拟操作权限、当前厂站与设备归属；以接收时间写入设备遥测字段，Redis保存模拟状态/异常标签。设备行加锁串行处理状态修改。接口仅在非生产且启用联调时注册。
- 安卓通讯录 → 主后端 `people`、`devices`（含详情/currentAssignment）、`work-tasks`（含成员详情）。每10秒刷新设备，人员和作业关系支持下拉同步。
- 安卓作业详情 → 主后端作业成员 + 各成员 `people/{id}/equipment` + `devices/{id}`，不从装备检查结果推断在线。
- 安卓视频 → 主后端 `GET /api/v1/lab/calls/{callId}/video/stream?deviceId=...`，携带登录和厂站头。主后端鉴权后转发固定联调视频源，安卓不直连5188。

## 页面与交互

- 通讯录增加人员安全帽状态：正常在线才显示绿色“在线”；其余显示离线、异常标签、数据陈旧、状态未知或未关联。
- 未指定设备类型的在线筛选按人员安全帽判断；指定设备类型时，保持“同一设备同时满足类型和在线条件”的组合规则。
- 作业成员帽/带/表显示真实领用设备状态；独立保留“装备检查”的核验结果、人员调整与原有跳转。
- 选择员工呼叫时，只选主后端声明支持intercom的设备，避免把安全带一同拨入导致整组失败；播报仍独立选择。
- 视频保留比例、加载/失败重试、静音循环、全屏与挂断释放；进入后台暂停。

## 状态约束

- 联调状态携带 `simulation: true`、`source: simulation`；这些是主后端保存的测试输入，不能称为真实硬件遥测。
- 心跳30秒未更新后，主设备查询不再显示该模拟设备在线。
- 后续真实设备遥测可取代旧模拟状态。
- 联调控制台不能覆盖主平台设备领用关系；读取人员列表不会自动把设备上线。
- 控制台状态写入必须等待主后端受理，失败不显示成功。停用原先直接SQL更新/伪造定位心跳的同步方式。

## 当前边界

当前视频是联调目录中的MP4/WebM样片，经主后端以视频流传输，页面标记“联调视频”。尚非真实安全帽摄像头或真实音频驱动验收。通话信令仍由联调适配器模拟，安卓经主后端调用；正式设备音视频厂商接入不在本轮范围。

工作任务、人员、分组、领用关系继续沿用主系统接口；没有将联调临时人员关系写进安卓本地。
