# 首页多条 SOS 列表整改

本轮仅修改首页 SOS 入口、增加紧急求助列表和路由，复用当前 SOS 详情及处置接口，不修改后台和网页联调项目。

原因：首页通过 size=1 取得第一条 SOS 和总数，展示共 N 条；点击却始终只携带第一条 eventId，因此多条事件无法从此入口逐一访问。

修改后：
- 无未关闭 SOS：隐藏首页提示。
- 只有一条：保留直接进入现有详情。
- 多条：进入“紧急求助列表”，显示当前厂站所有未关闭 SOS；读取后续接口分页，页面连续滚动，无上一页、下一页按钮。
- 点击任意卡片进入其原有详情，保留认领、处置、通讯及记录功能；返回列表重新读取数据，返回首页重新读取数量。
- 列表沿用浅蓝背景、既有 SOS 顶部素材、白色圆角卡片、红色紧急标识。保留 Logo 和底部导航比例。
- 独立查询，不读取或写入消息页的历史筛选；厂站或账号变化后丢弃旧范围的请求结果。

验证：
- 修改前的多条入口测试失败，确实误开单条 EventReferenceView。
- 修改后 11 项针对性测试通过，包含三条求助逐条进入正确详情、接口分页合并、单条入口、空数据/跨站旧响应、消息页筛选隔离与连续列表回归。
- 本轮四个 Dart 文件静态检查无问题。

数据来源仍是 /api/v1/events?type=sos。复用既有 active 语义（服务端默认排除已关闭），并在列表校验 SOS 类型、未关闭状态和当前厂站。未注入新事件或修改事件状态。

雷电实机验收：debug APK 覆盖安装 Success，保留 18084 业务后端与联调开关。使用模拟器现有 A站值班员登录态验证首页共3条 → 列表共3条 → 向下滚动至全部显示 → 第二、第三条分别打开对应详情 → 返回列表 → 返回首页。第三条正确显示“演示人员01 / MH-DEMO-001”，首页仍显示共3条。保存列表顶部、底部与详情截图；未认领、关闭或更改事件。
