# 轨迹回放页面 · 2026-09-18

本轮按用户提供的轨迹回放截图改造原 `/tracks` 页面。已阅读客户《智能穿戴管理平台-整体设计方案.docx》，遵循按人员组织定位、室外优先安全帽位置的思路；保留当前接口只提供安全帽 GNSS 的事实，不新增或虚构室内定位能力。

## 截图元素与落地

| 参考图区域 | 页面实现 |
| --- | --- |
| 返回、ROLLING、厂区背景、页面标题及说明 | 复用现有厂区图片，等比例裁剪；页头沿用 148dp 和大字号自适应规则，标题 16sp、说明 12sp；提供返回和明确的示例预览入口 |
| 人员头像、姓名、编码、下拉箭头 | 点击整行打开人员搜索面板，显示真实人员姓名、编码及在职/历史状态；支持按姓名搜索 |
| 开始日期、结束日期、蓝色查询按钮 | 日期采用 YYYY-MM-DD；保留日期校验和原查询接口；无人员时引导选择人员 |
| 厂区地图与折线、人物位置标记 | 真实数据继续使用原 FlutterMap 和经纬度折线；显式进入示例预览后显示现有厂区示意图、示例折线和随进度移动的标记 |
| 进度条、起止时间、播放轨迹 | 可拖动进度，播放/暂停；播放到结尾可重新播放；当前时间点随之更新 |
| 轨迹来源、当前时间、当前数据 | 展示来源、时间和点数；真实数据保留定位质量；示例显示“示例轨迹点” |
| 底部导航 | 使用现有外层导航，无重复底栏，不改变原有比例 |

原有 0.5x、1x、2x、5x 倍速以及“定位时间”放入地图卡中的“回放选项”，避免常驻控件挤占地图。整页可连续滚动。

## 数据与功能边界

- 保留 `/api/v1/people`、`/api/v1/people/:id` 和 `/api/v1/locations/people/:id/tracks`，仍传递 UTC 日期范围并按原有规则分批查询最多 500 点。
- 保留人员详情深链接、搜索人员、日期自动查询、显式查询按钮、播放暂停、拖动进度、倍速及就近时间定位。
- 示例由用户主动打开，姓名、地图、数据来源和点数均明确标记。示例播放不发出真实轨迹查询；选择真实人员即退出示例。
- 无轨迹、人员加载失败、轨迹加载失败及无效坐标各有明确显示；不以示例冒充查询成功。
- 本轮未修改后端或其他页面。没有新生成图片，现有图片以等比例方式显示。
