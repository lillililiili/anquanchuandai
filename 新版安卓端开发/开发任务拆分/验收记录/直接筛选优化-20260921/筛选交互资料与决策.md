# 事件与通讯：直接筛选交互资料与决策

研究日期：2026-09-21。范围：降低点击次数、保留多选、减少筛选区域占用，并统一两个页面。本文记录研究与建议，具体完成情况以实现和验收记录为准。

## 第一手资料核查

1. **Material 官方组件**：Filter chips 用于按标签筛选内容，可替代勾选框，具有明确的选中状态；应成组出现，组与选项都有可理解的标签。它适合直接展示少量常用选项，无需每次先打开菜单。[Material Web — Chips](https://material-web.dev/components/chip/)

2. **即时筛选与批量应用没有统一答案**：NN/g 根据用户是否连续组合条件、结果响应速度进行取舍。其移动端批量应用建议针对连续刷新与等待的成本，同时也提出可在用户停止选择一小段时间后更新。页面自动跳动、频繁结果闪烁会破坏连续选择。[Katie Sherwin，User Intent Affects Filter Design](https://www.nngroup.com/articles/applying-filters/)

3. **让条件与结果保持联系**：NN/g 的移动筛选研究强调，用户需要看到条件如何影响结果；独立筛选页面造成来回切换，总结果数应容易看见。文章用覆盖面板举例，但关键证据是条件、结果与反馈的关联，并不证明本项目必须使用弹窗。[Kathryn Whitenton，Mobile Faceted Search with a Tray](https://www.nngroup.com/articles/mobile-faceted-search/)

4. **紧凑不等于难以点击**：Android 官方建议交互目标至少为 48 × 48 dp，并为控件提供有意义的可访问描述。缩减占用应优先去除重复标题和空白、减少操作层级；视觉胶囊可以较小，触摸范围仍应足够。[Android Developers — Make apps more accessible](https://developer.android.com/guide/topics/ui/accessibility/apps)

Material 3 设计站的页面正文需要 JavaScript，本次没有将无法读取的内容当作已验证依据；使用上面的 Material 官方组件文档核实 chips 行为。NN/g 两文发布于 2015/2016 年，属于交互原则依据，不作为当前产品性能数据。

## 本项目采用的方案

以下是结合用户明确要求作出的设计判断，并非上述来源直接规定的布局：

- **一眼可见，一次点击**：事件的常用状态、设备，通讯的常用对象条件直接呈现为可勾选标签。单次选择立即有勾号和蓝色选中反馈，不再走“打开弹窗 → 打开下拉框 → 选择 → 应用 → 关闭”的路径。
- **共用一种交互**：两页用同一筛选容器、分组标签、选中样式、清除入口、结果反馈和展开规则。条件内容可以不同，操作手感相同。
- **选中即更新，连续勾选不中断**：本地选择马上显示；网络查询短暂防抖合并，不要求额外点击“应用”。面板不因选择自动关闭，页面不自动滚回顶部。数据更新不替换整个页面。
- **常用直接展示，较长分组就地展开**：长类型列表显示部分常用项，并提供明确的“更多类型”；展开后保持展开，以便连续多选。展开只影响当前区域，不跳转、不遮盖全屏。已有选中的隐藏条件必须在摘要中可见。
- **可理解的组合**：同一分组多选为“满足任一”，不同分组为“同时满足”。不选表示不限；“全部”是清除此组限制，不应作为普通选项与具体值叠加。
- **清除容易，结果透明**：选项再次点击即可取消；提供整组/全部清除。条件附近显示结果数、更新中或失败状态。零结果保留当前条件并允许直接取消，不能悄悄放宽条件。
- **核心数据仍由后端提供**：具体告警名称不为 UI 方便另写一套映射；筛选候选项不应仅由当前已筛出的结果反推，否则其他可选类型会消失。

## 实现风险与验收重点

| 风险 | 处理与验收 |
| --- | --- |
| 连点产生大量请求 | 合并短时间选择；已发出的请求可以结束，但旧响应不能覆盖最新条件的结果。 |
| 加载期间再选一个条件 | 选择控件始终可操作；结果区局部提示，避免整页清空、白屏或高度骤变。 |
| 慢网或失败 | 保留条件，明确显示加载/失败；旧结果若暂时保留，必须提示正在更新，不能误当新结果。 |
| 长类型名和大字体 | 自动换行或有完整名称查看方式；不能只靠固定高度截断关键设备/告警含义。 |
| 条件列表长、首屏被占满 | 优先压缩重复文案与无效空白，常用直接显示、低频就地展开；保留足够触摸范围。 |
| 筛选后列表缩短 | 不主动跳回顶部；仍需检查滚动边界，避免用户看到空白却不知道结果在上方。 |
| 已选项目被折叠或刷新隐藏 | 摘要持续可见，已选值稳定保留；更新动态候选项不暗中清空筛选。 |
| 两页逐渐变成不同样式 | 共享控件统一间距、蓝色选中态、勾号、清除与展开；同时验收事件和通讯。 |

建议防抖时长先用较短值并根据真实请求耗时调整；它是本项目实现参数，不应把 NN/g 的示例秒数当作硬性标准。对真正慢的后端，即时更新需要异步、取消/过期保护和稳定反馈共同实现，单纯去掉“应用”按钮并不足以改善体验。
