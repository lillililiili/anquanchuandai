# 安卓与虚拟安全帽通信联调使用说明

日期：2026-09-20。范围：本轮 `/business` 通信状态模式。本文是操作说明，实际雷电跨端结果由同目录独立验收记录记载。

**2026-09-20 本轮流程更新：** 语音 / 视频入口已合并为统一“呼叫 / 接听”。接通后由值班端单向查看安全帽画面，无需安全帽第二次同意，不创建第二个通话。历史实机验收记录保留当时结果，不作为新流程已验证的依据。

## 1. 本轮验证什么

验证安卓值班端与虚拟安全帽的外呼、呼入、接听、拒接、挂断、超时、群呼逐参与者状态，以及群发文字播报的逐设备模拟回执。不采集或传输真实音视频，不验证摄像头、麦克风、声网媒体质量或真实扬声器播放。

| 入口 | 身份 | 用途 |
| --- | --- | --- |
| `http://127.0.0.1:5188/business` | 真实业务账号，如 `admin` | 本轮多人设备在线与安卓通信状态联调 |
| `http://127.0.0.1:5188/` · Agora | 旧工具测试身份 | 原有声网合成媒体测试，需要有效声网凭据 |
| 同一首页 · WebRTC | 旧工具测试身份 | 两个网页间合成音视频自检，不等于安卓 Agora 互通 |
| `http://127.0.0.1:5188/alarms` | 真实业务账号 | 独立的设备模拟告警、认领、处置与复核测试 |

不要混用以上模式的上线身份或把“状态接通”当作“媒体已收到”。原 Agora / WebRTC 工具继续保留。

## 2. 启动与连接

本轮安卓已改为通过 **Java 业务后端跳板**访问虚拟安全帽，不再直接访问 Node `5188`。链路是 `安卓 18084 → Java 业务鉴权 / 厂站 / 白名单 relay → Docker call-lab:18766 → 虚拟安全帽状态`。网页 `5188/business` 仍是测试设备控制台入口。

业务后端必须先包含本轮桥接代码。在项目根目录启动虚拟设备服务并应用专用覆盖：

```powershell
docker compose -f "新版安卓端开发/音视频网页联调/compose.yaml" up -d --build
docker compose -f docker/compose.yaml -f "新版安卓端开发/音视频网页联调/backend-business-bridge.compose.yaml" up -d --no-deps backend
```

该覆盖设置 `MELHAT_CALL_LAB_ENABLED=true` 与虚拟上游 `http://call-lab:18766`，加入已有 `wear-call-lab_default` 网络，不改真实厂商配置。关闭时在项目根目录执行：

```powershell
docker compose -f docker/compose.yaml up -d --no-deps backend
```

不要应用旧 `backend-link.compose.yaml` 的 Agora 厂商覆盖来替代这个跳板。本轮真实厂商同会话画面控制协议仍未接入。

安卓工程构建参数必须同时包含：

```text
--dart-define=API_BASE_URL=http://127.0.0.1:18084
--dart-define=CALL_LAB_ENABLED=true
```

当前机器可在 `C:\melhat-runtime\wearable-android` 构建，避免中文路径影响原工程插件。以下命令在安卓工程目录执行，雷电序列号以实际输出为准：

```powershell
flutter build apk --debug -t lib/main.dart --dart-define=API_BASE_URL=http://127.0.0.1:18084 --dart-define=CALL_LAB_ENABLED=true
adb devices
adb -s emulator-5554 reverse tcp:18084 tcp:18084
adb -s emulator-5554 install -r build/app/outputs/flutter-apk/app-debug.apk
```

网页使用 `admin`，安卓使用 `siteA_duty`，两端选择同一厂站。使用当前环境实际密码，本文不记录密码。网页支持验证码，仅在页面内存保存认证；刷新后需重新登录。

本轮 APK 只需要 `18084` 反向映射，不需要 `5188`。带业务认证访问 Java `/api/v1/lab/bridge-info` 应返回 `bridge: java-business-backend`、`upstreamType: virtual-helmet`、`enabled: true`、`simulation: true`、`realMedia: false`。先读到桥接标识，再验证通话状态；不能只凭 Node 工具响应就声称业务后端链路已打通。

网页在线值班状态出现**唯一在线值班账号**后再进行设备呼入。联调将该账号映射为本班接听人；有多个在线值班账号时拒绝呼入，需整理测试账号，只保留本班账号在线。当前没有正式排班路由接口，不能把最新心跳或列表首项当作实际当前值班人；正式排班接入仍待完成。管理员有部分管理或呼叫权限，并不自动成为值班接听人；账号角色和厂站授权仍由业务后端校验。

## 3. 多人设备在线与作业组

1. 网页读取项目原有人员、设备和作业，不另造一套人员。可按姓名 / SN、设备类型或作业缩小列表。
2. 勾选多台设备，点击“所选上线”；也可为每台设置测试佩戴人、在线、异常，点击“应用此设备配置”。安全帽、腰带、手表可参与在线与筛选测试，本轮呼叫与单向画面查看仅支持安全帽。
3. 测试佩戴人与异常标记只保存在联调内存，不修改真实设备分配、不写入普通异常事件。修改表单后需要点击应用，未保存草稿不代表服务状态已改变。
4. 网页每 2 秒续租；加载名单或提交业务操作期间仍续心跳，不覆盖未保存表单。中断连接约 25 秒后模拟设备离线；重新连接后按需重新上线。
5. 安卓通讯页的人员组、在线状态、设备类型、作业组可独立使用或组合；同一维度多选表示包含任一所选项，不同维度合并限制，例如“组 1 + 在线 + 安全帽”。按当前选择发起群呼或群发。
6. 网页“作业临时组”读取真实作业成员。只有点击“保存作业成员（业务数据）”才调用真实的新增 / 移除成员接口。修改影响安卓作业详情及通讯作业筛选，受现有权限和作业状态限制；不是自动销毁的内存测试组，不会自动恢复。

成员批量调整包含多次请求，部分失败时页面会回读实际结果。不要仅凭一次报错假定所有成员修改均未生效。

人员 / 设备设置、作业组与普通 / SOS 注入均属于管理员测试面板。**真实安全帽无屏幕，仅有“呼叫 / 接听”共用键及“挂断”键，不能选联系人、浏览名单或操作以上管理菜单。** 呼出固定路由至当前值班，网页不提供帽端联系人选择。摄像头由值班端开启后被动上传，帽端无需另外确认。

## 4. 统一呼叫、单向画面与群呼

### 安卓外呼

安卓通讯页选中在线安全帽，点击统一的呼叫入口，不再选择语音或视频类型。多选安全帽可群呼。网页通话区显示每台设备的响铃状态，在对应设备卡片使用两个帽端模拟按键：按“呼叫 / 接听”接听，按“挂断”拒绝响铃；已接通后按“挂断”结束此设备通话。没有第三个独立拒接键。

核对双方同一会话的参与者状态。群呼中一台拒接或挂断，不应直接终止仍活跃的其他参与者。安卓主动结束会话时，网页所有仍活跃参与者应结束。状态模式下的麦克风、扬声器或视频 UI 不构成真实驱动 / 媒体能力验收。

### 接通后的四个按钮

| 按钮 | 本轮行为 |
| --- | --- |
| 麦克风 | 显示开启 / 关闭状态；联调模式不采集真实音频 |
| 扬声器 | 显示开启 / 关闭状态；联调模式不播放真实声音 |
| 开启视频 / 关闭视频 | 值班端在原通话内单向查看 / 关闭安全帽示例画面；手机不采集或发布视频 |
| 结束通话 | 结束原会话，同时关闭画面查看 |

画面查看需至少一位参与者已接通，只面向已接通的安全帽。网页同步显示“值班端查看安全帽画面（单向模拟）”，逐人显示查看中 / 未开启；响铃、拒接、离线或已结束的参与者显示不可查看。网页不提供设备端开启手机摄像头的按钮，也不发起第二次同意流程。

状态模式通过 `POST /api/v1/lab/calls/{id}/video` 的 `enabled` 更新同一个通话，不重新创建 `call`，不重置接通时间。正式接口尚未接入同会话开启安全帽画面的控制，因此当前不能宣称真实通道已开启视频；正式模式会说明未接入并保留原有通话，不能另起一次呼叫冒充开启成功。联调画面仍是非实时示意图。

### 设备呼入

空闲安全帽按“呼叫 / 接听”键，自动向本厂站唯一在线值班账号呼出；等待接听或通话中不能重复呼叫，按“挂断”可取消或结束。管理员测试区也可每次选择 **1 台在线安全帽**点击“注入普通来电”，该区域不是帽端屏幕。页面不再提供联系人选择或视频呼叫勾选项；接通后由值班端控制单向画面查看。设备多选不用于反向群呼；多人群呼从安卓发起。

安卓应用运行期间，在应用内当前页面弹出接听 / 拒接入口，可核对网页和安卓两端状态。这里是应用前台内任意页面的来电提示，**不是操作系统后台推送**，不承诺应用退出、被杀或系统后台限制时仍收到弹窗。

## 5. SOS 紧急呼入

1. 管理员测试区选择单台在线安全帽，点击“注入 SOS 紧急呼叫”；按唯一在线值班路由，不选择联系人。此按钮用于测试注入，不表示安全帽拥有带菜单的 SOS 屏幕。普通与 SOS 使用相同的统一呼叫流程；SOS 的紧急标识和事件流程保留，画面查看在接通后进行。
2. SOS 测试佩戴人必须与该设备当前真实佩戴人一致。若真实绑定为甲、模拟选择乙，将返回明确错误，不发起呼叫、不写事件，也不自动修改业务绑定。若两者都未绑定，事件与来电均不冒充已知人员。
3. 接口通过真实 `/events/simulate` 写入明确标记的模拟 SOS 事件，标识以 `call-lab:` 开头，`source=simulator`、`demo=true`。它会保存在业务数据库中，进入既有事件流程。
4. 接听由指定在线值班账号操作，其他账号不能接听该通话。若没有在线值班人，不写 SOS 事件；若值班人或设备忙线，明确拒绝新呼叫。
5. 事件写入期间若设备离线，可能出现“事件已登记，但呼叫未发起”的部分结果。此时应按返回的事件编号核查，不应把它当作呼叫成功，也不应无脑重复点击生成更多事件。

## 6. 文字播报与回执

安卓选择人员 / 设备后输入文字提交，可群发；网页也提供向所选设备发送测试播报的入口。网页“播报与逐设备回执”逐台显示结果，点击“模拟收到播报”确认该设备回执。

离线设备不能确认回执。模拟确认只证明状态链路可用，不证明语音已合成、下发到真实设备或从扬声器播出。页面会明确标注模拟回执。

## 7. 清理与数据边界

| 数据 | 保存位置与退出影响 |
| --- | --- |
| 模拟在线、测试佩戴人、异常标记、通话、播报回执 | Call Lab 内存；重启服务清空 |
| 网页登录信息 | 当前页面内存；退出 / 刷新清除 |
| SOS 模拟事件及处置记录 | 真实业务数据库；退出或重启联调服务不清除 |
| 保存后的作业成员 | 真实业务数据库；需要按业务操作显式调整回来 |

网页退出或切站会清理选择，并尝试让当前账号控制的模拟设备离线；网络失败由心跳超时兜底。不要通过删除真实人员、设备或事件来“清空联调界面”。
