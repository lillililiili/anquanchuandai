# 统一呼叫与安全帽单向画面

日期：2026-09-20。本轮替代之前“对讲 / 视频”两种独立呼叫的交互。

## 设备模型

- 安全帽无屏幕，只有“呼叫 / 接听”共用键和“挂断”键。呼出固定联系当前厂站值班端，不选择人员、不向其他员工发起通话。来电响铃时按挂断等同拒接。
- 麦克风、扬声器支持与值班端语音沟通。安全帽摄像头为被控设备，由有权限的值班端开启，单向上传画面；不需要帽端另行确认，不显示手机视频。
- 网页的人员、模拟佩戴、在线、作业成员配置以及 SOS 注入均为管理员测试工具，不代表安全帽有操作屏幕。
- 本地联调暂以当前厂站唯一在线的值班角色账号作为接收人。后台尚无唯一“当前排班人员”查询接口；多人在线时明确阻止测试呼入，不按最后心跳猜测值班人，也不允许帽端指定其他联系人。

## 安卓变化

- 通讯仅保留“呼叫”和“文字播报”，原视频深链接兼容为统一呼叫。
- 呼叫后显示等待接听，接通后开始计时。通话页固定四个操作：麦克风、扬声器、参与人员、开启 / 关闭视频；挂断独立放在下方。
- 开启视频只改变当前会话的画面状态，通话 ID 和接通时间不变，参与人员入口始终保留。群组展示已接通安全帽画面；未接听、离线、退出成员不会冒充正在传输画面。
- 视频为安全帽单向示例画面，全屏入口位于画面角落。没有手机画面小窗。
- 移除旧“使用本人安全帽呼叫任意选中对象”的入口。值班手机统一通过后端操作所选安全帽。
- 原真实 RTC 适配器不再因旧视频标志申请手机摄像头权限或发布手机摄像头；扬声器按钮接入原 SDK 音频路由。正式厂商“同一会话开启帽摄像头”的协议仍未接入，正式通路明确提示，不显示伪成功。

## 后端跳板

原正式通话已有 Java `/api/v1/calls`、凭证、加入、挂断及厂商网关。本轮新增的是业务身份保护下的虚拟安全帽信令跳板，不替换旧正式接口。

当前安装包链路：

`安卓 → Java 18084 /api/v1/lab → Docker 虚拟安全帽适配器 → Java 返回状态 → 安卓`

安卓不再直接请求网页联调的 5188 端口；已移除雷电 5188 反向映射，只保留 18084。API_BASE_URL 为 `http://127.0.0.1:18084`，保留 `CALL_LAB_ENABLED=true`。

新增 Java 控制器 `WearCallLabBridgeController` 与服务 `WearCallLabBridgeService`：

| 方法和路径（前缀 /api/v1/lab） | 用途 |
| --- | --- |
| GET /bridge-info | 返回 Java 跳板身份与模拟模式，不暴露上游地址或凭据 |
| GET /roster、/state | 获取人员/设备/作业和呼叫状态 |
| POST /presence | 测试设备在线配置 |
| POST /calls | 统一呼叫，由后端选定帽呼入的值班接收人 |
| POST /calls/{UUID}/accept、reject、end | 接听、响铃挂断、结束 |
| POST /calls/{UUID}/video | `{enabled: true/false}`，同一通话启停帽端单向画面 |
| POST /tts、/tts/ack | 播报及逐设备模拟确认 |

Java 先验证登录、厂站与权限，再向服务器配置的固定适配器地址转发；并非任意 URL 代理。禁止重定向，保留上游业务错误与 HTTP 状态，超时返回“执行状态未确认”。普通账号不能代控其它通话；同厂站管理员按最新管理权限可查看画面，当前通话所属值班端也可控制。跨厂站仍受隔离。

此虚拟设备跳板默认关闭、prod 环境禁用。本地 Docker 使用 `音视频网页联调/backend-business-bridge.compose.yaml` 启用并连接联调容器网络，不修改原厂商 / Agora 配置。不新增音视频驱动，不声称 Java 转发真实媒体流。
