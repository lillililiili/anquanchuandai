# 通话邀请名单（2026-09-20）

用户问题：通话中邀请人员列表为空，但其他人员应处于在线状态。

## 原因及修复

- 通过主系统 :18084 的真实接口比对：联调内存记录多台设备 online=true，而主系统设备接口返回 online=0。主系统对模拟设备实行 30 秒心跳有效期。
- 设备原由管理员 userId=1 启用；新联调首页自动使用 siteA_duty 账号轮询。旧服务只续期 `device.controller == currentUserId` 的设备，导致跨账号查看控制台时心跳无法写回主系统，设备过期，安卓正确过滤了主系统返回的离线设备。
- 联调服务改为：经过厂站和联调权限检查的控制台，续期当前厂站已经启用的模拟设备。不变更设备关联、不自动启用离线设备，不使用联调内存状态替代主系统作为安卓数据源。
- 安卓邀请弹窗原来只在打开时加载一次，设备恢复在线后仍显示空名单。现每 10 秒从主系统更新，前台恢复时更新，提供“刷新在线人员”按钮；刷新失败时显示错误并停止使用旧名单，离线选择自动移除。保留搜索和仍有效的选择，后台更新不清空界面。

- `invite-refresh-red.log`：人员在弹窗打开后变为在线，原前端等待 11 秒仍没有显示候选人的复现。
- 联调服务 33 项测试通过，覆盖跨账号续期、厂站权限、离线设备不被激活、邀请/通话等。原有一项“读取名单自动上线”测试与既有主系统权威数据要求冲突，已改为读取名单不自动上线。
- 安卓 18 项测试通过，覆盖自动更新、手动刷新、选中者离线移除、搜索、邀请加入原通话、禁止重复、厂站切换和通话状态。测试邀请调用的是隔离模拟 API，未向真实人员发起呼叫。
- 静态检查无问题；APK 构建成功，安装到雷电 emulator-5554。
- Docker 联调服务重建部署成功、healthy。部署前确认没有活动通话，备份并恢复已有的 25 项模拟设备在线选择；未重启 Java 主系统。
