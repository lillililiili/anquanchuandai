# 手机与雷电直接访问后端

日期：2026-09-21。

## 原因与变更

此前 APK 编译地址为 `http://127.0.0.1:18084`，必须依靠 ADB reverse。手机重新连接后该临时规则丢失，手机访问自身端口被拒绝，而电脑 Docker 后端仍正常。

本次把旧 HTTP 客户端和 WearApi 统一到 `lib/config/backend_config.dart`，当前默认地址为 `http://10.137.74.38:18084`。保留 `API_BASE_URL` 编译参数，可按后续网络更换服务器地址。通知、视频等通过 WearApi 派生的业务链路沿用同一地址。

`bin/run-ldplayer.ps1` 改为直接连接，不再配置 reverse；`bin/connect-ldplayer.ps1` 改为直接读取后端健康状态，不再启用 root 或创建 NAT 规则。`恢复手机连接.cmd` 改为直连端口检查，不再建立映射。

## 网络条件

当前电脑地址 `10.137.74.38` 和手机地址 `10.137.74.62` 位于 USB 共享网络中；雷电也可以直接路由到电脑该地址。两端后端地址相同。

**不依赖 ADB 转发，不等于不依赖 USB 网络。** 关闭 USB 共享网络、拔线、电脑睡眠、关闭 Docker 或电脑 IP 改变仍会影响访问。以后若要求无线使用，应让手机与电脑处于互通网络，或部署到稳定服务器域名，再使用该地址构建 APK。本次没有擅自修改手机 Wi-Fi 或系统防火墙。

## 可复验的直连检查

从安卓项目目录执行：

```powershell
node bin/check-direct-backend.mjs http://10.137.74.38:18084 6HUGIJZLDM8PRWG6 emulator-5554
```

脚本先检查两个设备的 reverse 规则；只要后端端口仍有映射，就返回失败。然后从每个设备内部向电脑 IP 发送 HTTP 健康请求，必须返回 200 和 UP。

首次运行检测到两端映射，失败。移除两端 `tcp:18084` 映射和此前雷电针对 `10.0.2.2:18084` 的精确 NAT 规则后，两端检查通过，结果见 `direct-connect.json`。未清空其他网络规则。

## 构建方式

在英文目录联接 `C:/melhat-runtime/wearable-android` 中执行：

```powershell
$env:GRADLE_USER_HOME = 'C:/melhat-runtime/gradle-home'
C:/melhat-runtime/flutter/bin/flutter.bat build apk --debug -t lib/main.dart --dart-define=API_BASE_URL=http://10.137.74.38:18084 --dart-define=CALL_LAB_ENABLED=true
```

保留最新业务联调功能，使用当前源码构建。不是复制旧包或仅修改 ADB 设置。

本机依赖缓存位于 `C:/melhat-runtime/gradle-home`。本次默认用户缓存不完整且远程仓库请求等待，最终使用上述已有缓存，通过 Gradle `--offline assembleDebug` 和相同 dart-defines 构建。不要删除缓存或退回旧包。
