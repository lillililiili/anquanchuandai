# 统一事件详情页重构

用户要求：SOS 与普通事件共用一种风格、互补定位与现场研判能力，原流程和功能保持，重新构建并安装雷电。

## 页面与接口

- 统一页头、品牌色、圆角卡片、事件快照、状态操作、定位、现场研判、通信协助与更多处置记录。SOS 以红色标识突出，普通事件使用告警色，布局共用。
- 两类事件均使用同一份现场研判输入、草稿、附件预览和提交反馈。SOS 不再重复显示原详情里的旧处置输入框。
- 告警名称、描述、人员、设备、发生时间、位置及状态仍来自主后端事件 DTO；没有按设备类型写死告警文案。
- `EventController`、`EventPolicy` 和后端事件状态机没有修改。认领、处置、转交、复核关闭、重开、作业关联、审计时间线继续复用原入口、权限和 version 校验。
- 联系现场沿用 `/communications`，携带 eventId / deviceId / personId；实际检查事件 #138 正确定位王海涛 / QA-H006。没有自动发起电话。
- 协助组、照片上传原本未接入的部分保持明确的本地示例标识；本次没有宣称新增真实附件上传或协助组会话。

## 定位

- 使用事件的 WGS84 经纬度快照，在地图上显示事件标记，支持拖动、双指缩放、回到事件位置。位置时间、质量及演示来源同时展示。
- 缺失/无效坐标显示“暂无有效定位”；陈旧点明确标注，不把示意图或手机当前位置当成事件定位。
- 新增主项目 `GET /api/v1/events/{id}/map-tiles/{z}/{x}/{y}`。Android 通过 WearApi 访问主后端，复用令牌、厂站头、会话取消和错误处理，主后端再获取底图；不存在 Android 直连地图供应商/模拟设备。
- 主后端按事件厂站权限鉴权，在 Redis 缓存底图 7 天，固定上游 URL，限制瓦片参数；无效响应不缓存。遵循 [OpenStreetMap 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)，页面保留版权标识。
- 底图失败保留坐标与研判功能，可点击重试；重试不会继续复用失败的图片缓存。
