## 原功能如何保留

| 原功能/数据 | 现在的入口或显示 |
| --- | --- |
| 当前作业→详情 | 原/tasks/:id及真实taskId，不新建作业数据模型 |
| 任务状态、类型、区域、计划/实际时间、成员编号 | 任务卡底部“更多作业信息”展开 |
| 工作票 | 只读来源行；无需工作票/待核实/未关联按数据展示 |
| 负责人、监护人 | 优先接口名称或成员名称；负责人接口仅返回ID时显示“账号 ID”，不使用预览人名替代 |
| 成员→人员详情 | 点成员行，传真实personId，保留原人员页面 |
| 装备SN与检查结果 | 成员下方“装备检查”展开；原记录完整保留 |
| 装备状态 | 帽/带/表图形槽位，符合要求显示正常；缺少、未知、未关联分别显示。equipment-check并非实时在线接口，不凭图写在线 |
| 关联事件→原事件详情 | 所有事件保留，包含实际状态、风险级别、发生时间及多候选关联说明；查看核验传真实eventId |
| 联系监护人 | 进入原通讯页并选中guardianPersonId，不自动拨号；没有监护人时原位提示 |
| 查看待认领事件/事件中心、发起值班交接 | 红框内保留为紧凑文字入口；交接仍检查原值班权限和忙碌状态 |
| 其他现场功能 | 原装备、搜索、指标、近期事件、列表、现场工具及交接提交逻辑保留 |

## API与假接口边界

继续调用GET `/api/v1/duty/summary`、`/api/v1/me/equipment`、`/api/v1/events/inbox/count` 以及 `/api/v1/work-tasks/{id}`、`/equipment-check`、`/events` 三个作业接口。通讯、成员和事件仍由原页面加载其既有接口，后端未修改。

上述作业接口在当前后端已有实现，雷电截图为后端演示作业“东区巡检”的真实响应。没有把现有接口替换成mock。接口返回404/501时，错误页提供“查看界面示例”，从本地只读假接口载入03结构的3人样本，显式标注“界面示例 · 非真实业务”。示例人员/事件/联系按钮只作提示，不向真实API提交示例ID；403不进入假数据兜底。
