# 首页交接入口、值班交接页和设置页验收

日期：2026-09-20。范围：安卓 UI 与原有交接流程迁移。依据：本轮四张参考图、现有安卓统一样式、客户整体设计方案。未改后端、其他业务页面、底部导航和亮暗主题。

## 本轮结果

- 首页原“查看待认领事件”替换为“发起值班交接”，位置与比例沿用原入口，进入独立交接页。消息页认领功能继续保留。
- 值班交接页：厂区背景、待接班/已接班分栏、状态卡片、交接双方、时间、交接快照数量、备注、权限内的确认接班。值班角色可通过“发起交接”选择接班人、填写备注并提交。
- 设置页：人物背景、切换厂站卡片、交接摘要、查看交接记录按钮、通话提示、版本信息。返回与底部导航沿用现有规则。
- 全部背景复用现有素材并等比裁剪，未拉伸图片。字体与通用控件比例沿用现有系统。

## 数据和权限

- GET /api/v1/duty/handovers：后端仅返回当前厂站最近 20 条。页面明确标注这一范围，设置页也使用“最近记录中”文案。
- GET /api/v1/duty/operators：保留候选接班人加载、排除当前账号。
- POST /api/v1/duty/handovers：只传接班人和选填备注，快照由后端生成。
- POST /api/v1/duty/handovers/{id}/confirm：仅原有值班角色且本人为待接班记录的接收人可确认；保留确认弹窗。
- 图示“待处理事件/处理中事件”未伪造：接口快照只有 eventIds/taskIds，因此展示真实“交接事件/关联作业”；快照缺失显示“未提供”。
- 保留通话中禁止切站；异步交接操作增加厂站/会话范围校验。

## 验证

- 修改前 home 入口回归测试实际失败，red.log 记录了与目标不符的旧入口。
- 5 个相关测试文件共 17 项通过；新增非值班角色、大字适配后，交接测试文件 3 项通过（累计 18 个不同测试）。覆盖首页返回、设置菜单、四栏比例、发起请求字段、指定接班人确认、分栏筛选、其他厂站隔离、通话限制。
- 6 个改动文件 Flutter analyze 无问题；debug APK 构建成功。
- 雷电 emulator-5554 覆盖安装成功，使用原登录状态。真实接口返回的待接班和已接班记录均可展示；当前 admin 不具有 wear_duty/wear_team_lead，因此只读，不显示发起/确认操作。写操作通过自动化假传输测试验证，未在模拟器制造真实交接或确认记录。
- 模拟器检查：首页顶部及底部；交接页待接班/已接班与底部；设置页顶部及底部；首页→交接→返回；设置→交接记录→返回；设置→选择工作厂站→返回。
