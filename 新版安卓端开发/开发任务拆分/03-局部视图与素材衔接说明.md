## C2：本人装备轻量视图

当前我的菜单已通过局部详情容器展示 `EquipmentPanel()`，只展示当前账号关联人员装备。T17优先复用该容器补图00页头；必要时才提取 `lib/wear/queries/my_equipment_page.dart` 中的 `MyEquipmentPage({super.key})`，不重复创建入口或装备仓库。

当前 `EquipmentPanel({super.key, this.personId})` 已存在。T18可新增可选展示参数：

```dart
enum EquipmentPresentation { existing, productCards }
// EquipmentPanel 的新增可选参数：
// EquipmentPresentation presentation = EquipmentPresentation.existing
```

原调用默认existing，新视图显式productCards。`personId == null`仍表示当前账号装备，不能改成全站；传personId仍表示对应人员。T19连接首页两个本人入口与绑定历史，保留来源分支与返回。

## C3：人员、终端与发起端

继续现有PersonOption、CommunicationDevice等模型，不为换肤重建通讯域。

- 已选人员集合按稳定personId去重；独立设备用deviceId单独记录，显示数量时不要混为人数。
- 一个已选人员可以有多台装备，执行时在原卡或局部面板确认有能力且被授权的目标终端。
- 发起端是手机或本人安全帽，与联系对象不同。不要因本人绑帽就仍调用本机RTC并称为帽端呼叫。
- T10解决原发起区的确认与能力反馈；T22、T30、T40引用这套目标语义，不复制呼叫流程。
- 缺组呼／帽端执行能力仍可完成UI准备、选择与确认，远程结果显示未开通；不能偷偷只执行第一个目标。

## C4：保留旧链接的操作意图

T11在现有 `/communications` 上增补可选 `intent`，取值 `tts`、`voice`、`video`。保留deviceId、personId、eventId及原video=true/1。

意图只定位原通讯页相应区域。参数未传时保持原行为；不能自动提交TTS或自动拨号。未知意图回到原通讯内容并保留对象，不报整页错误。T40复用此约定，不新建一套mode参数。

## C5：核验、SOS与作业局部承接

现有事件控制器文件为 `lib/wear/events/event_controller.dart`。T25、T28仅包装它，不新增第二个事件状态机。

```dart
// T25 VerificationView({required EventController controller})
// T28 SosView({required EventController controller})
```

controller由原事件页拥有，局部视图订阅／取消自己的监听，但不得dispose外部controller。eventId、权限、草稿和写入状态来自该同一实例。列表到原详情不自动变成核验；只有原处理入口进入核验。若局部视图返回时有草稿，沿用既有保存规则。

作业仍由原taskId与接口驱动，局部无底栏只针对图03，原 `/tasks/:id` 继续兼容。具体四项例外见04，不将全部查询页移出壳层。

## C6：本地照片UI不依赖上传接口

已核查当前pubspec及代码，未发现image_picker／file_picker或既有选图封装。因此T27不能假定已装选图库，也不能只写“复用已有能力”然后停下。

在不新增依赖的前提下，T27采用**现有Android MethodChannel的局部扩展**，只为图02选照片：

- Flutter侧由 `verification_attachments.dart` 调用 `rolling/wear` 的新增方法 `pickVerificationImages`，参数 `remainingSlots` 为0—4。
- Android侧限于 `android/app/src/main/kotlin/com/rolling/intelligence_headband/MainActivity.kt`，保留pushAppKey／pushVendors等原方法。使用系统文档图片选择器，允许多选；取消返回空列表，不报错误。
- 回传列表元素只含本地应用私有副本路径 `path` 与 `mimeType`；按剩余数量校验，读取失败原位提示，不申请整库读取权限或擅加新存储权限。
- UI最多4张、能预览删除；使用系统已有选择器，不新做相册管理页面。图中“支持照片”不自动扩展为拍照摄像或视频上传。
- 本地草稿的归属键含账号／厂站／eventId；文件失效原缩略图位置提示重新选择，不当成已上传。正文真实提交前明确哪些照片未上传，用户不能被静默丢附件。
- 无后端上传时，本地选择／预览／删除／草稿仍可验收；真实上传与远程附件回执不伪造。

这项原生改动只服务于一个看得见的附件区域，与T27同时交付，不拆成后台基础建设任务，不改Manifest权限或Gradle依赖。如果系统选图差异使任务增大，则先拆T27a本地附件卡和T27b系统选图闭环，两个都必须有可见UI结果。

## C7：视频展示复用同一会话

T31候选 `lib/wear/communications/call_view.dart`：`CallView({required CommunicationsController controller})`。当前控制器定义在 `lib/wear/communications/controller.dart`。

容器不拥有RTC实例，不创建新通话，只监听现有阶段与渲染现有视频。T32的静音／音频路由／挂断调用原controller／RTC适配器，不能只切换图标。退出显示视图与结束实际会话分开；返回原通讯区继续显示同一会话。
