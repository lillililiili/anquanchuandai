# 安卓数据来源与后端对接核查

核查范围：当前 `WearApp` 正式页面入口；不将旧 `LEGACY_DEMO` 应用、测试 fixture 或网页静态设计稿算作正在运行的安卓业务数据。后端为 Docker Java 服务 `127.0.0.1:18084`，本轮仅调整安卓对接，没有新增后端接口、改数据库或覆盖另一任务的音视频网页联调代码。

## 结论

当前安卓并非全是假数据。人员、班组、设备台账、领用关系、作业与成员、事件等大部分已读后端。发现并修正了空装备被示例数据替代、设备在线字段未适配、装备卡缺少遥测读取、人员当前作业仍为占位等问题。

**来自后端不等于来自真实硬件。** 数据库内已有演示人员、作业、设备和事件；当前安装包保留用户要求的 `CALL_LAB_ENABLED=true`。通讯的在线勾选、呼叫和摄像头状态来自 Java 跳板后面的联调服务，是服务端模拟状态，不能作为真实安全帽在线或实际音视频已接通的证明。

## 实连证据

使用本地已有管理员测试账号、厂站1，只读查询现有接口，没有写入业务记录。抽查时返回：33名人员、4个班组、42台设备、60条领用记录（含历史）、21项作业；管理员 `/me/equipment` 返回空数组；人员3的装备接口返回2条。这里的数量是核查时快照，可能随其他任务的联调而变化。

核对了 `PersonService`、`AssignmentService`、`DeviceService`、`WorkTaskService` 的数据库查询及 DTO。读取接口字段与安卓使用字段逐项比较；已保存去除令牌、密码和完整人员资料的证据 `验收记录/数据来源核查-20260920/backend-api-evidence.json`。

## 来源对照

| 对象/页面 | 后端来源 | 核查结果与处理 |
| --- | --- | --- |
| 厂站与账号 | `/me`、`/sites`、`PUT /me/current-site` | 使用授权厂站与当前账号，不使用预览图上的厂站名称冒充实际厂站。 |
| 人员档案 | `/people`、`/people/{id}` | 后端人员记录；在职/停用是人员状态，不是在线状态。 |
| 班组 | `/teams`、人员的 `teamId/teamName` | 后端班组。通讯下拉按当前联系人中出现的班组生成；无人班组不会出现在通讯联系人筛选中。 |
| 设备台账 | `/devices`、`/devices/{id}` | 后端型号、能力和台账；补齐手表类型和“已领用”资产状态的中文映射。 |
| 人员与设备领用关系 | `/people/{id}/equipment`、`/me/equipment`、设备 `currentAssignment` | 后端关系；领用记录的 `id` 是领用ID，设备读取使用 `deviceId`，未混用。 |
| 领用/归还历史 | `/people/{id}/assignments`、`/devices/{id}/assignments` | 已有数据接口、安卓已有查看功能；不再生成本地示例历史。当前账号无领用且缺少人员ID时，个人装备页无法据此反查个人历史，显示无可查询记录，不伪造历史。 |
| 我的装备 | `/me/equipment` + `/devices/{id}` | 原空数组自动补三件本地装备；已删除本地装备样例与示例切换，空就是“暂无领用装备”，失败就是错误提示。 |
| 首页、人员详情装备卡 | 领用接口 + `/devices/{id}` | 原先领用DTO不含实时状态，卡片直接使用它导致状态未知；现补读设备DTO，失败保留领用关系、显示状态未知。 |
| 正式设备在线 | `online` + `connectionQuality` + `lastReportedAt` | 后端在线标记为1/0。通讯筛选现统一转换为online/offline；陈旧、未知遥测不当作当前在线。设备DTO的连接质量由后端按最后上报时间判断。 |
| 人员在线 | 正式 PersonDto 没有独立在线字段 | 不把在职当在线。通讯“设备在线状态”筛选基于该人员匹配的领用设备；不能据此声称有独立人员心跳服务。联调服务人员上线状态另属模拟数据。 |
| 作业列表、详情、当前作业 | `/work-tasks`、`/work-tasks/mine`、`/work-tasks/{id}`、`/duty/summary` | 后端数据；无当前作业时首页跳全部作业，不默认打开假作业。 |
| 作业组/临时组 | 作业详情 `members[].personId` | 后端作业成员，不是安卓自行编造组。通讯按作业成员筛选；增加、移除人员已调用成员POST/DELETE接口。 |
| 人员详情当前作业 | 活动作业列表 + 作业详情成员/监护人 | 原固定“未获取”；现读取进行中/暂停作业，按该人员ID匹配成员或监护人，可进入对应详情。人员ID与账号ID不混用；无匹配显示空，失败显示未获取。 |
| 作业装备检查、失去监护 | `/work-tasks/{id}/equipment-check` | 后端 readiness 检查结果，卡片“正常/缺少/待核验”不等同于设备当前在线。 |
| 设备分配操作 | POST `/assignments`、归还/回收接口，PUT `/devices/{id}/site` | 后端有接口；安卓当前主要是查看，未实现完整领用/归还/调拨操作页面，也不存在提交后假成功的按钮。本轮不扩建管理页面。 |
| 值班交接 | `/duty/handovers`、`/duty/operators`、确认接口 | 已接后端列表、发起与确认。 |
| 事件、SOS与处置 | `/events`、详情、动作接口 | 后端事件，保留demo标记；首页SOS总数和多条列表来自后端，不是本地数量。 |
| 实际定位与轨迹 | `/locations/people/{id}`、`/{id}/tracks` | 默认查询使用后端坐标与时间。明确点击“示例预览”才出现本地示例轨迹，未替代成功返回的实际轨迹。 |

表内相对接口均位于 `/api/v1` 下。

## 保留现状的 UI / 未完成闭环

- **忘记密码申请**：目前填写校验与本地图形码是UI；未找到匿名提交重置申请、供管理员审核的对应业务接口。系统管理员直接改密接口不能冒充找回申请流程。本轮不修改。
- **SOS协助组**：协助组成员、加入协助/结束协助仍是明确的本地演示；已有通话接口不等于协助组业务接口。本轮不补造组服务。
- **事件现场照片**：添加的是本地示例照片；现有 `/files` 为文件审计、查询和下载，未见事件处置附件上传并绑定事件的完整契约。本轮不把普通文件服务当作已完成事件附件闭环。
- **SOS实时地图、通话摄像头画面**：仍有明确的示意图/非实时图片。坐标数据与实时地图/视频流不是同一能力。本轮不将静态图片宣称为实时画面。
- **音视频联调**：呼叫与状态通过Java后端跳板；模拟设备上线、人员上线由联调服务配置，非安卓硬编码，但仍不是硬件遥测。正式单向摄像头媒体驱动没有在本轮实现。
- **作业界面示例、轨迹示例预览**：保留明确的手动预览入口，实际业务默认仍查询后端；示例操作不会提交真实业务成功。这与已删除的“空装备自动变三件装备”不同。

## 修改边界与验证

只修改安卓读取、字段映射及相应显示。没有生成新人员、新班组、新领用记录或新作业，没有改已有后台演示数据，没有把另一任务的联调上线状态写进正式设备状态。

专项回归覆盖后端1/0在线筛选、陈旧遥测排除、空装备不造假、领用ID/设备ID分离、按成员匹配作业而非账号ID，以及现有通讯/作业/首页/个人装备交互。测试和构建证据放在同名验收记录目录。

最终验证：49项针对性测试通过，9个修改/测试文件静态检查无问题，debug APK构建并覆盖安装雷电成功。实机现有A站值班员账号的我的装备显示后端空状态、不再显示三件样例；人员周明详情从后端匹配6项当前作业，点击锅炉平台检修（联调07）进入对应作业详情。人员装备卡显示后端遥测的数据陈旧/状态未知，保留领用历史。验收滚动至人员详情下部及历史记录底部并保存截图。本轮没有提交领用、归还、作业变更或测试事件。
