# 三端共用后端：第三阶段实施与验收

更新日期：2026-10-07。第二阶段的共用后端继续使用，本阶段完成安卓真实接口接入。安卓保持四个底部入口与主要页面布局。

后续已按 PC 尚无真实设备的进度完成一轮无设备走查与修复，详见[无设备阶段页面走查与三端验收](无设备阶段-页面走查与三端验收.md)。本文件原验收数量保留为第三阶段当次记录，后续结果见该补充报告。

## 已实现

- 默认运行真实模式，使用现有 Spring 后端。`WEAR_MOCK=true` 才启用本地模拟；请求失败不会退回模拟成功。真实凭据按后端地址隔离，Mock 不读取真实凭据。
- 登录、身份、厂站、首页、人员、装备、领用记录、只读作业、事件详情使用共享数据。普通用户读取范围由服务端控制；管理账号未关联人员时不显示个人装备或手机求助入口。
- 真实登录遵循后端协议，不要求本地模拟验证码。密码找回仍为联系管理员。停用、凭据重置及权限调整通过真实会话和身份刷新生效。
- 发放、正常归还调用现有台账服务，发送人员、设备和领用关系的版本。异常归还仍从 PC 后台办理。修复移动端 HTTP 嵌套请求列表的类型转换问题，没有另建领用账本。
- 事件认领、员工现场补充、核验草稿、最终核验及 JPG/PNG 照片调用共享事件服务。草稿保留开始编辑时的版本；冲突必须明确读取最新表单后再操作。
- 手机 SOS 可直接确认提交，真实来源为 `manual_sos`，详情和位置可后补。每条事件关联各自的协助记录；重试保留请求编号，结束协助不自动完成核验。
- 员工补充与最终核验分别显示照片、实际操作人及时间。已核验页面只读。
- 安全帽语音、文字广播接入现有设备服务，新增会话记录、加入、结束、凭据及广播受理接口。PC 通讯记录能读取安卓记录。凭据不进入兼容快照；平台受理、本端加入、设备接通分开显示。
- 示例台账没有真实遥测或通讯能力时显示未知/不可用，不将示例在线状态作为真实设备状态。
- 正常运行只在前台定时刷新身份和数据；没有接入旧联调 WebSocket、后台离线推送或手机间音视频。
- 底部入口返回对应主页面，顶部返回保留父子页面关系。修复普通用户无法进入带字母设备编号详情的问题。

## 接口与代码位置

安卓 `lib/wear/shared_backend.dart` 将原页面 DTO 转成共享 API 调用；`shared_models.dart` 只做展示转换。写操作和权限判断均由后端执行。

| 安卓业务 | 共享接口 |
| --- | --- |
| 登录、身份、厂站 | `/api/guardian/v1/mobile/login`、`identity`、`sites` |
| 页面只读数据 | `/api/guardian/v1/mobile/context?siteId=…` |
| 装备办理 | `/api/guardian/v1/mobile/assignments/issue`、`return` |
| 手机求助 | `/api/guardian/v1/sos` |
| 认领、员工补充、核验、协助 | `/api/guardian/v1/events/{id}/{action}` |
| 照片 | `/api/guardian/v1/files/{uploadId}`，受会话及事件范围校验 |
| 安全帽语音 | `/api/guardian/v1/mobile/calls`、`{id}`、`{id}/credentials`、`joined`、`end` |
| 文字广播 | `/api/guardian/v1/mobile/broadcast` |

`mobile/context` 在服务端完成授权过滤，只带当前可见人员、设备、作业和事件。作业成员姓名作为已授权作业资料返回，不因此开放其他人员档案。人员/设备的 PC 编号和台账编号分别保留，办理时使用台账编号。

所有真实请求使用 `X-Wearable-Token`。PC 前台、PC 后台和安卓分别登录取得自己的会话，不复用值守凭据给普通用户。

## 本机启动与热更新

后端使用现有 Docker Compose，本机地址 `http://127.0.0.1:18084`。PC 前台为 `http://127.0.0.1:5191`，PC 后台为 `http://127.0.0.1:5181`。

在安卓项目目录执行：

```powershell
# 先打开雷电，再连接本机共用后端；脚本自动设置 adb reverse。
.\bin\run-ldplayer.ps1

# 明确开启离线 Mock 预览。
.\bin\run-ldplayer.ps1 -Mock

# 后端不在本机时指定真实可达地址。
.\bin\run-ldplayer.ps1 -BackendUrl http://后端地址:18084
```

已有调试会话中，按 `r` 热重载、`R` 热重启；修改 `WEAR_MOCK` 或后端地址需要重新启动。VS Code 提供 `Android Shared Backend (hot reload)` 与 `Android Mock (hot reload)` 两个配置。

本次已在雷电启动默认真实模式开发入口，并实际执行 `r` 验证热重载成功；后端及 PC 前后台开发服务保持运行。

Flutter、Android SDK、Pub、Gradle、Maven 缓存及本轮临时文件继续使用 `D:\AndroidDev` 的现有配置；安卓构建使用 `D:\AndroidDev\wearable-android` 到项目的目录联接。JDK、Node、Docker 沿用已有安装，没有重新安装一套。Docker 数据使用原数据卷。

真实模式使用 PC 后台中的实际账号。普通用户需要关联人员并授予对应厂站的移动端业务权限；没有创建正式测试账号，也没有把测试 SOS 写入现有业务库。

## 验收结果

- Spring 后端：159 项测试通过，完整打包成功。覆盖身份/范围、事件并发与重复提交、照片、设备请求去重、凭据私密性和嵌套 HTTP 请求转换。
- 安卓静态分析：`lib/wear`、集成测试及新增契约测试无问题。
- 安卓相关回归：58 项通过，其中 37 项涵盖显式 Mock、真实协议、失败不回退、角色、草稿版本、人员装备和页面流程；另 21 项验证语音控制器、RTC 适配器及通讯状态。
- PC 前台：33 项测试通过，生产构建通过。
- 隔离 Docker HTTP 回归：53 项通过，覆盖普通用户越权拒绝、同一事件三端读写、照片权限、版本冲突、重复 SOS、账号停用和重置凭据失效。
- 雷电真实网络集成测试：`integration_test/shared_backend_flow_test.dart` 完整通过。实际操作了登录、四入口、设备与作业父子页面、空表单 SOS、现场补充、照片、多 SOS、协助结束、核验草稿与提交、只读结果、PC 值守核验后安卓读取，以及正常归还/重新发放与 PC 台账一致性。

雷电测试强制使用隔离端口 **18085**，入口断言禁止直接指向 18084。测试使用独立数据库、Redis 分库和文件目录，设备供应商地址在 QA 中关闭；测试数据和测试账号不进入现有业务库。
