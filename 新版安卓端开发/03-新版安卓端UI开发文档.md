| 边界 | 本稿要求 |
| --- | --- |
| 产品 | 客户§10.3：App承担通话调度与收告警。三入口为待审核安卓适配建议 |
| 架构 | 客户§10.1不复用旧脚手架；先确定新工程边界、接口与数据迁移，不默认批准复用WearApp壳层。旧源码用于现状、字段与行为参考 |
| 范围 | 按人组织设备与位置，统一告警；不新增AI、考勤、完整两票、巡检工单或大型数字孪生 |
| 依赖 | 每个按钮注明真实API、权限、设备能力、回执及不可用原因；没有接口不增加虚假成功交互 |
| 历史兼容 | 旧通知ID、处置历史、草稿、角色与厂站约束有迁移方案；是否保留原URL另做映射，不要求旧路由全部照搬 |
| 辅助能力 | 交接、轨迹、复杂处置按角色审核；保留数据不等于每个旧按钮必须留在手机主页面 |

## 2. 功能与页面的施工顺序建议

| 阶段 | 交付内容 | 可审核结果 |
| --- | --- | --- |
| 1 架构与接口盘点 | 新工程边界、账号／人员／设备ID映射、厂站权限、能力和状态契约、旧深链迁移表 | 无真实接口的动作有明确依赖，不凭姓名猜关系 |
| 2 统一设计基础 | 视觉色彩、字体、间距、列表、表单、按钮、弹窗、空错状态 | 同数据页面稿；默认客户暖石深色，普通与大字号均可操作 |
| 3 授权与页面骨架 | 登录、授权选站、三主入口、返回栈、全局通话／SOS提示 | 未认证不显站；选站全局一致；原登录、路由与业务状态保持 |
| 4 通讯主流程 | 找人、装备终端、准备、实际通话、TTS、记录 | 单呼／组呼／发起端如实显示；失败不静默降级，来源入口可返回 |
| 5 统一告警 | 列表、独立详情、发生时位置、同人联系、授权确认／说明、历史 | 不另造SOS或核验状态机；草稿和冲突恢复有效 |
| 6 关联与个人设置 | 人员／装备／位置／作业只读上下文、我的装备、接警帮助、获准兼容子页 | 不重建现场管理中心；本人装备与全站台账分离 |
| 7 联调验收 | Docker API、雷电导航与页面、真机接警、RTC、穿戴协议、分层位置 | 分项记录实际结果、缺口与负责人；UI通过不能替代设备闭环 |

三入口和布局审核后才开展实现；此表是顺序建议，不是承诺当前后端具备全部能力。

## 3. 必须保持的业务语义

- 登录用户账号不等于现场人员；以稳定ID和明确关联为准。
- 同人一处当前主位置；历史告警位置与当前位置分开，时间、区域、层、来源和质量可读。
- 来源设备不等于联系设备。安全带可提供告警，但联系应指向同人可用通信终端。
- 通话创建、振铃、媒体接通、挂断、告警确认与结案分别表示不同事实。
- 组呼和帽端发起是客户目标，尚无完整链路时明确待依赖，不以取首个设备单呼冒充完成。
- TTS下发受理不等于对方听到；无播放回执不能提示已收听。
- 所有告警沿用服务端合法状态与版本；移动端精简入口不丢责任历史或绕过权限。
- “未处理”“未关闭”“未读”按服务端各自定义，不能直接共用计数。
- 正式数据空缺、失败、未知和演示分别呈现，不补固定姓名、设备、票号或在线状态。
