# 雷电网络故障原因与修复记录

日期：2026-09-17。范围：本机 Docker 后端与雷电模拟器之间的调试连接。本轮没有修改 Flutter 页面、业务接口或 UI 跳转。

## 原因

App 默认使用 `http://10.0.2.2:18084`。这个地址用于官方 Android 模拟器访问电脑宿主机；本机雷电需要额外映射才能使用。检查时 Docker 后端健康接口返回 `UP`，但雷电的 `adb reverse --list` 为空、NAT OUTPUT 中没有对应重定向，设备访问该地址超时。因此 App 报“无法连接服务，请检查网络后重试”。

旧连接脚本先创建 reverse 再执行 `adb root`。后者会重启 adbd，可能丢失刚创建的转发；模拟器重启也需要重新建立这些临时映射。

## 本次处理

恢复的链路：

```text
App → 10.0.2.2:18084
    → 雷电内 NAT 重定向至本地 18084
    → adb reverse
    → Windows 127.0.0.1:18084
    → Docker 后端
```

修正 `android代码/melhat_android-main/bin/connect-ldplayer.ps1`：先 root 并等待设备重新连接，确认权限后再创建 reverse；NAT 规则先查再加，重复运行不会叠加；检查各关键命令退出码和最终健康结果，失败时明确报错。

## 下次启动

确认 Docker 服务和雷电已启动后，在工作区根目录运行：

```powershell
& './android代码/melhat_android-main/bin/connect-ldplayer.ps1'
```

脚本使用本机雷电 ADB 路径 `C:/leidian/LDPlayer14/adb.exe`，适用于当前已允许 root 的模拟器。模拟器重启、ADB 服务重启后需要重新运行；此次没有安装后台常驻程序或自动计划任务。

另有 `bin/run-ldplayer.ps1` 可通过 `API_BASE_URL=http://127.0.0.1:18084` 启动开发包，避免 NAT 映射，但它要求 Flutter、ADB 的 PATH／SDK 环境配置可用。本次修复使用现有已安装 APK，不需要重新构建。

## 本次验证

- 修复前：宿主机 `/actuator/health` 返回 `UP`；雷电访问默认地址 4 秒超时。
- 修复后：雷电访问 `127.0.0.1:18084` 和 `10.0.2.2:18084` 均返回 `UP`。
- 连接脚本连续运行两次均通过；reverse 映射存在，NAT 规则仅一条。
- 主动将 adbd 切回非 root 后再运行脚本，root 重连及后续健康检查通过，验证了调整后的顺序。
- 使用登录页已有账号密码重新提交，App 成功进入厂站选择，选择演示厂站 A 后加载“现场”首页。
- PowerShell 语法解析通过。本次未重新编译 APK，也未将单次登录验证扩展为全部业务验收。
- 恢复后的首页截图与 UI 层级保存在安卓工程的忽略目录 `build/verification/network-20260917/restored-home.png` 和 `restored-home.xml`。
