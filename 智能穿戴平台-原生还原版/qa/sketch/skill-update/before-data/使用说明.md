# 个人 UI 规范的持久化使用

本目录保存的是两份提示词的合并规范与 Codex Skill，尚未执行提示词中的 PDF/参考图提取，也未生成 CSS 或 HTML Starter。

## 文件入口

- `personal-ui-framework/SKILL.md`：技能入口，要求完整读取合并提示词及两份原文。
- `personal-ui-framework/references/合并提示词.md`：可以直接交给 Codex 的完整合并规范，包括精准参数、使用场景、强限制、交付、验收及原文差异。
- `personal-ui-framework/references/提示词原文-A.md`、`提示词原文-B.md`：标记之间的提示词正文，逐字保留，防止合并时遗漏。
- `personal-ui-framework/references/完整性核对.md`：原文段落索引、数值覆盖核对、哈希及来源。
- `personal-ui-framework/references/来源文件/`：两份源 Markdown 的完整副本。
- `AGENTS.md`：当前目录的规范读取入口。放在 data 中不意味着其他任意项目会自动读取此目录。

## 现在直接使用

在新对话中复制下列文字，把实际项目目录和本次需求接在后面：

```text
请完整读取 C:\Users\qiyue\Desktop\UI设计规范\data\personal-ui-framework\SKILL.md，按其中要求完整读取合并提示词及两份提示词原文，使用这套个人 UI 规范处理本次任务。所有颜色、状态、用途、字体、组件、交互、布局与强限制必须逐项遵守，不得凭空补值。原文冲突先保留并说明；不要自行裁决。任何违反规范的实现我都会打回重做。
```

## 在多个项目中保留

`personal-ui-framework` 是完整的技能文件夹，内部引用使用相对路径。可完整复制到个人技能目录 `C:\Users\qiyue\.codex\skills\personal-ui-framework`，不要只复制 SKILL.md。该路径遵循 skill-creator 的个人技能存放约定；本次没有自动安装或修改全局配置。

也可把整个技能文件夹放到目标项目，并把本目录 AGENTS.md 中的读取要求合入该项目已有 AGENTS.md，调整为实际相对路径。保留目标项目原有指令，不覆盖原文件。迁移后必须确保所有引用文件仍可读取。

## 后续生成和迭代

需要生成实际 UI 框架时，要求 Codex 执行合并提示词并指定输出目录；它必须先读完整 PDF 与 12 张参考图，再按两个原提示词的全部交付要求制作规范包。

生成规范包后，既可按原文的附件三步流程使用，也可复制 Starter 工程开始新项目。两种原始 SOP、契约要求、主题选择、打回指令与迭代方法均在合并提示词中保留。

发现违反已有规范的实现时，按 STYLE.md / SYSTEM_RULES.md 的真实条款号打回。新增规则必须来自你明确的要求或可核实的源素材；不能把 AI 的猜测写成个人规范。
