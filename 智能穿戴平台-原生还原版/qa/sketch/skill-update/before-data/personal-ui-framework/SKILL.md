# 个人通用项目 UI 开发规范

本技能合并两份用户提供的提示词。这里只提供入口，全部细则位于引用文件中，不能只读本文件就开始实现。

## 必须读取

1. 完整读取 [合并提示词](references/合并提示词.md)，包括色值用途、组件交互、交付结构、验收和原文差异。
2. 完整读取 [提示词原文 A](references/提示词原文-A.md) 和 [提示词原文 B](references/提示词原文-B.md)。原文是细节核对依据；合并整理不允许降低原文约束或替代任何未列出的细节。
3. 需要查证出处时读取 [完整性核对](references/完整性核对.md)。

## 执行边界

- 生成设计系统及标杆模板时，执行合并提示词的素材读取、参数提取、交付和验收要求。必须先完整读取 PDF 与所有参考图，再写代码；Sketch 忽略。
- 后续使用已生成的规范开发项目时，必须读取该项目的 STYLE.md、.codex/SYSTEM_RULES.md、design-system/tokens.css、design-system/components.css 和相关标杆模板；以 tokens.css 为令牌唯一事实源。
- 本技能中的具体数值来自提示词 B，并未因技能整理而被重新核实为视觉素材实测值。不得声称已读取原始 PDF 或图片，除非当次确实读取。
- 不得推测缺失色值、字号、尺寸、字体黑名单、交互时机或双主题映射；原文冲突或素材无法辨识时，保留出处与差异，继续不依赖该差异的工作，需实现相关内容时向用户澄清。
- 本技能固定的是视觉及规范约束。原文“不要写 React / Vue / Svelte、package.json、构建或部署”限定规范包的制作任务，不得据此擅自改变后续用户指定项目的技术栈。
- 输出位置服从当次用户指定目录。本次仅把提示词持久化到 data，不执行原文的 UI 框架生成任务，不修改全局 Codex 配置。

## 核心约束提示

以下只用于防止入口误用，不能替代完整引用：跨行业中立；Light/Dark 双主题；六组品牌与语义色完整四态；Dark P3 蓝色与 Light P3 黄色差异；色值及 px 必须使用 CSS 变量；只准原文列出的字体、字重、字号、圆角与尺寸；七类组件及全部交互；禁用原文列出的公模色、字体与视觉效果；零外部 CDN；原文两组验收全部执行。
