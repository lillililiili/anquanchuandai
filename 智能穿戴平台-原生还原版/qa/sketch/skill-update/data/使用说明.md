# 个人 UI 规范的使用

本目录已根据 2026-10-10 提供的 `UI规范.sketch` 原生图层核实关键参数。它包含技能、规则与来源证据；不包含已生成的 CSS 框架或 Starter，也未自动安装或修改全局配置。

## 当前入口

- [SKILL.md](personal-ui-framework/SKILL.md)：判断任务范围，读取需要的规范。
- [合并提示词.md](personal-ui-framework/references/合并提示词.md)：当前有效的实施方式，区分现有项目修改、新建页面、规范包制作。
- [Sketch核实参数.md](personal-ui-framework/references/Sketch核实参数.md)：53 项颜色及透明度、字体、组件状态、交互原文、图层来源，以及原稿和项目适配的边界。
- [Sketch证据.json](personal-ui-framework/references/Sketch证据.json)：可追溯的图层 ID、路径、Frame、颜色/alpha、状态与文字证据。
- [历史合并版](personal-ui-framework/references/合并提示词-历史未核实版.md)、[原文 A](personal-ui-framework/references/提示词原文-A.md)、[原文 B](personal-ui-framework/references/提示词原文-B.md)：历史归档；原文保持不变。
- [完整性核对](personal-ui-framework/references/完整性核对.md)：版本范围、哈希与检查说明。

## 修改已有系统

可以在新对话中使用下列请求，并替换实际项目路径：

```text
请读取 C:/Users/19221/Desktop/data/personal-ui-framework/SKILL.md，按已核实的 Sketch 参数精修 <项目路径> 的样式。保留现有导航、分栏、模块顺序、业务内容和交互流程；按本次需要修改颜色、字体、边框与控件状态。先核对相关组件证据，区分源稿规则与项目适配，不生成无关 Starter 或虚构 Light 主题。完成后给出前后对比及实际验证结果。
```

若字体、控件高度等允许变更，也在请求中说明。对于明确要求保留的布局，不套用历史提示词中的固定 Header/Sidebar 尺寸；大屏指标按展示场景适配，不能机械统一为24px。

## 新建页面或制作规范包

新建页面时指定业务、主题及目标分辨率，复用实际需要的组件即可。只有需要跨项目复用时，再明确要求“制作通用规范包”，并指定输出目录和需要的模板。此时提取中性组件、集中令牌、规则文档与可运行标杆；主题数取决于实际证据和你的要求，不能把尚未核实的 Light 色值写成源稿事实。

## 放到其他项目

完整复制 `personal-ui-framework` 文件夹，保留相对引用；可在目标项目已有 `AGENTS.md` 中添加读取入口，不覆盖其原有指令。也可由你指定安装到个人技能目录。本次仅更新这个目录里的规范文件，没有进行全局安装。

## 迭代原则

核对时引用当前文档的真实条目和图层 ID。新增规则必须来自你的明确要求或可验证的源稿，避免把一次实现的取舍变成所有项目的硬限制。需要更换设计源时，先重新核实参数；原始提示词用于追溯，不自动重新执行其中的框架生成任务。
