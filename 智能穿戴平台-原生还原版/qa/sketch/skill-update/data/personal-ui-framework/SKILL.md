# 个人 UI 风格

先确定本次是修改现有界面、新建页面，还是制作通用规范包。读取 [实施方式与范围](references/合并提示词.md) 和 [Sketch 核实参数](references/Sketch核实参数.md) 中相关组件，再实现本次请求。

## 使用依据

- 用户当前请求和已确认范围优先。只改样式时，保留布局结构、模块顺序、业务内容、路由、事件和数据关系；不能为套用模板而重写系统。
- 区分三类信息：规范区的明确规则/状态、业务画板的具体实例、本项目的适配选择。参数文档的标记不能省略；不能把一个实例推广为全局禁令。
- 有原始 Sketch 时读取其原生图层、启用的样式、文字和祖先可见性，结合 PDF/预览核对用途。Sketch 可作为 ZIP 读取 JSON，不因 Windows 无 Sketch 应用而忽略。
- 已核实文档只证明所列源文件和图层。换源稿时重新核实差异；未读过的资产不能声称已核实。历史提示词不能覆盖源稿证据。
- 原稿的颜色透明度、图层透明度、填充类型和叠底都是参数；不能只抄 RGB 或用取色后的合成颜色冒充原始 Token。
- 本稿尚未证实完整 Light 参数，不自动补齐双主题；原稿内部冲突保留出处，仅在影响当前实现且无法由用户范围解决时澄清。

## 按任务执行

- **修改现有项目**：读取项目已有样式约定与相关组件；集中修改主题变量/组件样式，保留技术栈和几何约束。无需附带生成 Starter 或无关组件。
- **新建页面/项目**：复用已有令牌、组件和标杆；没有时按本次所需组件建立最小样式层，注明项目映射。
- **制作通用规范包**：仅在用户要求时抽象中性组件、编写规则、令牌和标杆。完整流程见实施文档；不把历史交付目录硬套到普通项目。

复用颜色、字号、圆角和状态应集中为 CSS 变量；保留项目布局常量不需要为“禁止 px”进行无关重构。数字可采用等宽数字特性以减少跳动，但这是工程选择，不能称为 Sketch 明文规则。无新增在线字体/CDN依赖，除非用户任务另有要求。

## 验证与历史

按本次改动验证默认、悬停、聚焦、按下、禁用和选中等实际存在的状态；检查目标分辨率、文本截断、遮挡、滚动及受影响交互。记录源稿参数与项目适配的差别，不能把近似实现称为像素级还原。

需要追查旧要求时才读 [历史合并版](references/合并提示词-历史未核实版.md)、[原文 A](references/提示词原文-A.md)、[原文 B](references/提示词原文-B.md) 和 [完整性核对](references/完整性核对.md)。原文保留用于溯源，其中未证实或与 Sketch 冲突的参数不再作为当前硬约束。
